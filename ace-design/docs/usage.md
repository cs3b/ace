# Session and interaction contract

Invoke `/as-design-site Design a site for …` or `/as-design-app Design the working screen for …`. The agent calls `ace-design explore` to create a session under `.ace-local/design/<base36-token>/`. Generate the token with `ace-b36ts encode --format ms` (in this repository `bin/ace-b36ts encode --format ms`). Create a fresh directory; on a collision generate a new token without overwriting an existing session. Put the readable project name in session.json rather than the directory name:


```text
session.json           {"surface":"site","title":"Example","language":"en","variants":["a","b","c"]}
brief.md               audience, action, constraints, A/B/C composition
fixtures.json          one JSON object; shared unchanged by all variants
assets/                optional shared local assets
variants/a/index.html  fetch('../../fixtures.json')
variants/a/direction.md composition, hierarchy, tradeoff, mocks
variants/b/…
variants/c/…
gallery.html           generated by preview
feedback.md            append-only feedback rounds
selection.json         created only after explicit choice
```

Each variant may use a subset of the fixture object, but must not invent contradictory alternative records. Session validation checks structure and selection integrity, not the semantics of arbitrary JavaScript. The agent must verify common content and distinct hierarchy/composition. Site variants include a first screen and following section; app variants include a representative screen and one local interaction.

`preview` generates a comparison gallery. It displays ready variants even if another is not present; it never deletes completed variants. A prepared session can show an empty gallery while workers run; `validate` still reports that no variants are ready. Existing variant files and shared data are not overwritten by the gallery command. Only trusted local mockups should be previewed; running their JavaScript is part of rendering them. The frames share an origin to fetch fixtures and are not isolated from one another.

Give feedback such as “B: less dense, keep the headline from A”. The agent calls `ace-design revise SESSION --variant b --prompt TEXT`. Only B is replaced, and successful feedback is appended to feedback.md. Failed attempts retain their feedback and error in run.json. A request to change shared fixture content requires a new session. Do not run full production reviews during these rounds.

After “choose B”, the agent records:

```json
{"surface":"site","variant":"b","fixtures_sha256":"SHA256_OF_EXACT_FIXTURE_BYTES","variant_sha256":"SHA256_OF_SELECTED_ARTIFACTS","decisions":["Keep B hierarchy and A headline","Replace mock form during implementation"]}
```

`validate SESSION` rejects mismatched surface, missing selected variant, changed fixture or selected-artifact hashes and empty decisions. A combined direction must first be represented in the selected variant. It does not auto-select a winner.

Then `/as-design-site-implement SESSION PROJECT` or the app equivalent starts proper engineering with actual data, required languages, states and tests. `/as-design-site-audit URL [PROJECT]` and app audit can operate without a session. URL-only audits explicitly label unavailable source coverage. Current checkout is used only if it is established to correspond to that URL.

Templates ship in `handbook/templates/design`; benchmark brief/fixture pairs ship in `handbook/benchmarks`. Pass the benchmark brief as the prompt and its JSON through `--fixtures`, then generate variants before previewing the printed session. Never edit packaged benchmark fixtures in a candidate comparison.

See [runner configuration](runner.md) for presets, optional per-variant prompts and CLI lifecycle commands.
