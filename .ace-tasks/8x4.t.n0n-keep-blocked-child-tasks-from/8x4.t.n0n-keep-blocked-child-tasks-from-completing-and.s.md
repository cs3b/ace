# Keep blocked child tasks from completing and archiving their parent

## Observed defect — 2026-10-05

During source-only closure, `bin/ace-task update 8wr.t.qkb.0 --set status=done,needs_review=false` changed the child but returned `Task '8wr.t.qkb.0' not found`. Immediate show found parent qkb marked done and archived while qkb.1 remained blocked. Root restored qkb to blocked/root using `bin/ace-task update 8wr.t.qkb --set status=blocked --move-to next`; show confirmed child .0 done and .1 blocked. No product fix is claimed.

Source evidence: FolderCompletionDetector::TERMINAL_STATUSES includes done/skipped/blocked. TaskManager check_auto_archive delegates this classification and can archive a parent before returning the updated child. This contradicts blocked meaning an unresolved required outcome. No repeated mutating reproduction was performed against user tasks.

## Outcome and contract

Updating a child to done must preserve a parent and sibling with unresolved work. Blocked is not completed work and never independently authorizes parent done/archive. Public update must return the updated child reliably, even when a legitimate whole-family archival occurs. Explicit parent archive requests must not silently convert unresolved children to completion.

One small source slice in ace-task/shared completion detection. Determine all consumers of the shared terminal classification during review, including doctor and idea/task archival. Keep skipped/cancelled explicit terminal semantics consistent with documented task policy; never rewrite historical records wholesale.

## Success criteria

- [x] Parent with one done child and one blocked child stays at its prior nonterminal status/location; sibling status and evidence remain unchanged.
- [x] Pending/draft/in-progress siblings likewise prevent automatic completion/archive.
- [x] Legitimately complete family archives as specified and update returns the requested child rather than post-move not-found.
- [x] Update/show/list/doctor agree on resulting state; no incorrect doctor fix archives blocked work.
- [ ] Independent source review and actual isolated CLI regression/package tests pass.

## Reviewed behavioral decisions — 2026-10-06

- Task completion uses exactly `done`, `skipped`, and `cancelled`; `blocked`, `pending`, `draft`, and `in-progress` are unresolved. The shared folder detector adopts these task defaults. Its explicit `terminal_statuses:` contract remains available; idea validation remains `done`/`obsolete` and has no production dependency on this detector.
- A child terminal-status update automatically completes and archives its parent only when every child/descendant is terminal. The parent's prior nonterminal status does not prevent legitimate completion. Empty child sets do not trigger completion. Already archived families do not relocate again.
- The successful update returns the child from its current resolved path after any family move, with the same ID and `_archive` location; show/list of archived records agree.
- Explicit parent `--move-to archive` with unresolved descendants is softly refused using an actionable update note, before applying any requested fields. Parent and all descendant content/paths remain unchanged. Child archive requests retain the existing soft-refusal semantics when siblings are unresolved.
- Doctor may report existing scope inconsistency, but must skip automatic parent archival when any descendant is unresolved. Doctor never changes an archived nonterminal task to `done` merely because of its location; that repair requires human lifecycle judgment. Dry-run obeys the same safety decision.
- Neither CLI flags nor idea/retro status policy change. Consumer scope is ace-task manager/doctor and ace-support-items detector; assignment and issue tracking already match the canonical task terminal set.
