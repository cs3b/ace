# Bind suite verdicts to exact package test invocations

## Observable outcome

Running a package test concurrently with a suite cannot change the suite's counts, verdict, assertions or report links. Each suite entry uses evidence produced by its own exact child invocation, including when multiple entries select the same package. This is one medium, independently deliverable test-evidence reliability slice owned by ace-test-runner; callers retain existing ace-test and ace-test-suite commands and test selection.

## Closed behavior and interfaces

Every actual test invocation owns a unique, collision-safe report identity and directory before writing results. Equal clocks, concurrent allocation and duplicate package selections never overwrite another invocation's evidence. Summary, detailed report and raw execution evidence belong to that same identity. Completed evidence is not silently reused or overwritten by later invocations. The existing latest convenience pointer may change; it is never an authority for an active/completed suite entry's result.

The suite binds the scheduled entry and its exact child process to that execution identity. It captures counts, assertions, success and immutable report location from that binding, once the child completes, and retains the same values through aggregation and rendering. A later unrelated run cannot change them. No package-name-only key or timestamp freshness check substitutes for invocation identity; separate entries remain separately attributable.

Missing, incomplete, malformed, mismatched or unreadable evidence for this execution produces an explicit failed/unverifiable package result and nonzero suite exit, even if latest points at a valid earlier/later report or the child exited zero. A nonzero child exit, timeout or interruption cannot become success from any report. Existing failure details and executed counts are retained when trustworthy. No fallback to a stale report or an exit-code-only successful proof. Summary and detailed report cannot be combined across invocations.

Public progress, final table, totals and detail links agree on the same execution. Existing single-package report output continues to point at a concrete retained report; latest remains navigational only. No new required user flag or backward-compatibility report dialect is introduced. Existing configured selections, explicit timeout overrides and duplicate entries are preserved; deduplicating packages or raising default budgets is out of scope.

## Success criteria

- [ ] SC1: Controlled overlap of suite child A and focused run B for one package leaves A's counts/verdict/assertions/link unchanged after B updates latest, for both success and failure combinations.
- [ ] SC2: Equal-clock concurrent report allocation and duplicate-package suite entries retain distinct, correctly attributable evidence without overwrites or dropped entries.
- [ ] SC3: Timeout, interruption, nonzero child exit, zero exit without valid current evidence, missing/malformed/mismatched report and mixed summary/detail inputs fail truthfully; unrelated valid reports never rescue them.
- [ ] SC4: Progress and final aggregation consume the same captured execution result, with stable report links usable after another invocation and after suite completion.
- [ ] SC5: Existing standalone ace-test and suite selection behavior remains usable with no new required invocation flags. Real CLI orchestration/regression checks, affected package all tests, default fast suite and independent frozen-source review verify the result.
