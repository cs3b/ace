# Validate paired native tmux reverse references

## Objective

Allow the shared HITL reverse-reference contract to carry the exact native tmux address already produced by Runtime, so a legitimate installed managed request is not rejected before delivery. This is one small standalone owner-layer slice in ace-hitl-contract with consumer adoption; qjz separately owns its installed sixteen-hour acceptance.

## Expected behavior

The existing `ace.hitl.ref/v1` session/pane pair has two accepted forms:

| Form | Session | Pane |
| --- | --- | --- |
| Herdr token pair | Nonempty ASCII letters, digits, `.`, `_`, `:`, `-` | Same existing token alphabet |
| Native tmux pair | `$` followed by canonical nonnegative decimal digits | `%` followed by canonical nonnegative decimal digits |

Canonical decimal means `0` or a nonzero first digit followed by digits. Both components remain bounded to128 characters. Native pairs are required together: `$0` with `pane1`, or `session1` with `%0`, is invalid. Session `%0`, pane `$0`, window `@0`, bare prefixes, negative/padded numbers, embedded whitespace, path/shell punctuation, extra prefixes and non-String components refuse. Accepted names such as `W692.lab_1`/`agent:3-x_9.y` remain valid. The codec does not expand the general punctuation alphabet.

Address validation is separate from authority. Acceptance of `$0`/`%0` proves syntax only; it never proves those objects exist, share a server, belong to an attempt, or may receive an answer. Recorded native process/server/target binding, exact producer-consumer comparisons, authenticated requester ownership, liveness and signed delivery checks remain mandatory. No label lookup, target substitution, environment adoption or fixture address rewrite is added.

## Public interface contract and producer/consumer map

| Boundary | Existing producer/input | Required result |
| --- | --- | --- |
| Runtime/Tmux native process binding | `NativeRuntimeBackend#process_target`, session_id/pane_id | Preserve exact `$N`/`%N` pair unchanged |
| Lab AssignmentBinding reverse address | Actual accepted Assign runtime_binding | Carry those exact IDs into `ace.hitl.ref/v1` |
| Ref direct construction and `from_env` | Explicit session/pane or existing HERDR variables | Validate the whole typed pair; no unchecked constructor bypass |
| ManagedEnvelope reverse address | `reverse.session` and `reverse.pane` | Apply the same pair contract, retaining InvalidEnvelope classification |
| Herdr CLI/support, Inbox and Deliverer | Explicit ref or persisted reverse pair | Consume the leaf's typed pair contract, without their own punctuation dialect |

The field role is explicit in the public validation boundary, never inferred from an arbitrary diagnostic/source label. Single-component validation cannot establish a valid pair. Obsolete component-only consumer paths must be replaced rather than kept as compatibility fallbacks. Existing diagnostic labels may identify errors but cannot select which forms are accepted.

Ref direct construction/from_env accept String components and normalize surrounding whitespace as the existing environment interface does. Their returned/to_h components are canonical. Wire/persisted managed references must already be canonical; noncanonical outer whitespace refuses rather than changing a recorded target. Invalid Ref inputs raise the existing InvalidRefError; ManagedEnvelope maps address failure to its existing InvalidEnvelope. No schema bump, new runtime field, CLI flags or implicit current target is introduced.

## Success criteria

- [ ] SC1: Exact real tmux `$0`/`%0` binding traverses Ref and ManagedEnvelope without rewriting IDs and reaches the existing authoritative ownership/liveness validation.
- [ ] SC2: Every listed entry point enforces paired field semantics, canonical String components and length limits; mixed, cross-field and malformed addresses refuse before native submission or answer consumption.
- [ ] SC3: Existing valid Herdr token/environment forms remain accepted, while native ownership/signed claim/receipt checks remain intact and cannot be bypassed by a syntactically valid ref.
