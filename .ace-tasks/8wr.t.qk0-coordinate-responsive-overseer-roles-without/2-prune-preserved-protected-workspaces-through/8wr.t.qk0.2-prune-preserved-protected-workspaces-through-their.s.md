# Prune preserved protected workspaces through their owner

## Behavioral Specification

### User Experience

After accepted work is preserved and its original execution is terminal/released, dry-run explains precisely what cleanup remains safe. Explicit apply removes only the accepted obsolete workspace through its authorized owner, preserving durable execution evidence. A stop/pane exit/slice retirement alone never counts as workspace cleanup.

### Expected Behavior

- Preserve delivered local prune's cleanliness, untracked/ignored-artifact preservation, executed ancestry/destination proof, exact HEAD/branch revalidation/CAS and shared start/exclusive prune exclusion. Force suppresses only convenience confirmation.
- Protected physical cleanup is distinct from disposable coordinator cache/display cleanup and existing reusable execution-parent retirement. The canonical journal/history, original descriptor/public keys, imported receipts and boot/network evidence remain outside every deletion target. Never delete a root still selected by current/candidate protected descriptor.
- Protected apply requires the actual authorized source maintenance/service owner: exact original authenticated selection, complete affected-root eligibility/exclusions and authenticated original terminal/release, plus executed preservation at the mutation boundary. Unknown work or evidence refuses; never translate an earlier status into a live exclusion grant.
- Request ownership is a separate authorized maintenance attempt with executable/evidence outside the target, through the existing structured scoped service contract. The sealed/released target gets no new effect permission. No arbitrary shell/path service, cross-UID local prune or private-journal fallback. Generic protected physical-prune composition is a real implementation obligation of this child; absent source is not assigned only to installed gad.2.
- Final evidence and filesystem removal must occur under the same maintained start/prune exclusion and lock order. No RPC taking shared lifecycle locks is called recursively while holding its exclusive prune lock. Removed marker prevents starts into removed identity; legitimate future provisioning remains explicit.

### Interface Contract

`ace-overseer prune --assignment ID --dry-run` previews classified allowed/blocked targets with evidence refs. Explicit apply consumes exact preview identity plus fresh owner/preservation checks; changed scope/head/descriptor/ref/authorization blocks. Protected source-owner route and exact request/reply selector composition must be independently finalized before this child leaves draft; do not invent a public cleanup operation merely in implementation. Existing scoped service request/status is the intended transport, not an already delivered cleanup executor.

### Success Criteria and Verification Plan

- [ ] SC1: Actual controlled protected owner composition previews, revalidates, preserves and removes an obsolete workspace while retaining literal original journal/descriptor/key/receipt/history evidence. Only the exact eligible original scope is retired/reused; no claim that slice StopUnit removed files.
- [ ] SC2: Race fresh start against apply; late new attempt/head/ref, dirty/untracked/required ignored data, conflicting current/candidate root, surviving writers, unknown settlement, unavailable permissions and corrupt preserved destination all retain work. Service replay never duplicates removal and lost confirmation remains reconciled rather than redone blindly.
- [ ] SC3: Separate maintenance requester and sealed target avoid an authorization/liveness cycle; unrelated active scopes aren't stopped/deleted. Execute real Git/flock/controlled authority fixtures and independent exact review; no native/installed proof claim.
