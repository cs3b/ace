## Proposed installed root and policy

Reuse the selected authority's fixed installed state_root, outside every original/candidate/deletion workspace, as the trusted authority storage owner. SAME Installer provisioning creates state_root/lifecycle-exclusion and a mapping subtree before publishing the original boundary. This proposal requires the actual deployment producer to authenticate the authority UID/GID and protected ancestor identities; it does not infer protection from a path. Publication and the original boundary's existing parent-resource declaration/verified eight-field resource identity select the exact mapping subtree inode. The installed host ancestry is not worker-writable. Mapping reader directory mode0755 and lock/marker mode0644 expose only lock/fence metadata; the private authority state parent prevents ambient traversal. Existing namespace topology publishes only this mapping subtree at one literal view_path, worker_visible=true, read_only=true. No current directory, CACHE_BASE, environment path or caller path selects the protected root. No new registry or canonical completion ledger.

Workspace identity uses the original authenticated cwd resource identity, not its pathname alone. Before exposing reader access, provisioning creates its empty regular lock and a closed initial nonremoved marker. Dynamic assignment/task identities are provisioned by the existing trusted authority before reservation/release; positive worker/launcher code cannot mkdir/create/reset/delete/write any protected artifact. Ordinary standalone LifecycleExclusion remains separate and does not select a protected grant. The exact authority-state DAC and boundary publication join must be independently reviewed with the SAME Installer author before implementation; it is not an existing installed capability.

## Same owner reader/writer APIs

The existing LifecycleExclusion gains source-composed protected reader/writer policy, rather than a separate lock owner. Protected reader uses RDONLY|NOFOLLOW|NONBLOCK, validates regular type/nlink/mode/selected ownership, retained root/file path-inode identity and the existing installed protection owner, then takes SH on the preprovisioned inode. It refuses missing lock or missing/corrupt/misbound marker; it never resets a fence. Protected writer opens the SAME inode, uses EX, and writes the removed fence only while its exact key's EX is held. It never replaces a lock inode or clears a removed original workspace identity. A newly provisioned original resource has a distinct identity/key; reuse never clears an old creator's fence. Marker schema/type/key/UTF8/size/duplicate fields are strict, with atomic nofollow/exclusive temporary publication, file fsync, rename and parent fsync. Reset remains only a standalone fresh-provisioning operation and cannot turn corrupt state into absence.

Protected LaunchLifecycle's task/assignment exclusion selection must move to the original installed root/resource identity and retain existing task→assignment and sorted slot ordering. PreparedWorker/ForkSessionLauncher creator adoption consumes the same original readonly workspace lock and holds SH throughout the actual provider/resource writer lifetime. Merely holding SH until reserve/start returns is insufficient. Unconfirmed outstanding child ownership retains exclusion; no return/EOF is substituted for drain proof. Task/worktree provisioning and protected dispatch creators must use the identical installed workspace identity and may not request slot/authority RPC while holding an incompatible workspace lock. PreparedQueue's private queue-cache exclusion stays its existing separate local state guard; it cannot substitute for workspace fencing.

SAME Installer cleanup ordering remains publication→sorted slots→retained inventory→workspace EX. Fresh canonical/physical checks and full writer quiescence remain mandatory. Lock contention is bounded by the existing absolute maintenance deadline and never weakens proof. Marker corruption, missing provisioned reader files, inode replacement, wrong original mapping/view, readonly violation or unavailable child ownership preserve the target and report unavailable/busy; none establishes removal/no-effect.
