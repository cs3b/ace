## Git preservation, capture and interruption

Require a supported linked Git worktree, original filesystem/admin identity, HEAD/branch and executed commit/dirt/untracked/required ignored preservation. Main worktree, submodule-containing or nested/ambiguous worktree layouts refuse. Common Git object/ref/admin store, all canonical/history/evidence and requester data remain outside deletion. Protected cleanup retains the preserved branch/ref; local prune's existing branch CAS remains unchanged.

Under installer→slot→inventory→explicit lifecycle locks, set the maintained removed fence BEFORE capture. Source-derived quarantine is outside deletion with installed owner protection. `git worktree move OLD CAPTURED` is a maintained Git operation, NOT atomic across rename and administration updates. Before command record a bounded immutable intended capture artifact in existing evidence sink. After success reread both paths and linked admin identities, original dev/inode, HEAD/branch and preservation. Require only original registered object at CAPTURED; OLD may have a replacement, which survives. Then maintained git worktree remove CAPTURED without force deletes only verified original. No generic rm_rf fallback or branch ref deletion.

Failure/crash before rename: original remains fenced/preserved, record untouched only if inspector positively authenticates no move/effect. Failure after rename before admin update: original may be at CAPTURED while admin still points OLD; mark partial, never remove OLD/replacement. Failure after admin update before removal: captured registered original remains, partial. Failure during deletion/admin cleanup: revalidate retained capture intent, actual filesystem and common Git admin; absence alone remains uncertain. Read-only inspector reports exact state; any repair/continued deletion requires a new explicitly authorized maintenance request that names the original captured identity and cannot blindly replay the original dispatched invocation. Such recovery may use maintained git worktree repair only for exact verified captured original, never an untrusted path. Successful removal requires authenticated retained operation receipt plus current original/captured/admin absence and preserved surviving data.
