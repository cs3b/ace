# Complete canonical inventory index authentication

Root independently approved this source precision before implementation after real raw-Git reproduction `bf90c957-78a1-409a-97aa-c8399dde17b0`: a cryptographically valid registration rewritten to a foreign mapping was filtered before historical authentication and falsely appeared as empty inventory.

The existing EvidenceJournal owner adds `canonical_event_inventory!(commit:)`, selected internally by the protected authority after verifying membership in its pinned canonical ref. Its closed source-only result is `{commit, events, introductions}` (String keys), where events maps assignment IDs to the exact selected immutable event arrays and introductions maps each assignment/event digest to its original commit. Every returned level and String is copied/frozen; no mutable journal, exclusion or permission is returned. This is not a new wire operation, registry, ledger, cache or controller.

One fixed complete first-parent walk enumerates assignments at every immutable tree. Reuse the existing bounded tree/blob reader and EvidenceEvent chain owner. At every adjacent prefix, authenticate each assignment/per-attempt chain and require the older chain to be an exact prefix of the newer chain; comparing one combined assignment array is forbidden because legitimate interleaving of attempts changes that array order. Earlier assignments, attempts or event files cannot disappear. Every older event filename/OID must remain exactly unchanged in the newer tree. All original introductions derive from that same authenticated walk, including facts later used to exclude foreign mappings. Ordinary inherited appearances and appends remain valid; a verified retained empty prefix is valid, a missing ref is unavailable.

The inventory producer filters current authorized mapping only after this complete index proof, then applies existing parsed definition/tuple and actual terminal/release owners at their exact introductions. Current peer authorization is still required on each page. No selected commit, metadata status, return value or frozen entry authorizes maintenance, native I/O, launch, cleanup or old-birth control. Existing selective event-commit APIs retain their contracts and source callers.

Executed tests must cover valid foreign mapping exclusion after proof, valid-but-rewritten ownership, removed assignment/attempt/event, changed raw serialization, ordinary append/interleaving, retained empty prefix and source result immutability. Preserve the fixed Client30s budget and actual per-read timing; do not raise ceilings or substitute row-count assertions for measured owner delivery.
