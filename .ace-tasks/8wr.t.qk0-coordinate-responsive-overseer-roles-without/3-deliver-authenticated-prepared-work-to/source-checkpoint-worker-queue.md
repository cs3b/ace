# Worker and scoped queue source checkpoint

Implementation remains in progress. This checkpoint implements the original worker, retained private queue and supported scoped Assign consumers. It does not complete the compact native release binding, selected task-context executable/Bundle bridge, production Lab entry producer, or installed acceptance.

## Source contract

The fixed public entry is `ace-assign authority worker`, with no arguments/options. Installed mappings select exactly `[accepted_executable, authority, worker]`. Environment IDs are lookup hints only. The worker performs the existing authenticated original prepared fetch, verifies its exact immutable graph, and compares kernel-captured self to `original_worker_identity` before queue or provider effects. A descendant can fetch; it cannot activate. Repeated adapter invocation refuses an active/failed queue and preserves a complete matching queue without another provider. A dead original worker cannot be replaced by a new birth under the old attempt.

The descriptor carries `original_worker_scratch_root` from the authenticated retained original descriptor, rather than the current descriptor. Client validates that descriptor before receiving bytes and stages the transfer beneath the same verified private root. The explicit queue is `<original scratch>/prepared-queues/<mapping>/<attempt>/<assignment>`; the existing LifecycleExclusion lock lives outside transfer cleanup. No authority assignment root, ambient cache selector or new journal/grant ledger supplies progress.

Only original adapter activation may first-publish the initial queue. It stages private durable files, atomically renames under exclusion, verifies the accepted graph, and marks the selected fork root active before invoking the maintained inline provider launcher. Later CLI consumers never recreate a missing published queue. Missing queue after effects, duplicate active adapter and changed work-bearing bytes refuse. The executor selects the captured Assignment directly; scanner decisions use the same held bytes that were checked. Job/instructions/frontmatter are immutable, with only the existing closed progress fields and report output mutable. Reports and input files are bounded, held regular/no-follow reads and private writes.

Scoped Status, Step, Start, Finish, Fail and Resume independently authenticate the original input before consuming the queue. Resume supports only `--dry-run`. Graph-changing commands refuse before effects. Current and retained deployment owners classify protected worker UIDs, so removal from the current mapping cannot restore ordinary local mode. Invalid or unreadable installed selection refuses; only genuine absence admits ordinary use. Runtime selectors render only the closed `admitted.*` instruction tokens after authentication; accepted bytes remain unchanged.
