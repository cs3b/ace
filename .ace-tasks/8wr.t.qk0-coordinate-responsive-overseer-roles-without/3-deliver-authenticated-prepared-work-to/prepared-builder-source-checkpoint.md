It selects one canonical reviewed leaf, propagates the selected project into the real managed assignment and captures the actual generated job plus unique task-bearing fork subtree. Dependencies are traversed through TaskManager with cycle/missing-input refusal. BundleLoader loads the exact spec pathname already resolved by TaskManager, matching the final owner used by task:// without a second external task/shim lookup.

The source API requires explicit `dependency_reports`, including an explicit empty array. Each selector is exactly task_id/assignment_id/number; only transitive dependency reports from the same project are permitted. AssignmentManager and StepFileParser resolve the existing managed report; callers cannot supply a report pathname. Duplicate selectors, wrong association and unavailable inputs refuse. No report is evidence of successful execution merely because it was captured as instruction context.
