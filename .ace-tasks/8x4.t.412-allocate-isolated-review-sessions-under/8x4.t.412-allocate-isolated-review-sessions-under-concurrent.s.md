# Allocate isolated review sessions under concurrent starts

## Behavioral specification

An operator can start independent reviews concurrently in the same checkout and cache root. Each invocation receives its own session identity and directory before writing prompts, metadata, reports or findings. Equal clock readings and simultaneous allocation must not cause sharing, replacement or cross-attribution. A session's subject, model output, evidence and feedback remain attributable to that invocation throughout completion, interruption and retry.

Automatic allocation returns distinct session locations even when timestamps collide or a candidate location already exists. Existing sessions remain byte-for-byte intact. Failure to allocate a writable session produces a nonzero actionable refusal before reviewer execution or writes to another session.

For an explicit `--session-dir`, an occupied nonempty directory is refused before modification. An empty explicit directory may be claimed by one invocation; a concurrent contender must refuse without touching the winner's content. This command does not implicitly resume or replace an earlier review. Existing dedicated campaign/delta/evidence APIs retain their documented behavior; this task introduces no new resume mechanism or historical migration.

## Interface and usage

Existing `ace-review --preset code-valid --subject ... --auto-execute` and `--session-dir PATH` flags remain. Output identifies the actual isolated session. Feedback list/create with that exact path can only consume its own reports; no shared latest-session pointer is evidence for concurrent review selection. See `ux/usage.md`.

## Success criteria

- [ ] Two actual concurrent preparations with one fixed clock/cache receive distinct automatic session paths and retain distinct subject/prompt metadata.
- [ ] Controlled concurrent reviewer outputs with different sentinel findings remain in their own reports and feedback collections, in either completion order.
- [ ] An existing automatic candidate or explicit nonempty directory is preserved unchanged; automatic allocation isolates the new invocation and explicit reuse refuses nonzero.
- [ ] Two invocations racing for one empty explicit directory cannot both own it; the loser writes no review artifacts there.
- [ ] Interruption or unwritable allocation cannot overwrite or publish another invocation's results. Completed history remains readable.
- [ ] Existing single-review and campaign/delta/evidence workflows pass affected tests and independent review.

## Ownership and scope

Owner: ace-review session creation. Consumers: independent code/spec review, feedback synthesis, delivery evidence. One small standalone observable slice. Excludes changing global timestamp formats, renaming historical sessions, automatic repair of already mixed reports, and redesigning campaign policy. This follow-up does not block Lab source work using explicit unique session directories; before promotion, readiness review must assess existing explicit-directory workflows against the refusal contract.
