# Refuse unmatched or ambiguous file-line test selections

## Outcome

An explicit file:line selection never silently widens to a whole file, a neighbouring test, an inherited test or a same-prefix method. This is one medium-sized runner behavior slice, owned by ace-test-runner. No Lab deployment is required.

## Evidence

During protected-source verification, selecting line166 before a Runtime test starting at167 ran25 tests instead of the intended one (receipt5979192c). A later producer join repeated the same behavior for line18 versus method19. CommandBuilder currently drops an unresolved selector and emits no --name filter; InProcessRunner does the same before loading files. LineNumberResolver assumes methods close at indentation<=2, so deeply nested tests may also wrongly absorb following blank/helper lines. Existing command patterns use unanchored method-name regexes. On 2026-10-07, protected_work_on_composition_test.rb blank line283 (method moved to284) again resolved to nil and omitted --name, expanding four intended worker selections to the whole file. Timeout receipts819489a5,0fb43e34,b04acda1,1e1f6122 are excluded selection failures, not worker diagnosis or acceptance. The correctly selected method then executed exactly once (ec362f34), exposing a separate controlled fixture cwd conflict. Another mixed invocation58820 used blank47 instead of declaration48 and was cancelled on the observed invalid selector (terminal130), excluded. The attempted exact-method --filter run3c8f8e71 is also excluded: this CLI filters filenames and executed zero tests. Until this task is implemented, verify the unique method declaration line immediately before dispatch and inspect the generated --name/count.

## Contract

For `bin/ace-test PACKAGE TARGET path_test.rb:LINE`, LINE must identify exactly one supported test declaration or a line inside that test body, including its closing delimiter. Resolve all explicit selectors before loading any selected test file or spawning a test child. Missing file, nonpositive/out-of-range line, blank/comment/helper line outside a test, malformed source, unsupported ambiguous construction or multiple possible identities produces a nonzero selection error naming the selector; no test body or selected-file top-level effect executes.

Retain supported Ruby `def test_name` and `test "description" do` forms. Nested class/module indentation, nested blocks and strings/comments containing `def`/`end` must not change the test boundary. Do not pick the nearest preceding/following test. A selection includes that test identity, not another method whose name contains it, an identically named test from a different class, or an inherited test from a required support file. If an exact identity cannot be established, refuse rather than widen.

Multiple line selectors execute their exact deduplicated union. If any selector is invalid, the whole invocation refuses before test loading/execution. Mixed plain-file and file:line input must preserve the explicit per-file intent (whole unqualified files plus only the selected tests in qualified files); if the current backend cannot express that exact union, visibly refuse before execution. Subprocess and in-process backends obey the same policy. Ordinary unqualified file execution is unchanged. Report the resolved selection or a precise selection error; no zero-test success or whole-file fallback substitutes for an invalid selector.

## Success criteria

- [x] SC1: Valid declaration/body/end lines select exactly the intended test with nested modules/classes and blocks, for both supported declaration styles.

- [x] SC3: Prefix-colliding names, same names in separate classes and inherited tests cannot expand the selected set; multiple/mixed selectors have exact or explicitly refused behavior.
- [x] SC4: Both execution backends and public CLI demonstrate these outcomes; unqualified execution and existing ordinary test runs remain unchanged.
