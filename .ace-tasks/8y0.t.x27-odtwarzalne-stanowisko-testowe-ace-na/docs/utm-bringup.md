## Local Forgejo probe and current runtime

The final scope uses only guest-local Forgejo for issues, reviews and merges. The `15.0.11` ARM64 binary matched its pinned SHA-256 and the release signature verified against the published signing-key fingerprint; the real guest executed `forgejo --version`. The `fj 0.6.0` ARM64 archive is pinned by its computed SHA-256 from the official release download. A separate temporary Forgejo instance bound to guest loopback port 3017 was used to test the actual API; its process, database and temporary credentials were removed after the probe.

With `REQUIRE_SIGNIN_VIEW=true`, its anonymous version endpoint returned HTTP 403 despite the service being healthy. Forgejo also defaults later newly created users to a required password change, causing their API calls to return 403. The fixture now handles the readiness response and explicitly disables that flag for its disposable users. The real server accepted repository creation (201), adding the separate reviewer (204), and issue creation (201).

The installed ACE Forgejo auth provider assumes `POST /api/v1/admin/users/{account}/tokens`. The actual Forgejo 15 instance returned 404 and its swagger document lists only `/users/{username}/tokens`. A PAT with the `sudo` scope and `Sudo` header returned 401 `auth method not allowed` for token creation. An administrator's Basic authentication with the `Sudo` header created a repository-targeted token (201, requested scope returned) and revoked it (204). This confirms a product integration gap; the probe does not show a safe mechanism for an unprivileged worker to access the administrator credential or start a correctly leased role. Do not mark the scenario accepted or distribute the administrator credential to agents as a workaround.

The current clean runtime provisioning subsequently completed `ace-lab install` and `ace-lab verify` (16 pass, zero failed, zero unknown), verified all 55 external gem names and versions against the pinned manifest, and installed Pi's lockfile. Native Herdr build and the runtime readiness receipt are still pending; the E2E cycle has not been run.
