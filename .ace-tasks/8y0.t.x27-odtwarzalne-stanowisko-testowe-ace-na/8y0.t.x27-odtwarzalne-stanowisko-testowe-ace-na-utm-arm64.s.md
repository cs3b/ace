# Odtwarzalne stanowisko testowe ACE na UTM ARM64

## Cel i kontekst

Usuwalne stanowisko E2E w projekcie ACE: Debian 13 ARM64 na UTM, lokalny HITL, prawdziwi Herdr/Pi i opublikowany runtime ACE. Nie jest to lab produkcyjny. Konfiguracja, procedury i reset należą do repo. Bez Omarchy, Incus i Hermes/Telegram.

## Warunki odbioru

Dwa pełne przebiegi od czystego stanu z resetem pomiędzy nimi; niezależny worker i weryfikator, potwierdzony pierwszy turn i eyes nadzorcy projektu, pięć minut bezczynności, brak duplikatów po restarcie i ponownym raporcie, jawne blokady przy awariach. Wyniki zachowują tożsamość artefaktów i zdarzeń; sekrety i obrazy nie trafiają do repo.

## Zakres

Profil UTM, bezpieczny helper prepare/status/reset/destroy, instalacja root-owned runtime przez ace-lab i projekty mo:mo, dwa scenariusze TS-MONO-003 i 004, odporność i raport. Nie zamykać przed wykonaniem obu cykli na VM.

## Scenariusz Kapitana: od bootstrapu do integracji

1. Lab Overseer otrzymuje cel przygotowania ACE; tworzy zadania i deleguje konfigurację wykonawcy. Po niezależnej weryfikacji potwierdza pierwszy turn i aktywne eyes projektowego Overseera.
2. Projektowy ACE Overseer otrzymuje kilka zadań z GitHuba. Sam ustala kolejność i zależności, tworzy/przydziela pracę podagentom, obserwuje postęp, zleca niezależne review i prowadzi poprawki.
3. Po wykonanych testach i pozytywnym niezależnym review scala gotowe zmiany na main we właściwej kolejności zależności. Kontynuuje następne zadania samodzielnie, bez osobnego zlecenia Kapitana dla każdego.
4. Release pozostaje w kolejce: nie jest wykonywany ani publikowany w tym scenariuszu. Sukces wymaga potwierdzonych merge commitów, wykonanych testów i niezależnych werdyktów; same PR lub plany nie wystarczą.

Test używa wydzielonego testowego repozytorium GitHub i odpowiednich testowych uprawnień; nigdy nie zmienia rzeczywistego produkcyjnego main ani nie publikuje wydania. Brak dostępu do GitHuba lub niezależnego review to jawna blokada, nie symulowany sukces. Odbiór wiąże identyfikatory GitHub, tasków, przydziałów, review i PR z kolejnością scalania i końcowym HEAD.
