# Reject incomplete test executions in aggregate verdicts

## Behavioral specification

A test operator running multiple targets or files receives a failed overall verdict whenever any selected execution times out or exits unsuccessfully, even when earlier targets passed or partial stdout contains zero failed assertions. A green test summary is never evidence that an incomplete process finished successfully.

### Expected behavior and interface

- Existing `ace-test PACKAGE all`, explicit-file, single-batch and per-file modes retain their flags. CLI returns nonzero when any executed component is unsuccessful. Timeout, signal/nonzero exit, interruption and incomplete execution cannot be erased by aggregation or parsed assertion counts.
- Terminal output, saved report and summary JSON agree on overall failure. Preserve completed test counts and available diagnostics; identify the execution failure without fabricating completed test cases. `summary.json` must have `success: false` for an incomplete/failed execution.
- All-success execution remains successful. Assertion failures remain failures. A successful process merely printing the word timeout is not classified as a timeout.
- Fail-fast stops at the failed component; without fail-fast subsequent selected components may run, but their success cannot overwrite an earlier failed execution. Consumers such as `ace-test-suite` observe the failed aggregate.
- Existing deadlines and test selection remain unchanged. Do not obtain green results by increasing deadlines, suppressing stderr, omitting targets or rewriting reports.

### Ownership and scope

Owner: ace-test-runner. One independently verifiable slice, advisory size small. Consumers: ace-test CLI, suite/report consumers and delivery agents. This task fixes verdict propagation; broad performance work, changes to tested products and process-tree cleanup redesign are outside this scope. No implementation dependency on qjz; qjz supplied the observed failure.

### Success criteria

- [ ] SC1: A completed passing first target followed by a timed-out or otherwise failed target produces nonzero CLI exit and a failed machine-readable report, preserving the first target's actual counts.
- [ ] SC2: Equivalent refusal is demonstrated for selected single-batch and per-file execution, with and without fail-fast; failed process output containing a green partial summary cannot override execution failure.
- [ ] SC3: All-success, genuine assertion failure, and successful output mentioning timeout retain correct outcomes. Source package tests and independent review verify the fix.

### Verification plan

Controlled component tests cover mixed target outcomes and report construction. A disposable package invoked through the actual bin/ace-test CLI supplies a passing target then bounded failure/timeout; inspect terminal status and saved summary/report. Use short deterministic fixtures, not the slow ACE suite as the regression. Run `bin/ace-test ace-test-runner all` and affected reporting/CLI integration tests. Independent review must inspect both the aggregation and final TestResult success calculation.

### Explicit mode and interruption acceptance

The regression matrix pins execution instead of relying on automatic selection: by-target `--direct`, by-target `--subprocess`, explicit files `--subprocess --per-file`, and `--run-in-single-batch --subprocess`. Exercise failure followed by a passing marker with fixture `execution.target_fail_fast: false` and `--no-fail-fast`; assert the marker ran but aggregate still failed. Repeat with fail-fast enabled and assert the marker did not run. Preserve existing precedence: subprocess `--fail-fast` selects per-file execution even alongside `--run-in-single-batch`; do not mistake that case for single-process batch coverage. Direct execution has target-level stopping; tests must reflect its actual boundary.

Child termination by signal is an unsuccessful execution and must produce a failed normal report. Operator Ctrl-C is distinct: CLI retains exit 130 and interruption diagnostic; it need not create a normal completed report, but must never publish a successful report for that interrupted invocation. Prior completed artifacts remain unchanged and cannot be represented as this invocation's success. A controlled SIGINT test verifies exit 130 and absence of a fresh successful artifact, rather than relying on the child-timeout test. Abrupt uncatchable termination cannot promise a final artifact.
