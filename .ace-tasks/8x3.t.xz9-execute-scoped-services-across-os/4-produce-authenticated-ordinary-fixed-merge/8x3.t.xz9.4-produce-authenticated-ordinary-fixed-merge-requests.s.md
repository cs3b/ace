# Produce authenticated ordinary fixed merge requests and receipts

## Observable result

An authenticated ordinary project overseer can submit one fixed, exactly bound
merge operation, receive a durable acknowledgment, and inspect the same operation
through a read-only status command after either side restarts. The terminal receipt
is attributable to the exact repository, PR, reviewed head and authorization. An
uncertain effect is never repeated to manufacture a receipt.

This child owns the missing ordinary admission/execution/status producer. A new
child is required because xz9.0 owns the protected fixture/endcap, xz9.1 protected
boundary recovery, xz9.2 protected steering and xz9.3 protected canonical result
maintenance. Expanding any of them would mix ordinary overseer authority into a
protected worker boundary. The protected receiver, its children and its request
schema remain unchanged.

## Authority and maintained public surface — decided

Use an explicit `ordinary-merge` mode of the maintained `ace-lab service
request/status` vocabulary. Do not create a second command pair. This preserves
one discoverable fixed-service vocabulary while the mandatory mode selector sends
the request to a separately configured ordinary receiver and admission policy; it
does not broaden the default local route or protected route. `ordinary-merge` is
valid only for `operation=merge` and never accepts executable, argv, UID, socket,
evidence path, credential path or token selectors.

`ace-assign` canonical attempt/evidence state is the sole queue/effect record. The
ordinary receiver writes the admitted request and subsequent outcome through the
public Assign coordinator API and returns an opaque reference only after that
canonical record is durable. The receiver has no journal, mapping database or
receipt ledger of its own. `ace-assign` owns the shared opaque-reference creation,
resolution and read-only-status primitive; this child owns its ordinary merge
admission and `ace-lab` CLI composition. iy6 may later compose that primitive but
does not own or authorize merge. qkb.1 consumes it; qk0 owns queue/recovery;
`gad.b` installs it and `gad.2` owns installed distinct-account acceptance.

## Closed request contract

The only request form is:

```text
ace-lab service request --mode ordinary-merge \
  --project PROJECT --assignment ASSIGNMENT --attempt ATTEMPT \
  --queue-entry QUEUE_ENTRY --operation merge --input INPUT.json \
  --authorization AUTH_REF --request-id REQUEST_ID
```

`INPUT.json` has schema `ace.lab.service.ordinary-merge-request/v1`, rejects unknown
fields, and contains exactly these selectors:

- `forge`: configured forge server stable ID;
- `pr_url`: normalized PR URL;
- `head_repository`, `head_ref`, `candidate_head`: exact source repository, ref and
  40-lowercase-hex reviewed head;
- `base_repository`, `base_ref`, `expected_base_head`: exact target repository, ref
  and observed 40-lowercase-hex head;
- `method`: the closed value `merge`;
- `review_evidence`: exact accepted independent-review reference and reviewed head;
- `test_evidence`: non-empty exact executed-test receipt references for that head.

The command selectors plus the canonical JSON input, authorization reference and
request ID form the immutable binding. The producer canonicalizes it and computes
`input_digest` as lowercase SHA-256. Admission authenticates the calling project
overseer against the installed project/receiver mapping, resolves the named queue
entry and attempt, and revalidates authorization, repository/PR provenance,
candidate/base heads and current review/test evidence. A request ID already bound
to the identical digest returns the original acknowledgment/status; reuse with any
different field refuses before effect. Missing, extra, caller-selected execution or
protected mapping/scope/service/generation selectors refuse before effect.

Successful admission returns only the closed acknowledgment:

```json
{"schema":"ace.lab.service.ordinary-merge-ack/v1","status":"accepted","request_id":"…","input_digest":"<sha256>","reference":"<opaque>"}
```

`reference` is a receiver-issued bounded opaque string naming the canonical Assign
record. Clients may persist and echo it but may not parse it or derive paths from
it. No acknowledgment is accepted until the request is durable. A refusal uses
`status=error` with a closed refusal code and has no reference; lost output after
durable admission is unconfirmed/uncertain, never a proven refusal.

## Closed read-only status and terminal receipt

The sole lookup form is:

```text
ace-lab service status --mode ordinary-merge --reference REFERENCE \
  --request REQUEST_ID --project PROJECT --assignment ASSIGNMENT \
  --attempt ATTEMPT --queue-entry QUEUE_ENTRY --input-digest SHA256 \
  --format json
```

All selectors are required and must match the canonical record. Status authenticates
the observer, performs no dispatch, retry, authorization refresh or selector repair,
and returns schema `ace.lab.service.ordinary-merge-status/v1` with exactly
`status`, `reference`, `request_id`, `input_digest`, and `receipt`. `status` is one
of `pending`, `uncertain`, `succeeded`, `failed`; `receipt` is null until terminal.
Unknown/mismatched references refuse without revealing whether another project has
that reference.

A terminal receipt uses schema `ace.assign.fixed-effect-receipt/v1` and is stored in
the same canonical attempt/evidence record. It contains the opaque reference,
request ID/digest, project/assignment/attempt/queue entry, authenticated producer
identity, operation/method, authorization reference, all request selectors, effect
start/finish timestamps, terminal outcome, and verified remote observation. Success
requires outcome `merged` or `already_merged` plus the exact forge/PR, target
repository/ref, candidate head, expected and observed base heads, resulting target
head/merge commit, and the producer's registered checkout/worktree/branch identity.
Failure is terminal only when the fixed producer proves no uncertain merge remains.
Logs, process exit, a SHA without repository identity or a caller-authored file are
never receipts.

## Failure, recovery and rollback

Lost acknowledgment, requester restart and receiver restart reconcile only by the
original request binding/reference and perform at most one merge. Unavailable
pre-admission receiver is a refusal/blocker. Disconnect after admission or after
effect start stays pending/uncertain until canonical evidence proves one terminal
outcome. Only a proven pre-effect refusal permits a new reviewed request. Confirmed
remote merge with stale local state returns `already_merged`; qk0 schedules local
synchronization rather than dispatching merge again.

Rollback disables new `ordinary-merge` admission in installed configuration while
preserving canonical records and read-only status for every accepted reference.
It stops the ordinary receiver only after in-flight records are terminal or
explicitly uncertain. It never redirects ordinary callers to local execution or the
protected receiver and never deletes an Assign record to permit replay.

## Explicit exclusions

token, borrowed protected authority/attempt/mapping, implicit grant, caller-selected
executable/argv/socket/evidence/token, log-parsed success or invented HTTP transport.
