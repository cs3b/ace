# Selected receiver recovery — source contract

No new RPC ledger, effect permission or generic verifier. Extend existing service_status executor-only projection with a closed settlement_context produced by the same original service owner: original terminal receipt binding, claim_binding, dispatch_phase, exact current accepted challenge payload/digest, and canonical generation/commit. Ordinary roles retain their existing projection. A selected executor must authenticate its actual peer and original mapping/project/request before this data is returned. Shared ServiceEvidence authenticates retained record/challenge; no caller selector or target is trusted.

Receiver `recover_no_effect(binding:, input_bytes:, mutation_id:, expected_generation:)` runs as its fixed installed executor. Binding contains exactly original assignment_id, attempt_id, candidate_generation, head, request_id. Candidate generation must be a nonnegative Integer matching the existing request shape; expected_generation must be a positive Integer. IDs/canonical head must satisfy the existing fixed validators, mutation_id must satisfy the existing stable mutation validator, and input_bytes must be the original structured String. These validations occur even on an authenticated settled/current-challenge path.

Before any communication, snapshot and freeze the original binding, structured bytes and mutation ID; validate the retained snapshots and derive the request ID from them. Caller mutation during status/claim/upload cannot change the original input or stable claim/completion identity.

It reads canonical status and validates original input against the source-selected canonical input_digest and target before any short-circuit. Authenticated succeeded/failed-settled returns without inspection or mutation. For uncertain/failed, an authenticated current accepted challenge is reused without claiming again; expected_generation is validated but is not used as a new CAS assertion in these non-claim cases. If no current accepted challenge exists, claim_service_settlement uses the caller's exact supplied expected_generation unchanged, then rereads authenticated current challenge context. Stale CAS or lost ACK cannot refresh this value/token silently. Changed/missing/orphan context refuses. Original structured input conveys no new effect permission.

Trusted operation configuration selects a distinct fixed no_effect_argv for the operation/project/service/executor. This inspection lookup does not require a still-live effect lease and never selects normal argv. It validates trusted executable/ancestors using the existing policy owner. It is a domain source obligation: gad.b must implement operation-specific original target/handler/writer inspection; timeout/cgroup/generic cleanup cannot create the three absence facts. Missing inspector refuses, never falls back.

Receiver creates only a private selected staging directory, invokes the fixed inspector with exact immutable version1 service_no_effect_inspection envelope containing original canonical request, structured original input and accepted challenge/failure binding. Existing bounded handler transports its output and artifacts. Only outcome failed with exact original request/digest may proceed. Existing EvidenceTransfer reads bounded staged artifacts; existing complete_no_effect uploads the exact original failed receipt, accepted challenge and bytes. Authority alone validates/imports the fixed ace-service-no-effect artifact after its accepted challenge, CAS once, and authenticates replay. No caller true boolean can settle.

Lost completion ACK leaves uncertainty and preserved evidence. Retry first checks canonical status; failed-settled returns without inspector re-execution. Lost challenge ACK recovery first reads authenticated current status and adopts its accepted current challenge without another claim; an in-operation exact replay may use only the retained original claim parameters, never a refreshed generation. Reinspection is permitted only as fresh domain READ/inspection after actual current failure/challenge, not re-execution of the original operation. Ordinary status remains read-only. No new receiver socket protocol is introduced; the existing source-owned receiver method is the consumer API used by that owner.

Tests: actual canonical Client/Server+receiver+fixed controlled inspector boundary; assert no normal handler invocation, exact challenge/import/replay, expired effect lease inspection eligibility, wrong map/executor/input/target refusal, lost ACK status retry without duplicate import. ## Exact closed schemas and canonical producers

Executor-only status `settlement_context` has exactly `version`, `request`, `execution`, `challenge`. `version` is Integer1. `request` is exactly existing TERMINAL_BINDING_FIELDS: request_id, assignment_id, attempt_id, project_id, operation, input_digest, target, candidate_head, executor_uid, transport, copied from the authenticated original canonical service record. `execution` has exactly mapping_id, candidate_generation, head, claim_binding, dispatch_phase; head is original candidate_head, all other values come from the same record. Full original service_settlement_record! identity checks bind selected mapping/project, fixed receiver, actual executor UID/GID/groups and original request/candidate before this context is exposed. Current peer liveness and configured visibility remain required.

`challenge` is null unless an accepted authentic challenge matches the latest canonical uncertain/failed service failure. Otherwise its exact keys are request_id, input_digest, claim_binding, no_effect_challenge, challenge_generation, failure_event_digest, failure_generation, challenge_event_digest. They come from the existing authenticated ServiceEvidence challenge event payload plus its canonical digest. Retained stale challenge authentication still runs; only positively authenticated later failure permits returning null. Missing/corrupt/orphan/partial challenge is an error, never null freshness. The shared protected journal reader authenticates terminal receipt and imported bytes before any settled status result is returned.

Inspector envelope has exactly version, kind, request, input, execution, challenge. version is Integer1, kind is literal service_no_effect_inspection, request/execution/challenge are the immutable source-authenticated context objects above; input is parsed original structured input validated against that request's exact input_digest and target. Inspector target identity comes from the canonical record plus digest-bound original operation input; no current caller target/path is accepted. No new generation of effect permission is created. The ordinary handler's fixed response shape remains request_id,input_digest,outcome,evidence with literal failed outcome for this path; artifacts must carry the accepted existing strict ace-service-no-effect schema and ordinary original executor attestation.

Recovery validates changed input even for succeeded/failed-settled early return, then returns only the authenticated canonical projection. For unsettled status with authentic current challenge, reuse it directly without another claim. If no current challenge exists, caller supplies a fresh stable mutation ID and original status generation for claim. The exact original claim parameters are retained for retries within that operation; never refresh expected_generation under the same mutation. After lost claim ACK, reread canonical status: an authenticated now-current challenge may be adopted without re-claim; otherwise return uncertain and require an explicit fresh caller mutation, not an automatic token/generation refresh. After lost completion ACK, reread authenticated status and never rerun original effect.
