# Execute scoped services across OS users with trusted receipts

## Outcome and scope
A worker invokes the existing `ace-lab service request` and receives an attributable result from an authorized service running under a different OS user. ACE owns the reusable receiving boundary; lab-config installs it and supplies fixed domain handlers. This is the missing receiving half of qjx, not a reopening of its delivered client/contract scope. Advisory size: large, single end-to-end service capability.

## User experience and public contract
Preserve the existing request/status/dry-run vocabulary, request identity, digest and outcomes. Add `ace-lab service serve --service ID` for the deployment-controlled executor account. It reads fixed root-owned authorization/topology configuration; it does not accept caller-selected policy, repository roots, executable, UID, sink or credentials. The existing Unix transport selects the configured service socket. A protected project/assignment mapping selects the authoritative attempt journal and evidence root. A request may name those IDs but cannot select their filesystem locations.

The server authenticates kernel peer credentials and compares them with caller identity bound into the request, resolves the current authorized project and managed attempt, reloads exact operation authorization/lease and verifies current candidate head at dispatch. Request data is untrusted even when emitted by an ACE client. Recompute the canonical input digest, target and immutable request fields; reject client claims that disagree with current authoritative records. Domain handlers receive the accepted structured request and sanitized fixed execution context under the configured executor UID. No shell passthrough, dynamic UID changes, arbitrary callbacks or worker access to executor credentials.

ace-assign remains sole attempt/effect journal owner. A real cross-user call must finish through its public coordinator API with executor-authored verifiable evidence; merely returning JSON or trusting an executor_uid integer cannot authorize settlement. No second service ledger. The client can observe allowed public results but cannot forge, replace, delete or rebind accepted evidence through a writable parent or repository. Identical duplicate requests return the existing result; conflicting reuse refuses. Receiver restart, caller loss and effect-before-receipt crashes stay uncertain until current authoritative evidence proves outcome. No automatic replay of uncertain external effects.

`serve` has exclusive endpoint ownership for its lifetime. Refused second startup cannot remove an active socket; stale recovery requires positive absence and protected path ownership. Shutdown only removes its own endpoint. Connections, frame sizes and deadlines are bounded. Unsupported peer authentication fails closed. Malformed/rejected requests have no handler effects and return existing classified public errors without raw input, tokens or handler stderr. Dry-run checks current eligibility without dispatch, credentials or durable claim.

## Consumers and ownership
ACE ace-lab owns receiver/config validation and public service behavior; ace-assign owns authoritative claims/receipts and any required public cross-user evidence API. lab-config:gad.8 installs protected topology/storage/account mappings; gad.b installs handlers and proves actual operation outcomes. vs2/1w5 may consume resulting state but do not own this receiving engine. Local same-user execution remains supported through the same policy semantics. Host maintenance admission and updater separation from replaced deployment remain mandatory.

- [ ] SC2: Wrong user/project/attempt/head, substituted digest/target/repository/sink, revoked grant, expired lease, writable/symlinked trust paths, forged receipt and arbitrary argv all refuse before effects.
- [ ] SC3: Concurrent duplicates, receiver/client restart and deliberate disconnect after effect prove one effect or preserved uncertainty without blind retry. Read-only status and dry-run do not invoke handlers.
- [ ] SC4: Active-listener contention and stale socket/ownership tests preserve the correct listener; bounded malformed frames and stuck handler tests leave no writing descendants.
- [ ] SC5: Existing local and Unix client contract tests pass; installed cross-user proof uses genuine kernel identities and protected directories, not mocked Process.uid. Independent adversarial review accepts exact source.

## Evidence informing this draft
Current ServiceExecutor supplies Unix client/server-UID checking only. ServiceRequestService currently claims and settles through a caller-local AttemptCoordinator; cross-user receipt paths and journal authority therefore require explicit design. qjx docs assign receiver-side authentication to a domain receiver, whereas gad.b forbids a new domain daemon/auth engine. This task resolves that ownership conflict in ACE without restoring labd or a root broker.
