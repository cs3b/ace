# Submit canonical results and fetch authorized evidence


## Observable outcome and ownership

One mapped live worker submits its exact bounded business result as canonical
private metadata/artifact bytes and receives a sanitized immutable result
reference. An individually authorized peer retrieves one purpose-bound canonical
artifact, including retained evidence where allowed, without requester paths or
project-wide raw access. This child owns ONLY submit_result/evidence_fetch source
handlers, public client/consumer routing, closed contracts and their verification.
It is the independently executable result extracted from still-draft xz9.0;
xz9.0 consumes this child for terminal integration and depends on it, never the
reverse. It does not depend on 9c2, xz9.2, campaign integration or positive finish.

Prerequisites are accepted 09j launch origin/native peer mechanics and the
accepted service/canonical-evidence source checkpoint
f91b02889cd465250640c61076835dba7aeed7b5, integrated in main closure
3678bd21f99d52cf4cce338587ca7d6f556a8ca2 (reviewed combined base
4f0ca839fc18b98772ffd09b5b8cf7ee34d313f2). The implementation plan must use
this exact accepted source or a separately reviewed descendant.
This source prerequisite is not completion of the whole xz9.0 task. 09j's
remaining installed crash/restart matrix/filter limitation remains separate.

## Closed public contract

The family amendment's Closed wire schemas, Submitted result identity/digests
and Purpose-filtered evidence fetch sections are normative. Reuse existing
Server/Router, ReceiptTransfer, CanonicalEvidence, EvidenceJournal/JournalMutation,
ReceiptVerifier and injected Lab visibility owner; no second journal, controller,
policy dialect or wire-selected callback. Exact schemas are:

- submit_result envelope mutation_id required; params mapping_id, assignment_id,
  attempt_id, expected_generation, candidate_generation, head, receipt_sha256,
  transfer; fixed receipt_artifacts upload. Derive exact mapped live worker
  lineage; normal receipt producer must equal canonical worker attribution.
- evidence_fetch mutation_id null; params mapping_id, assignment_id, attempt_id,
  kind, purpose_id, artifact_id; fixed artifacts download of one referenced blob.
  Resolve exact historical purpose and current peer/visibility before bytes.

Submission verifies raw receipt SHA256 and original ExecutionReceipt digest,
imports declared ordered bytes, normalizes artifact references and records the
closed private result_submitted event plus sanitized reply in one existing CAS.
Failed receipts may have zero artifacts and still require private chain/binding/
digest provenance. Fresh/replay responses never reveal private receipt/native
binding. One result per candidate generation; correction requires a new canonical
generation even at identical HEAD and new exact review before successful finish.
Exact worker retry remains live/active only; after exit/terminality refuse
fail-closed. No submission emits receipt_accepted/terminal truth or frees scope.
Campaign-bearing receipts remain safely refused; mandatory support is ig3-owned.

Fetch uses one immutable canonical read commit for descriptor and blob. Owning
worker gets own result only; current assigned reviewer gets exact review and
same-candidate result under retained process-purpose binding; executor gets only
own service request evidence; exact launcher/mapped supervisor get permitted
attempt evidence. All require current project visibility and the family native
principal conditions. Unsupported inbox/observation provenance fails closed;
this child adds no signer/observer implementation. Corruption cannot fall back to
cache/filesystem. Normal Server error/response bounds and exact family projections
apply to both fresh and replay behavior.

## Success criteria

- SC1: Real canonical result upload returns exact public digests/references and
  one immutable private result_submitted record in the same CAS, including a
  failed zero-artifact result; producer/native details never leak in replies.
- SC2: Forged producer/process, stale candidate/generation, extra fields, framing
  bounds/order/digest errors, new-ID duplicates and changed-ID replay refuse
  with unchanged accepted state; exact replay imports once and exit retry refuses.
- SC3: Fetch returns one descriptor-bound canonical blob only for every permitted
  role/purpose, current visibility and native principal. Historical terminal
  evidence permissions hold; reassignment/revocation/wrong kind refuses.
- SC4: Missing/corrupt event/blob/provenance and deleted caches remain truthful
  after fresh-reader restart; no requester local fallback or path access exists.
- SC5: Same-head corrected result requires new generation and does not replace
  the previous record; consumer/client routing uses the existing authority public
  seam and private uploads without source-owner duplication.
- SC6: Full-service guard remains closed while finish/recover/inbox/no-effect
  operations are incomplete; independent frozen-source review and executed
  relevant package/default fast tests support this child alone, not full program.
