## Decision supported by source

Use the existing pinned Herdr `agent.prompt` operation **without wait**, through the existing trusted mapped launcher/supervisor ProtectedNativeControl owner, never a new text/Enter injection implementation. A valid positive response establishes terminal input submission only. Preserve one canonical durable issuance before one native request; lost/malformed/error replies after issuance remain uncertain and cannot retransmit. Scope/terminal replacement safety must be explicitly resolved before readiness promotion: this native request has no expected-incarnation condition.

The method and acknowledgement are available from source; installed protected acceptance is still unavailable and is not claimed. No need to run probes to choose the method. The remaining technical decision is whether accepted9c2's exclusive immutable per-attempt server/resource policy positively prevents target replacement during prompt issuance, or whether the pinned upstream/native method needs an expected terminal/origin field. A read-then-send followed by response validation alone cannot enforce before-effect refusal on replacement.

## Exact protocol

- Existing `.ace-local/lab-readiness/herdr-source/server.rs:429–438`: dispatches Method::AgentPrompt to prompt_agent; `:612` maps agent.prompt. Native JSON newline frame is `{id:String,method:"agent.prompt",params:{target:String,text:String}}`; omit wait. Schema is `prompt-research/src_api_schema_agents.rs:178–184`; optional wait contains until statuses and timeout_ms, not an idempotency key or incarnation condition. Request.id is correlation, not durable deduplication.
- `prompt-research/src_api_schema_response.rs:24–44,104–106`: success `{id,result:{type:"agent_prompted",agent:<AgentInfo>}}`; error `{id,error:{code,message}}`. AgentInfo supplies terminal_id, pane_id, workspace_id, tab_id, agent/session/status and revision; it contains no receipt of business consumption and no bound prompt digest. Treat raw response as private and produce only bounded canonical steering projection.
- `prompt-research/src_api_wait.rs:163–180`: wait omitted directly dispatches one request with no app response timeout. With wait, server adds pre-observation, activity/status waiting and may return agent_prompt_stalled after submission. Do not use wait to define submission or retry authority. ACE's own transport deadline remains bounded even though native app receive is unbounded; disconnect/lost reply does not establish cancellation.
- Native server initial frame max1MiB, initial read5s, write5s (`server.rs:30–33,689–738`). 16KiB raw UTF-8 prompt expands under JSON escaping, but worst-case control-character expansion plus envelope remains below1MiB. No source prompt-text max is enforced beyond native frame limit and nonempty string; ACE must enforce its own16KiB UTF-8 bound.

## Ack and failure timing

`prompt-research/src_app_api_agents.rs:82–106` defers response until completion.recv returns Ok(Ok). `:111–214` validates nonempty text, resolves target, rejects blocked agent, missing/not-ready foreground or pending launch, obtains runtime, queues existing encoded submission, and records AgentInfo. Queue writes text then one Enter after300ms (`:13`). `prompt-research/src_pty_actor_unix.rs:860–879` sends Ok only at Enter completion boundary. `:882–901` schedules Enter after delay. Thus positive ack is stronger than enqueue-only and weaker than agent consumption/completion.

Definite source prequeue refusals: empty_agent_prompt, agent_not_found, agent_target_ambiguous, agent_blocked and agent_not_ready. They happen before prompt text/Enter queueing. A blocked state is not a busy queue. Working agents are not rejected by this code merely for being working.

There is **no agent_pane_busy prompt code**: that code in `src_app_agents.rs:260` is an agent-start conflict. Queue full is WouldBlock (`src_pty_actor_unix.rs:143–179`) but maps to the same `agent_prompt_failed` as PTY closure/failure after text may have been written (`src_app_api_agents.rs:94–99,214`). Do not infer no-send from that public code or parse human error message to turn it into retry permission. Treat agent_prompt_failed, server_unavailable, timeout, disconnect, invalid response or acknowledgement identity mismatch after durable issuance as uncertain. agent_prompt_stalled with wait means post-submission observed activity absent and is also uncertain. No timeout proves no effect.

There is no native duplicate-request ledger or cancellation handshake in the inspected prompt path. A response thread can fail to send after native submission. Canonical same-mutation retry must return recorded outcome without invoking again; an issuance with no positive outcome stays uncertain. Source prequeue typed refusal can record a truthful refusal, but must never silently cause a second send under the same identity.

## Exact target limitation

`prompt-research/src_app_terminal_targets.rs:74–103` resolve_agent_target recognizes an existing public pane containing an agent, then exact agent name. Unlike resolve_terminal_target at33–70, it does **not** first match terminal_id. Sending terminal_id as agent.prompt target therefore cannot be assumed supported. Unknown/ambiguous targets refuse.

The request schema has no expected_terminal_id/process_birth/server_generation; native handler resolves target at dispatch time. Existing ACE ProtectedNativeControl observe (`ace-herdr/lib/ace/herdr/molecules/protected_native_control.rb:93–114`) checks pane/workspace/tab, pane.process_info and records terminal_id/process identity; request (`:29–47`) pins socket inode, live server, kernel connected peer and rechecks installed server afterward. This protects server endpoint identity, but preflight/observe and later prompt are distinct requests. Response AgentInfo can be compared to expected terminal/workspace/tab, but replacement can already have received input before a mismatching ack is rejected. Exact before-write guarantee requires enforced immutability of the isolated attempt target throughout issuance, or a source-owned native atomic incarnation guard. Do not invent a second controller or arbitrary key path to evade that gap.

### Accepted9c2 does not establish prompt target immutability

The scope proposal at `scope-owner-proposal.md:160–162` explicitly includes all native-created processes because the native server is inside the scope; containment accounts for native creation, it does not forbid native layout changes. At276 it mounts this slot's native control socket. `local-writer-boundary-proposal.md:129–132` also leaves the worker's own native endpoint visible. `native-readiness-acl-feasibility.md:223–225` repeats peer/generation checks for later native access and retains uncertainty on native mutation concurrent change. At194 it expressly allows worker socket removal/ACL change to cause uncertainty/refusal; same-User endpoint ownership is not immutable authority state. Fresh session/no restoration at scope proposal153–158 applies generation startup, not permanent pane binding. No inspected normative9c2 rule forbids pane close/reorder/replacement during the run or supplies atomic expected terminal/process matching at prompt dispatch.

Therefore **xz9.2 specification readiness remains blocked on an actual guarded native submission primitive or a concrete independently reviewed enforced target-immutability mechanism**. Existing agent.prompt chooses a public pane/name at effect time and cannot by itself fulfill replaced-target refusal-before-dispatch. The generic method/ack decision is closed from source, but exact-target safety is not. Dedicated server/scope isolation is not a substitute for this missing binding. A source-owned extension to the existing native method that atomically verifies expected terminal/origin before input is a plausible technical repair, but is not delivered or selected by this report. No execution/probe is required to identify the gap; no installed claim can be inferred.

## Existing ACE adapters are semantic references, not protected retry owners

`ace-herdr/lib/ace/herdr/molecules/herdr_executor.rb:59–61` runs CLI agent prompt; `:92–97` agent_wait is a separate status wait. CLI v0.9.3 `prompt-research/src_cli_agent.rs:834–852` sends exactly one AgentPrompt with wait absent by default; --timeout requires --wait. Busy retries elsewhere in that file apply agent-start, not agent-prompt.

`ace-herdr/lib/ace/herdr/organisms/runtime_adapter.rb:180–202` normalizes one agent prompt via SendContract; it also supports plain-pane/key behavior unsuitable for protected steering. `ace-runtime/lib/ace/runtime/atoms/send_contract.rb` explicitly says lifecycle wait never authorizes completion/receipts/pruning. Executor's broad AgentNotReady mapping for agent_prompt_stalled and errors.rb's historical safe-to-repush comment must not become protected retransmit policy. ProtectedNativeControl generic request currently collapses native errors to runtime unavailable; a future source-owned prompt method needs bounded error-code classification while preserving uncertain issuance semantics, not importing CLI retry rules.

## Authority transport/framing decision

Public prompt body must be one bounded ephemeral UTF-8 transfer part, max16KiB, separate from closed control params. Raw16KiB text in params can exceed control limit after JSON encoding. `ace-assign/lib/ace/assign/authority/server.rb:138` limits transfer control headers16,384; Client `:26–49` builds descriptor and writes bounded header, sends body then write-EOF. TransferCodec has source-owned purposes/limits; no prompt purpose exists today (`transfer_codec.rb:14–18`). Add one fixed purpose (e.g. prompt_text) with [16KiB,1,16KiB], closed descriptor/digest/byte equality, bounded UTF-8/nonblank checks, worker/executor exclusion, no raw body in mutation events/replies/logs and private spool cleanup. This is an explicit source/spec change, not an existing delivered operation. Native request may carry text internally because its distinct1MiB frame permits it; user never chooses native method,target,socket or executable.

Canonical identity must bind caller/action/attempt/original generation/body digest/bytes. Owner-admitted mapped driver gets text ephemerally, verifies exact pinned target/origin, records issuance under existing lifecycle/journal before sending once. Recovery cannot reconstruct or resend raw text from canonical journal. Define stale principal/unsupported capability preissuance refusal and issued-unknown retained uncertainty in the spec. Raw native request logging must be audited during implementation; inspected source uses no prompt-body logging in these handler paths, but this research is not a complete installed logging audit.
