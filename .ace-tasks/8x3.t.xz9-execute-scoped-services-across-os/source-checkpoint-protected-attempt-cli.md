## Next maintained consumer responsibility map

Result submission belongs to the actual admitted worker workflow. `Authority::PreparedInput#drive_prompt` renders exact original mapping/assignment/attempt hints and already directs queue/report completion. `Authority::PreparedWorker#run` verifies the captured queue complete while the original worker is still active, then returns without canonical result submission. The worker or its authenticated descendant must invoke a protected result upload before it exits; a launcher or supervisor may only consume the accepted result for finish. `EndcapResults#submitting_worker!` and `authorize_result_transfer!` retain the actual peer, original worker/server liveness and descendant gates. No launcher-generated receipt may substitute for this hook.

The upload consumer should reuse existing `Client#call("submit_result", ..., upload_parts:, purpose: :receipt_artifacts)` and `ReceiptTransfer`, retaining receipt-first exact SHA, at most 16 artifacts/17 parts, 16KiB receipt, 64KiB per artifact and 256KiB total artifact bounds. Original caller-provided head/candidate generation, authority generation and stable mutation remain explicit; no silent refresh or automatic resend after a lost reply. `attempt_status` exposes the existing worker-authenticated authority generation and selected result projection. `submit_result` also requires an already accepted candidate. `Endcap#dispatch("submit_candidate")` exists for worker/launcher but has no public worker producer command today; queue completion cannot stand in for candidate acceptance. Candidate capture/upload must therefore be included in the next original-worker producer composition, reusing the existing CandidateTransfer admission rather than a second repository authority.

Result tests must run actual registered worker command → real Client/Server → existing transfer/candidate/result owners → canonical acceptance, then supervisor finish with independent review and no-writers/settlement. Required negatives include launcher impersonation, replacement worker birth, missing/unaccepted candidate, corrupt receipt/artifacts, wrong original generation and changed same-ID bytes; exact upload replay and lost-reply reconciliation cannot upload a second result.
