# Observe native inbox outcomes before signed reconciliation

## Outcome and scope
A trusted supervisor obtains provider-native evidence for the exact inbox delivery before lab-config signs consumed/superseded proof. Existing y23 validates proof, but NativeQueueExecutor only proves submission. This new ACE scope owns trustworthy native observation extraction/correlation; gad.b owns protected signer policy and reconciliation, gad.8 owns keys/context installation. No second inbox or assignment ledger. Advisory size: large; cover native Codex and Pi explicitly.

## User experience and public contract
Add read-only `ace-herdr inbox observe --event EVENT --format json` in the protected supervisor execution context. It loads the authoritative event binding and queries the bound native runtime; caller cannot supply outcome, signer ID, digest, replacement identity or an arbitrary observation path. Return `observed` with a verifiable native reference and exact event/attempt/generation/payload/native binding, or `uncertain` with a classified missing/unsupported/stale observation reason. It does not sign, reconcile, resend, cancel or advance the event. Public output contains correlation and sanitized provenance, not message bodies, private keys, OTPs or unrelated conversation data.

The operation distinguishes provider-accepted submission from actual consumption. A positive consumed observation must establish native acknowledgement of this exact payload/delivery, not a later unrelated turn or matching text alone. Positive supersession must establish old queued payload cannot still be consumed. Native queue absence, elapsed time, terminal text, caller assertion or unverified filesystem content is never such evidence. Wrong/missing correlation, native history truncation, session replacement without evidence, reconnect gaps and conflicting observations yield uncertainty and retain resources. Observation is rechecked against current event generation before signing/settling; stale evidence never advances a new claim.

Use documented/native provider surfaces and the existing Pi integration owner for any required provider-side observation extension. Do not build private transcript scraping as an authority or pretend unsupported native functionality exists. A trusted operator may supply independently inspected native evidence through gad.b only when its trust/correlation is proved; merely being the requester or knowing event fields cannot grant signing authority. Existing RSA and pinned-fingerprint receipt contract remains unchanged.

## Success criteria and verification
- [ ] SC1: Real native Codex and Pi scenarios provide positively correlated consumed evidence; wrong event/digest/generation/native target and unrelated turn are refused. Scripted submit receipt alone cannot satisfy this.
- [ ] SC2: Actual eviction/expiry/thread replacement evidence proves supersession; a vanished queue or timed-out call stays uncertain. A verified replacement target is bound to fresh runtime identity.
- [ ] SC3: Observer/runtime restart, compaction, lost history, truncated/corrupt observation and concurrent generation change retain uncertainty or reproduce the same verified observation without resubmission.
- [ ] SC4: Requester cannot forge observation authority; public output and retained artifacts omit message bodies/secrets. Root/domain signer can independently verify provenance before producing y23 receipt.
- [ ] SC5: Consume observation through gad.b signing and existing y23 verifier under actual separate OS users; valid consumed settles once, valid superseded authorizes only verified retry. Wrong signatures/keys remain rejected.
Run ACE ace-herdr and affected Pi integration tests, then installed native failure drills with recorded provider versions/source SHAs and sanitized native observation artifacts. Component tests cover every refusal; native scenarios cover positive outcomes, not just safe refusal. Retain evidence with task; gad.2 remains full-Lab acceptance owner.

## Existing implementation boundary
NativeQueueExecutor invokes Codex queue or pi-overseer-queue-client and returns accepted/exit data. Inbox validates signed externally supplied proof but does not acquire native consumption evidence. Preserve those delivered histories. This task is a prerequisite for automatic native settlement acceptance in gad.b and recovery/vs2 installed drills; their deterministic consumer development may proceed meanwhile.
