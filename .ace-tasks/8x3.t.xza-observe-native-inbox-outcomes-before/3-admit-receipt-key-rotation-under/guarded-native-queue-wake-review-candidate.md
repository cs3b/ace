## Existing owners and the precise gap

`Inbox#submit` invokes the existing NativeQueueExecutor with the retained event payload and digest. Accepted submission persists its correlated signed delivery receipt and the delivered/wake decision before `attempt_wake`. Busy targets use their native queue without a wake. `Inbox#wake_idle` sends only the fixed string `Check your native queued messages.` through `HerdrExecutor#agent_prompt_bounded`; it does not send the event payload. However, that plain CLI call selects a pane and supplies no original guarded origin. Its generic failure becomes pending and `retry_wake` may issue again. Neither behavior is sufficient for protected original-target delivery.

`ProtectedNativeControl#prompt` is an arbitrary bounded text operation reserved for an already accepted canonical steering issue permit. Preserve that requirement and its call sites. Its private `submit_prompt` already joins `agent.prompt` to the exact captured `expected_origin`, authenticates the selected socket/server before and after exchange, requires exact correlated guarded submission acknowledgement, classifies only explicit native `phase=not_issued` errors as refusal, and otherwise returns uncertain without retry. Reuse those transport/result checks for a DISTINCT source-fixed queue wake; do not call the public arbitrary-text `prompt` without a steering permit or invent unsupported Herdr CLI flags.

## Proposed bounded domain operation

Add a source-owned protected wake adapter whose internal operation takes only the already verified original binding and the exact retained delivery association. It accepts no text argument, target override, caller permit, environment selection or serialized trust boolean. Its sole native text is the existing fixed string above. It cannot submit a queue payload, alter a receipt, mark native consumption, publish a canonical permit/reconciliation/import or clear an admission.

Before this operation is reachable, the maintained context owner must authenticate the explicit original project/assignment/mapping/context tuple through the existing fixed authority endpoint and original inbox_binding, and join the unique accepted record_launch digest and guarded origin to the retained DeliveryRecord and direct invocation's actual claim. The original guard cannot be reconstructed from a current pane or a caller's process description. The v2 direct binding and retained original association are prerequisites; a raw binding Hash alone is not a public authorization API. The authenticated original mapping supplies the actual existing ProtectedNativeControl socket/server selection. SAME installed release/resource ownership must make that exact channel available to the context service; a writable mount or root UID is not evidence of authorization.

Under the existing context→event exclusions, require the exact current direct delivery admission, key/epoch, event/attempt/payload, actual claim, original target association, accepted queue receipt and delivered state. An idle/done observation of that same guarded target may owe a wake; a busy observation records none. No wake precedes durable accepted queue submission. Before leaving those exclusions, persist a wake issuance intent in the SAME DeliveryRecord wake field; no new ledger or canonical event is introduced. Retain the direct issuer as running until the native call has returned and owner readback is durable. No event/context lock spans native IO.

The protected wake field has a closed shape `{status,claim_generation,binding_digest}` with status `pending`, `issuing`, `sent`, `not_issued`, `uncertain` or `none`; claim is the exact positive admitted claim and binding_digest the exact accepted original launch binding digest. A bounded fixed refusal code may additionally appear only for not_issued. `pending` denotes positively not yet entered native IO; `issuing` is durable before entry and becomes uncertain on interrupted/restarted observation. Exact submitted acknowledgement records sent. Only the existing closed native not_issued reply records not_issued; missing, malformed, foreign-origin, lost or late reply records uncertain. Failure to persist a returned result leaves issuing and cannot be interpreted as not_issued. Existing signed queue receipt and delivery state remain unchanged by all wake outcomes.

An explicit supported retry may invoke a wake only from positively pending or not_issued, after the same current admission/original guard checks. Sent, none, issuing and uncertain never invoke again. Replaying an unknown issuer remains read-only under the existing admission/recovery contract. Canonical consumption/supersession and verified no-writer recovery may settle the retained admission through their existing owners; they do not assert a wake was not issued or automatically issue a second wake. Any later explicit queue retry requires its existing canonical settlement/current-generation rules and invalidates the prior wake association with that new claim. No timeout or absent process is a native refusal proof.

This domain operation is distinct from steering because its source-fixed input can only notify the already durably persisted native queue associated with that exact admission. It cannot carry arbitrary instructions or create permission for another target. The existing arbitrary-text steering operation still requires its canonical permit. Whether this constrained queue-domain notification is accepted as a separate supported operation is the explicit review decision requested here; current transport mechanics alone do not authorize the change.
