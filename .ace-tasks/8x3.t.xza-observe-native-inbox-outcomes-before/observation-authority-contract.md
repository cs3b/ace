Candidate consumed proof: read the exact bound thread through the authenticated native connection, locate the matching clientId in an identified userMessage item/turn, verify canonical submitted content digest and recorded queue mapping, and retain a sanitized native reference `{provider, version, thread_id, queued_submission_id, client_user_message_id, turn_id, item_id, payload_sha256}`. This is eligible ONLY after a genuine disposable-runtime drill proves client ID propagation, message-start/consumption semantics, duplicates, busy queue progression, restart/history retention and unrelated identical text separation. A history item may prove insertion without execution; if the tested semantics stop at insertion, require positively observed native turn-start for the exact item before claiming consumed. The precise native acknowledgement definition remains the blocking question. Missing clientId, truncated history or unsupported version returns uncertain; do not infer from a later turn or queue absence. Do not promote on this candidate design alone.

## Protected observer and signer boundary

Observation runs for deployment-controlled supervisor runtimes only. gad.8 installs fixed runtime-owner UID, native endpoint/version, observer UID, authority endpoint and protected evidence root mapping by immutable runtime identity; workers cannot select an endpoint, source path, observer ID or version. Native observations from worker-owned transcripts/files are untrusted regardless of content. A runtime writable by the requesting worker cannot establish this trust boundary and returns uncertain until an independently authenticated operator supplies genuinely verified native evidence under gad.b.

The reusable ace-herdr observer authenticates native endpoint ownership/Unix peer where available, or controls a provider subprocess launched under the mapped protected runtime context with fixed executable/config; no request-selected argv or transport. It writes sanitized immutable evidence through the protected assignment authority evidence-import API. This is source proof storage, not another inbox/delivery ledger. Raw message bodies are compared transiently for digest and are not published/stored as observer artifacts. Persist exact source/version/reference, full event/attempt/generation/payload/native binding, observation outcome, source artifact hash, current process binding including OS birth and provenance. Read-only `inbox observe` never signs or transitions an event. A reference is an authority-issued opaque evidence ID, not a filename the worker can replace.

gad.b runs signing under a distinct protected signer UID, reads the current canonical Herdr event, fetches and independently verifies the retained authority evidence against the fixed observer/runtime trust map, and constructs the existing y23 proof. No signing oracle accepting caller observations, claimed observer IDs or raw receipts. gad.8 protects all trust configuration/public-key ancestry and the private key, retains the pinned key while unresolved events exist and serializes rotation against enqueue/reconcile. An authenticated worker can request inspection but cannot choose its outcome. Arbitrary runtime output or a compromised trusted supervisor is outside this mechanism's guaranteed trust; a worker-controlled runtime is explicitly inside refusal coverage.

The signer verifies native/event generation again immediately before producing the immutable signed bytes. Herdr's existing reconcile lock validates event/attempt/generation/full binding and pinned key before the transition. If the generation changes after signing, reconciliation refuses stale proof; it does not re-sign for a new generation. Assign's public bind_inbox/reconcile_inbox paths own registered consumer journal facts and route proof through the current expected_registration-under-event-lock contract; the owner cannot call bare Herdr reconcile then trust an independently observed transition. Crash after reconcile before service receipt is recovered from canonical event plus exact signed proof through existing idempotent APIs. No new long-lived inbox reservation protocol is needed for the observation/sign race.

## Supersession decision

A queue delete response/start response or replacement session alone is not accepted yet. The supersession child must prove atomic native eviction/expiry or thread termination/replacement which guarantees the old exact submission can no longer execute, including concurrent dequeue. A retained delete acknowledgement without documented/tested race semantics is uncertain. Session replacement signs the positively verified retirement of the old target AND a fresh Herdr replacement_target; a new UUID alone does not retire an old live runtime. Consumed wins only when exact positive consumption evidence exists; conflicting positive outcomes are uncertain/escalated, never guessed by timestamp. No disappearance/time inference and no terminal-dead mapping.

### Authenticated observation import/fetch and signed proof routing

Root-owned project map extends with `inbox_contexts.ID.owner_uid`, `socket_path`, `state_root`, `runtime_bindings`, `observer_uids`, `signer_uids`, `maintenance_uids`. A runtime binding includes project, owning assignment/attempt registration, provider and exact immutable native target/process binding; observer ID is owner-derived from peer UID, never payload authority. Herdr inbox_context owner alone accesses its 0700 event store; assignment authority talks to its fixed authenticated ACE context endpoint, not private directory traversal. Generic endpoint/API is ACE-owned. No domain daemon or cross-user chmod is allowed.

`import_observation(project_id, attempt_id, event_id, inbox_context_id, expected_registration, observation_bytes)` is permitted only to a configured observer for that exact runtime/project. Authority independently loads registered attempt/inbox/context and asks authenticated context owner for current event snapshot, checks event/attempt/generation/payload/complete binding and exact process birth, then imports bounded immutable evidence using xz9's canonical Git blob/provenance contract. `observation_bytes` is schema v1: `{schema: ace.native-observation.v1, provider, provider_version, event_id, attempt_id, claim_generation, payload_sha256, binding, runtime_process_binding, outcome, native_reference, source_sha256, source_bytes, source_excerpt}`. source_excerpt contains only sanitized native ID/status acknowledgement fields, no prompt/response content, secrets or arbitrary files. outcome is consumed or superseded; exact evidence kind must match existing y23 values. Unknown fields or unsupported/missing native references refuse. Event registration includes event_id/attempt_id/payload_sha256/receipt_key_sha256; current claim generation/full binding are additionally verified. source_sha256 covers the retained canonical sanitized source bytes, not an unretained message body. Content digest of actual payload is checked transiently by trusted observer against canonical event. Limits: each artifact 64 KiB, total 256 KiB; artifact provenance/import IDs generated by owner. Identical content/binding import returns same evidence ID; conflicting claims do not override an old artifact. Contradictory positive outcomes flag uncertainty for current generation and cannot be signed without resolving native conflict.

`fetch_observation(project_id, attempt_id, event_id, evidence_id)` returns exact retained bytes, SHA256, canonical blob/ref commit and peer-derived import provenance only to signer/supervisor allowlisted for this context. Observer can fetch its own imported artifact; worker status returns sanitized ID/outcome/uncertainty only. ID lookup never grants cross-project access. Signer recomputes bytes hash/schema, checks canonical authenticated owner/ref descriptor, mapped observer/runtime/provider/version and current context registration, then verifies actual native-reference semantics. Trusting a hash alone is insufficient. Missing current registration/generation, source/version incompatibility, changed keys or inaccessible native endpoint stays uncertain. fetch is read-only and deterministic across restart, including historical evidence visibility for exact registered signer while current grant permits it.

`inbox_context snapshot/bind/reconcile` is a reusable fixed ACE endpoint under context owner UID. Assignment authority derives peer-authenticated requester identity; bind is owning active attempt only, reconcile is mapped signer/supervisor only. For reconcile, signer sends exact signed JSON bytes plus detached signature over the protected authority transport, not filesystem receipt_path. Authority retains these bytes/provenance in canonical qjl import storage and creates its own private receipt/signature projection for the current public coordinator call. The configured context client forwards signed bytes and canonical expected_registration; context owner performs current Herdr signature/key/binding/generation and expected_registration checks under the event lock. The assignment consumer appends its fact only from that verified result. Current coordinator direct path reads must become private owner projections or a bytes API; signer/authority/context private roots never need mutual filesystem read. expected_registration and exact accepted proof replay from accepted recovery repair dab0dbeea are required semantics even though this older spec worktree does not include that source.

Cross-store crash: the protected import may commit before Herdr settles; it remains proof material, not a claimed inbox transition. Coordinator request resumes with those exact bytes. Herdr transition before qjl consumer event resumes via exact accepted proof replay under expected_registration, appending the missing consumer fact once. qjl import/consumer correlation uses a proof digest; a new signature/proof for another generation cannot complete the old operation. A bare completed/queued status, receipt filename or claimed previous transition never substitutes this replay. Bind_inbox/reconcile_inbox remain sole consumer mutation APIs; Herdr remains sole event transition owner.
