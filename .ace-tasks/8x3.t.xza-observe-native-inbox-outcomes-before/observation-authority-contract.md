## Codex extraction candidate

Installed primary-checkout research records Codex 0.159.3 experimental app-server schema. `thread/queue/add` accepts clientUserMessageId; queuedSubmission returns id and clientUserMessageId; `thread/read` with includeTurns exposes userMessage.clientId. Existing NativeQueueExecutor uses `codex queue --thread --message` and does not bind a client ID, so observing that old CLI receipt cannot establish the desired correlation. The Codex child must own submission plus observation correlation through the version-probed native app-server interface. Record provider/version, immutable thread, queue submission ID and clientUserMessageId equal to a delivery correlation ID bound to event/attempt/generation/digest before submission. A reconnect/lost response does not submit again.

Candidate consumed proof: read the exact bound thread through the authenticated native connection, locate the matching clientId in an identified userMessage item/turn, verify canonical submitted content digest and recorded queue mapping, and retain a sanitized native reference `{provider, version, thread_id, queued_submission_id, client_user_message_id, turn_id, item_id, payload_sha256}`. This is eligible ONLY after a genuine disposable-runtime drill proves client ID propagation, message-start/consumption semantics, duplicates, busy queue progression, restart/history retention and unrelated identical text separation. A history item may prove insertion without execution; if the tested semantics stop at insertion, require positively observed native turn-start for the exact item before claiming consumed. The precise native acknowledgement definition remains the blocking question. Missing clientId, truncated history or unsupported version returns uncertain; do not infer from a later turn or queue absence. Do not promote on this candidate design alone.

## Pi extraction candidate and ownership

lab-config's current pi-overseer-queue.ts validates id/session/digest, calls sendUserMessage immediately or followUp, and returns accepted. It never observes delivery. Upstream [extension docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md) and [agent-session source](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/agent-session.ts) expose message lifecycle hooks and queue behavior. They do not establish a stable per-delivery ID on the installed Pi user-message hook.

The Pi child owns a reusable ACE Pi provider integration, including a native queue correlation extension replacing the domain extension mechanism. lab-config owns only installation/config. Do not stash generic correlation/authentication/event capture in lab-config. The provider extension must associate the exact delivery ID with the native queued message and then capture that same native message's start/turn entry in the live provider lifecycle, persisting a sanitized message/turn reference and payload digest. It must prove association when two equal payloads, user-typed equal text, queue reorder/clear, steering/followUp, session fork/reload and restart coexist. An in-memory FIFO matched by text alone is forbidden. If supported provider hooks do not carry identity, extend the provider-owned queue integration at its actual enqueue/dequeue boundary rather than inventing a message_start ID. The accepted instrumentation/API decision requires executed installed-version evidence before promotion.

## Protected observer and signer boundary

Observation runs for deployment-controlled supervisor runtimes only. gad.8 installs fixed runtime-owner UID, native endpoint/version, observer UID, authority endpoint and protected evidence root mapping by immutable runtime identity; workers cannot select an endpoint, source path, observer ID or version. Native observations from worker-owned transcripts/files are untrusted regardless of content. A runtime writable by the requesting worker cannot establish this trust boundary and returns uncertain until an independently authenticated operator supplies genuinely verified native evidence under gad.b.

The reusable ace-herdr observer authenticates native endpoint ownership/Unix peer where available, or controls a provider subprocess launched under the mapped protected runtime context with fixed executable/config; no request-selected argv or transport. It writes sanitized immutable evidence through the protected assignment authority evidence-import API. This is source proof storage, not another inbox/delivery ledger. Raw message bodies are compared transiently for digest and are not published/stored as observer artifacts. Persist exact source/version/reference, full event/attempt/generation/payload/native binding, observation outcome, source artifact hash, current process binding including OS birth and provenance. Read-only `inbox observe` never signs or transitions an event. A reference is an authority-issued opaque evidence ID, not a filename the worker can replace.

gad.b runs signing under a distinct protected signer UID, reads the current canonical Herdr event, fetches and independently verifies the retained authority evidence against the fixed observer/runtime trust map, and constructs the existing y23 proof. No signing oracle accepting caller observations, claimed observer IDs or raw receipts. gad.8 protects all trust configuration/public-key ancestry and the private key, retains the pinned key while unresolved events exist and serializes rotation against enqueue/reconcile. An authenticated worker can request inspection but cannot choose its outcome. Arbitrary runtime output or a compromised trusted supervisor is outside this mechanism's guaranteed trust; a worker-controlled runtime is explicitly inside refusal coverage.

The signer verifies native/event generation again immediately before producing the immutable signed bytes. Herdr's existing reconcile lock validates event/attempt/generation/full binding and pinned key before the transition. If the generation changes after signing, reconciliation refuses stale proof; it does not re-sign for a new generation. Assign's public bind_inbox/reconcile_inbox paths record consumer facts after verified canonical transitions; they do not append a custom second transition. Crash after reconcile before service receipt is recovered from canonical event plus exact signed proof through existing idempotent APIs. No new long-lived inbox reservation protocol is needed for the observation/sign race.

## Supersession decision

A queue delete response/start response or replacement session alone is not accepted yet. The supersession child must prove atomic native eviction/expiry or thread termination/replacement which guarantees the old exact submission can no longer execute, including concurrent dequeue. A retained delete acknowledgement without documented/tested race semantics is uncertain. Session replacement signs the positively verified retirement of the old target AND a fresh Herdr replacement_target; a new UUID alone does not retire an old live runtime. Consumed wins only when exact positive consumption evidence exists; conflicting positive outcomes are uncertain/escalated, never guessed by timestamp. No disappearance/time inference and no terminal-dead mapping.
