# Protected delivery service request — reviewed amendment

This closes the public worker-request join in the existing qkb.1 scope. It does not decide whether create/update/ready may precede independent review. Those operations remain unavailable in this protected delivery route pending the separate policy decision. The existing authority review/authorization gate is unchanged.

## Source-grounded gap and owners

`ace-lab service request` currently calls ServiceRequestService, which unconditionally constructs caller-local AttemptCoordinator and ServiceExecutor. Its CLI has no protected mapping, scope, receiver or exact candidate selectors. The delivered ProtectedServiceClient#submit already performs the worker-to-configured-receiver claim exchange, but no registered service-request CLI selects it. The accepted fixed merge producer and Assign protected delivery consumer cannot make that local request path valid.

Reuse the existing ProtectedAssignmentContext deployment/history classification and original PreparedInput fetch. Reuse ProtectedServiceClient for submission and the existing receiver → authority claim → exact candidate export → independent review/current authorization → one fixed executor → canonical complete_service import/result chain. Protected status reuses ProtectedDeliveryCoordinator. Lab already depends on Assign; no new dependency cycle, RPC, journal, executable selection or authority field is needed.

## Public request contract

For a protected worker, retain the existing `ace-lab service request` command and existing project, assignment, attempt, operation, input, authorization and request-id options. Add explicit `--mapping ID`, `--scope NUMBER`, `--service ID`, `--candidate-head SHA`, `--candidate-generation INTEGER` and `--expected-generation INTEGER`. All are required in protected mode. This delivery route initially accepts operation=merge only. Mapping/service names are lookup selectors, never grants. Do not infer them from PATH, ambient repository HEAD, current provider state or caller actor/UID strings.

```
ace-lab service request --project PROJECT --assignment ASSIGNMENT --attempt ATTEMPT \
  --mapping MAPPING --scope SCOPE --service RECEIVER --operation merge \
  --candidate-head SHA --candidate-generation GENERATION --expected-generation AUTHORITY_GENERATION \
  --input merge-input.json --authorization ORIGINAL_AUTHORIZATION --request-id REQUEST
```

Before authority or receiver contact, validate all selector shapes and refuse `--dry-run` in protected mode: there is no delivered pre-claim authority eligibility API that can promise the effect is permitted. Read the input from one held regular, no-follow, nonblocking file, bounded to existing ServiceInput.MAX_BYTES=64KiB with stable metadata/path identity. Strict JSON is one depth16 document, decoded duplicate keys/comments/additions/nonfinite values refused. Input is exactly the accepted normalized `{target,delivery,method}` merge shape. Compute its existing canonical digest and target from these exact retained bytes; no filename reaches the authority or executor. Invalid/special/raced input produces no claim or provider effect.

Fetch the original prepared capability using the maintained context/client, require its assignment/attempt/scope/project association to match explicit selectors, and preserve current/history protected-principal admission. This fetch authenticates original worker ancestry; it is not a new grant. Select RECEIVER only from that installed mapping's existing project.service_receivers and use the delivered authenticated ProtectedServiceClient. Missing current installed selection for a retained protected principal refuses; never restore local service execution because a current mapping/descriptor was removed or unreadable.

Expected authority generation is explicitly retained from the authenticated canonical candidate/review/status response that the workflow already consumes, such as the accepted review's authority response. It is a positive integer original invocation selector, never inferred from a local journal or refreshed on repetition. Candidate head/generation similarly remain explicit expected selectors. The existing claim CAS and exact current candidate/review checks reject a stale generation or race; no automatic refreshed-generation retry. PreparedInput supplies authenticated original assignment/attempt/scope/project admission; the receiver and canonical claim owner still verify current active scope and accepted independent review. No extra attempt-status RPC or public generation-read protocol is required by this amendment.

Construct exactly ProtectedServiceReceiver::SUBMISSION: assignment_id, attempt_id, expected_generation, candidate_generation, head, request_id, operation, input_digest, target, authorization. The fixed claim mutation ID is SHA256 of `qkb.merge.claim:v1:ASSIGNMENT:ATTEMPT:REQUEST`; these IDs use the maintained colon-free token grammar. Do not include mutable input, expected generation, authorization or candidate bytes in the mutation ID. Identical invocation uses the same ID; changed input under the same request cannot generate a fresh mutation to evade original binding. Preserve the five-second public receiver claim exchange; preparation/status reads precede it and do not turn that bound into a total command-duration promise. No execution/review/provider wait occurs in this CLI.

## Outputs, observation and recovery

Keep the public JSON envelope. Accepted output is exactly `{status:"ok",data:{selection:SELECTION,claim:ORIGINAL_VALIDATED_CLAIM_REPLY}}`. SELECTION has exactly project_id, mapping_id, assignment_id, attempt_id, scope, service_id, candidate_head, candidate_generation, expected_generation, request_id, input_digest and target. It is lookup evidence, never authority. An authenticated accepted claim explicitly reports claim acceptance/current canonical state, not merge success. Its original reply carries request ID, generation, canonical journal commit and replay metadata. Busy/refused or unconfirmed claim returns `{status:"error",error:{code:CODE,message:MESSAGE,selection:SELECTION,claim:ORIGINAL_VALIDATED_CLAIM_REPLY}}` and nonzero exit; code is service_claim_refused or service_claim_unconfirmed. Unconfirmed does not mean no effect and never causes automatic resubmission or provider merge. All output remains bounded to 16KiB and omits input bodies/secrets.

For protected `ace-lab service status`, retain --request and require explicit project/assignment/attempt/mapping/scope/candidate-head/candidate-generation/input-digest/target, with nullable artifact-digest matching the original target. Reject mutation/input/authorization/dry-run options before input reads. Delegate the existing exact protected merge-status consumer; it authenticates original admission, canonical completion/import/result and artifact before reporting succeeded delivery. Pending/uncertain status matches the original expected input digest too. Reads do not append, repair or rerun anything. Agents may equivalently use the already delivered exact `ace-assign delivery --operation status` path; workflow instructions must show one actual supported command, not a local journal inspection.

The genuine standalone path keeps existing explicit local semantics. Protected-only flags in an uninstalled ordinary environment refuse rather than selecting an invented deployment. Installed unreadable/invalid deployment/history, protected retained UID with missing mapping, or any protected selection/admission failure never falls back to ServiceRequestService's local coordinator. No new force-local or compatibility path is added.
