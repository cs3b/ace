## Area-by-area assessment

**Kernel requester.** Verified end-to-end. `OrdinaryPeer#capture` double-reads `/proc/<pid>/stat` birth (boot_id+ticks) around `ps`, cross-checks SO_PEERCRED uid/gid, freezes the peer (`ordinary_peer.rb:13-28`). The exact peer (pid/uid/started_at/host) is pinned into `definition["requester"]` at admit; `command_claim!` requires exact hash equality (`command_owner_admission.rb:95-99`); the root helper independently requires `initial.dig("definition","requester") == request.fetch("caller")` before claim (`command_executor.rb:32`). Status after requester/owner restart degrades correctly to uid-account reconciliation (`command_reader!`, `command_owner_admission.rb:33-41`), and the ownership test (`command_owner_admission_test.rb:31-49`) proves post-revocation inspection without effect authority.

**Root launcher ancestry.** Sound. `command_launcher!` (`command_owner_admission.rb:63-90`) reads the pinned identity only through `GrantResolver.read_verified` (root-owned full-path traversal, O_NOFOLLOW, ≤8 symlink hops), requires peer uid 0, walks ≤64 `/proc` ppid hops that must all stay uid-0 on Linux, with `live!` birth re-validation at each hop and `parent <= 1` termination. PID recycling cannot forge `started_at`. Critically, the returned canonical daemon identity (not the ephemeral helper peer) is what enters the mutation digest and the recorded launcher (`command_execution.rb:46-50, 88`), so a new helper PID neither invalidates replay nor impersonates a worker — proven by `test_short_lived_helper_uses_canonical_daemon_identity_for_replay` and `test_policy_revocation_and_changed_launcher_refuse_without_new_history`.

**Immutable accepted context.** Verified. `verify_context!` (`command_owner_admission.rb:105-151`): `ProtectedSocket.root_path!` pins the entire ancestor chain root-owned/non-group-world-writable/non-symlink (defeats parent-rename substitution), `Find.find` lstats the whole cwd tree (uid 0, no 0o022 bits, no symlinks, files-or-dirs only, 20 000-entry and deadline bounds), executable ≤64 MiB read via `read_verified` with SHA-256 equality, and Git source provenance via `rev-parse HEAD HEAD^{tree}` + `status --porcelain` under `InstalledJournalRead::ENVIRONMENT` (NOSYSTEM, empty global config, no lazy fetch/replace/optional locks) — no git-config injection surface. Revalidation runs before claim and again before bind (`command_claim!`/`command_child!` both re-run `command_request!` and compare against the admitted definition), and again inside every CAS callback and replay authorizer.

**Literal argv / executor / whole service grant.** Verified. `CommandPolicy` is a closed frozen schema; `select` matches the *policy-owned* argv (never requester argv), requires exactly one argv match (ambiguous → deny), and the grant must bind kind/uid/command/executor and the exact sorted whole service set (`command_policy.rb:118-143`). Environment keys are denylisted (RESERVED + `GIT_CONFIG_`/`BUNDLE_`/`LD_`/`DYLD_` prefixes), conflicts between executor/service/secret destinations refuse, definition capped at 8 KiB. CLI parsing (`run.rb:11-34`) keeps everything after `--` literal, rejects duplicates/empty argv/stray options *before* client construction (tested), and post-admission failures collapse to `command_uncertain`, never a fresh usage refusal (tested).

**Same-journal lifecycle/replay.** Verified against `JournalMutation#mutate` (`journal_mutation.rb:49-139`): all four mutations go through the shared ref CAS with per-operation expected generations 0–3, digest over `{project, params, peer(canon), plan}` via sorted-key canonical JSON (deterministic across restarts), replay keyed on mutation_id with digest/operation/namespace equality — divergence is `Conflict` ("Mutation ID is already bound to different input"), so a re-forked child (different witness pid) can never rebind under `command-bind.#{id}`. `replay_authorizer` re-runs live admission before any replayed reply. Projection enforces chain validity, the strict admit→claim→bind→complete prefix invariant (≤4 accepted mutations), schema/project/execution association, and returns the last accepted data. Concurrency, restart projection equality, and journal-ref immutability on refusal are all covered by `command_execution_test.rb`.

**Gated child identity; lost bind ACK; no repeated exec.** Verified. The child is forked from a verified single-thread helper (`command_executor.rb:47`), does `setsid`, TIOCSCTTY, groups→GID→UID drop in the correct order, umask 077, `PR_SET_NO_NEW_PRIVS`, chdir, then blocks on the private gate pipe (`:63-84`). Only a **fresh, non-replayed** `command_bind` ACK releases the gate (`:93-96`); claim/bind replay raise before any exec (`:37, :94`), proven by `test_lost_bind_and_claim_replay_never_execute` (SecurityError, zero frames, child ESRCH, replay events exactly `[command_status, command_claim]`, no child). The 11-key closed witness schema is independently re-captured kernel-side by the owner (`command_child!`, `command_owner_admission.rb:101-125`) with zero-capability, pgid==pid, cwd, gid/groups equality against the policy executor. Lost complete-response replay is terminal-fact idempotent and correctly unchecked-for-replay.

**Namespace reservation.** Verified. `ordinary_lifecycle.rb:169-174` refuses the `command-` prefix on **every** ordinary route — the check lives in `authorize!`, which runs for status, dispatch, transfer admission, registration replay and the pre-CAS re-check — while `CommandExecution#namespace` writes only `command-#{id}`. The regression test proves refused registration *and* refused `registration_status` with unchanged ref and empty event stream. Router operation tables are disjoint; command ops carry no transfer binding, so a forged `params["transfer"]` is refused at the envelope (`socket_server.rb:186`).

**Framed output / status / PTY / cleanup.** Verified. Newline-JSON frames with base64 payloads, 131 KiB frame and buffered-input caps, socket backpressure, separate stdout/stderr streams, strict `started`/`result` frame schemas with exact execution-reference match, duplicate/late input EOF refused, `Errno::EIO` on PTY master handled. Client treats missing result as an error, never exit 0 (`command_run_client_test.rb`). PTY path preserves no-echo getpass, resize, and real signal death (kernel probe: signal 15 → 143); pipe path preserves EOF and exit 17. Teardown: 1 s post-zombie output drain, then group TERM/KILL with the direct child left unreaped so its PID cannot be recycled into an unrelated process group (`command_executor.rb:201-215`), bounded 5 s reaping on error paths.

## Concrete findings

1. **LOW — Detached-descendant teardown gap (coverage vs. plan).** `cleanup_group` (`command_executor.rb:201-215`) signals only `-pid` (the original group) and `pid`; a grandchild that calls `setsid()` escapes both. The requirement's test-responsibility map explicitly lists "detached descendants" among the scenarios to prove; no provided test exercises it. Risk is bounded (executor uid, NNP, all-zero caps) and the normative "Terminal and cleanup" clause promises only process-group termination — but the promised evidence is absent. Recommend a probe case and/or an explicit documented limitation.
2. **LOW — Privilege-gate asymmetry.** The helper CLI checks `Process.uid.zero? && Process.euid.zero?` (`command_execute.rb:12`) but `CommandExecutor#run` checks only `Process.uid.zero?` (`command_executor.rb:23`). A real-uid-0/euid-nonroot direct library invocation passes the organism check. Production path (labd → CLI) is unaffected; defense-in-depth nit.
3. **INFO — Caller identity trusted from labd stdin JSON.** The helper compares labd-supplied `caller` (`command_executor.rb:32`) rather than independently re-capturing SO_PEERCRED of the passed fd. Forgery requires the pinned root daemon to supply the exact admitted peer (pid+birth+uid+host), which only the genuine connecting process yields — matches the specified "Labd authenticates its actual caller" design; an independent fd re-capture would be pure hardening.
4. **INFO — Wire refusal-code laundering.** `OrdinaryClient` maps every server refusal, including the `invalid_input` produced by the command-namespace reservation, to `AttemptErrors::EvidenceUnavailable` with the code retained in the message (`ordinary_client.rb:47-52`). Fail-closed and deterministic; the namespace test's asserted class follows from this mapping, but callers cannot branch on the original code.
5. **INFO — Execution-id existence oracle.** `command_status` computes the projection before requester authorization (`command_execution.rb:23-28`); connected project participants can distinguish unknown vs. foreign references via missing-vs-unauthorized. IDs are 128-bit random and the socket is participant-gscoped (0660, service gid); negligible surface.
6. **INFO — TTY EOF semantics.** Client stdin EOF in interactive mode is forwarded as a `^D` byte to the PTY master (`command_executor.rb:145`), which is exact EOF only in canonical mode; a raw-mode child receives a literal 0x04. Pipe-mode EOF is exact. Consistent with "Interactive terminals preserve … signals; Pipe mode preserves EOF", worth a docs sentence at most.
