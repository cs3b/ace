# Allocate isolated review sessions under concurrent starts

## Behavioral specification

An operator can start independent reviews concurrently in the same checkout and cache root. Each invocation receives its own session identity and directory before writing prompts, metadata, reports or findings. Equal clock readings and simultaneous allocation must not cause sharing, replacement or cross-attribution. A session's subject, model output, evidence and feedback remain attributable to that invocation throughout completion, interruption and retry.

Automatic allocation returns distinct session locations even when timestamps collide or a candidate location already exists. Existing sessions remain byte-for-byte intact. Failure to allocate a writable session produces a nonzero actionable refusal before reviewer execution or writes to another session.

For an explicit `--session-dir`, an occupied nonempty directory is refused before modification. An empty explicit directory may be claimed by one invocation using a persistent exclusive ownership marker; a concurrent contender must refuse without touching the winner's content. The ownership marker remains after completion, failure or interruption; a claimed directory is never implicitly reclaimed. Existing files, regular-file paths and symlink session paths are refused without modifying their targets. This command does not implicitly resume or replace an earlier review. Existing dedicated campaign/delta/evidence APIs retain their documented behavior; this task introduces no new resume mechanism or historical migration.

Successful single-model release exports also use collision-safe exclusive allocation; equal completion clocks and models must not replace another invocation’s exported report. A release export retains the bytes of its own session report. Automatic session names remain `review-<compact timestamp>` with an opaque collision suffix when needed; callers use the returned path, not a guessed name. Allocation errors return `success: false` with an actionable path-specific error and the CLI exits nonzero before model execution.

## Interface and usage

Existing `ace-review --preset code-valid --subject ... --auto-execute` and `--session-dir PATH` flags remain. Output identifies the actual isolated session. Feedback list/create with that exact path can only consume its own reports; no shared latest-session pointer is evidence for concurrent review selection. See `ux/usage.md`.

## Success criteria

- [x] Two actual concurrent preparations with one fixed clock/cache receive distinct automatic session paths and retain distinct subject/prompt metadata.
- [x] Controlled concurrent reviewer outputs with different sentinel findings remain in their own reports and feedback collections, in either completion order.
- [x] An existing automatic candidate or explicit nonempty directory is preserved unchanged; automatic allocation isolates the new invocation and explicit reuse refuses nonzero.
- [x] Two invocations racing for one empty explicit directory cannot both own it; the loser writes no review artifacts there.
- [x] Interruption or unwritable allocation cannot overwrite or publish another invocation's results. Completed history remains readable.
- [x] Equal-clock single-model completions preserve both distinct published release reports.
- [x] Existing single-review and campaign/delta/evidence workflows pass affected tests and independent review.
