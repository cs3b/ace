# Include uncategorized fast tests in default complete verification

## Observable result

Default `ace-test fast` and `ace-test all` execute every deterministic `test/fast/**/*_test.rb` file, including newly introduced category directories, exactly once. Existing legacy category tests still execute. Adding `test/fast/authority` must not silently remove security-relevant verification from a package's advertised complete target.

## Contract and ownership

Owner: ace-test-runner discovery/default target configuration and sequential execution; existing ace-test CLI consumes that owner. No new CLI flags or package-specific authority allowlist. Default fast includes test/fast/edge along with every other fast subtree. Default `all` additionally selects test/feat and legacy test/edge and excludes separately owned test/e2e. Explicit project/user target overrides remain authoritative: a deliberately narrowed `all: [fast]` must not gain feat/e2e tests. Explicit category and file/line selection retain their existing scope; no blanket fallback may widen those invocations. Both by-target and single-batch modes select the same files without duplicate execution where patterns overlap. Reports list the actual selected/executed files and failure exit status includes failures in newly discovered categories.

This is one medium standalone behavioral slice. It repairs program verification, not native Lab acceptance or unrelated file-line semantics in jeo. No package runtime changes, paid providers, external services or Lab probes are needed.
