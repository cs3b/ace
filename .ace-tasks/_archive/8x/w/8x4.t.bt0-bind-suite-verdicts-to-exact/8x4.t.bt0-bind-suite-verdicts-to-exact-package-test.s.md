# Bind suite verdicts to exact package test invocations

## Observable outcome

Running a package test concurrently with a suite cannot change the suite's counts, verdict, assertions or report links. Each suite entry uses evidence produced by its own exact child invocation, including when multiple entries select the same package. This is one medium, independently deliverable test-evidence reliability slice owned by ace-test-runner; callers retain existing ace-test and ace-test-suite commands and test selection.

## Closed behavior and interfaces

Every actual test invocation owns a unique, collision-safe execution identity before execution; when report saving is enabled it owns a distinct report directory before writing results. Equal clocks, concurrent allocation and duplicate package selections never overwrite another invocation's evidence. Summary, detailed report and raw execution evidence belong to that same identity. Completed evidence is not silently reused or overwritten by later invocations. The existing latest convenience pointer may change; it is never an authority for an active/completed suite entry's result.

The suite binds the scheduled entry and its exact child process to that execution identity. It captures counts, assertions, success and immutable report location from that binding, once the child completes, and retains the same values through aggregation and rendering. A later unrelated run cannot change them. No package-name-only key or timestamp freshness check substitutes for invocation identity; separate entries remain separately attributable.

Missing, incomplete, malformed, mismatched or unreadable required machine completion evidence for this execution produces an explicit failed/unverifiable package result and nonzero suite exit, even if latest points at a valid earlier/later report or the child exited zero. A nonzero child exit, timeout or interruption cannot become success from any report. Existing failure details and executed counts are retained when trustworthy. No fallback to a stale report or an exit-code-only successful proof. Summary and detailed report cannot be combined across invocations.

Machine completion evidence is mandatory even with existing save_reports:false/--no-save-reports: the suite receives an identity-bound result snapshot containing the selected entry/package, completed selection (including explicit zero selected tests), counts, assertions and outcome, bound to that actual child. Optional detailed/human/raw report persistence remains disabled in that mode. There is no invented retained link: progress/final output explicitly has no saved report. This is intentional absence of optional files, not absent completion evidence. A child exiting before completion cannot masquerade as legitimate zero selection; zero tests are accepted only when that execution explicitly completed discovery with zero selected files. No-save mode neither forces persistent user reports nor falls back to exit-code-only proof.

Public progress, final table, totals, failure diagnostics and any detail links agree on the same execution. Both normal and simple displays preserve separate entry identity. Existing single-package report output continues to point at a concrete retained report; latest remains navigational only. No new required user flag or backward-compatibility report dialect is introduced. Existing configured selections, explicit timeout overrides and duplicate entries are preserved; deduplicating packages or raising default budgets is out of scope.
