# ace-git-worktree: commit_scoped visibility regression crashes every task-aware worktree create

## Behavioral Specification

### Defect

`ace-git-worktree/lib/ace/git/worktree/molecules/task_committer.rb`:
`commit_scoped` is defined at line 262, below the `private` marker at line
195, making it a private method. The orchestrator calls it externally at
`ace-git-worktree/lib/ace/git/worktree/organisms/task_worktree_orchestrator.rb:730`
(inside `commit_task_changes`):

```ruby
@task_committer.commit_scoped(paths, message)
```

At runtime every task-aware creation dies with:

```
Failed to create worktree: Unexpected error: private method 'commit_scoped'
called for an instance of Ace::Git::Worktree::Molecules::TaskCommitter
```

The crash happens AFTER the task-file bookkeeping write (status →
in-progress + worktree metadata block) and BEFORE `git worktree add`, so
each attempt leaves a dirty main checkout and no worktree. The suite stayed
green because no test exercises this external call path.

Introduced by commit `b13d87dfa` ("fix(git-worktree): restrict bookkeeping
commits to owned paths"), found via `git log -S "commit_scoped"`.

Production reproduction (coordinator, 2026-10-10, main@cc146c0e9):
`bin/ace-git-worktree create --task 8wj.t.vle` — evidence in `repro/`
(task-file diff the crashed run left behind; main checkout restored to
cc146c0e9 afterwards).

### Expected Behavior

1. `commit_scoped` is part of TaskCommitter's public collaborator interface:
   `commit_task_changes` in the orchestrator invokes it across the molecule
   boundary and succeeds.
2. Task-aware creation completes end-to-end: task metadata updated, worktree
   created at the configured path/branch, bookkeeping commit made.
3. No other visibility or behavior change: methods below the `private`
   marker stay private; `commit_scoped` signature `(files, message)` and
   return hash unchanged.

### Fix

Relocate `commit_scoped` (with its docstring) above the `private` keyword in
`task_committer.rb`. One-placement change; no logic edits.
