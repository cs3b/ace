# Preserve active Git operation state during scoped commits

## Objective

Prevent scoped commits from silently abandoning an active merge or other sequenced Git operation. During xz9.0 integration, the author reported loss of merge metadata and auto-staged paths after scoped commit staging. Source inspection confirms `stage_paths` executes an unrestricted `git reset --quiet`; the orchestrator validates only that the directory is a Git repository before staging. That initial observation is now covered by executed disposable Git regressions; see test-plan.md and independent-source-review.md.

## Behavioral contract

`ace-git-commit` refuses an active merge, rebase, cherry-pick, revert, or sequencer operation before changing the index, working files, operation metadata, refs, or invoking message generation. This applies to explicit paths, all-files, staged-only, and split modes, including dry-run, quiet and debug variants. Quiet must still show the refusal. No-operation empty/no-change calls retain their existing success behavior. Exit is nonzero with the detected operation and guidance to finish through the native Git continuation command. No automatic abort, reset, repair, or inferred continuation is allowed.

For repositories without an active operation, existing scoped and staged-only commit behavior remains available. Worktrees must be inspected through their actual Git metadata, including shared versus per-worktree state. An inability to inspect operation state refuses mutation with an actionable diagnostic. Resolve marker locations with Git itself (`rev-parse --git-path`), never assume `.git` is a directory. Inspect `rebase-merge`, `rebase-apply`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, and `sequencer`, with that precedence for overlapping markers. `rebase-apply/applying` identifies a git-am operation and advises `git am --continue`; other rebase markers advise `git rebase --continue`. Merge advises `git commit`; cherry-pick and revert advise their corresponding `--continue`. A sequencer without a specific operation marker advises inspecting `git status` and following native Git guidance rather than guessing the operation. Inspecting absent markers is normal; failed Git path resolution or filesystem inspection is an error. Shared repository-state detector consumers are outside scope.

## Success criteria

- [x] SC1: A resolved but uncommitted two-parent merge is refused unchanged; native merge completion still produces both expected parents and all resolved files.
- [x] SC2: Unresolved merge and active rebase/cherry-pick/revert/sequencer states are refused without losing staged entries, conflict stages, operation markers, refs, or working content.
- [x] SC3: Explicit path, all-files, staged-only and split invocations obey the same pre-mutation boundary, including linked worktrees and inspection errors.
- [x] SC4: Ordinary scoped commits still commit only the requested paths, with existing behavior verified outside an active operation.

## Slice and verification

Single medium slice: safe user-visible refusal before any commit preparation mutation. Use maintained real disposable Git repository scenarios through `ace-test`, with before/after index, operation metadata, tree/ref evidence and actual successful native continuation. Include a two-parent merge and sequenced cherry-pick/rebase in linked worktrees; component checks can cover detection errors. Run `bin/ace-test ace-git-commit all` and targeted new regression files through `bin/ace-test`. Deterministic feature tests invoke the CLI with explicit messages (no network): snapshot index bytes/conflict entries, marker contents, HEAD/refs and working files; assert nonzero diagnostic and identical state, then native continuation succeeds. Fast tests own path-resolution/filesystem failure and orchestration ordering before staging, split execution and message generation. SC1 maps to resolved merge continuation; SC2 to unresolved merge and real rebase/cherry-pick/revert plus sequencer marker cases; SC3 to the invocation matrix, linked worktrees and injected inspection errors; SC4 to ordinary scoped/staged-only controls. Independent review must verify the guard precedes every staging and split-reset path. Do not run destructive reproduction commands in a user checkout.

## Scope and readiness

Owns ace-git-commit operation-state safety and public diagnostics. Does not implement native operation continuation or change the Lab execution contracts. Existing native Git completion is the current integration procedure; this task is not a prerequisite for the Lab release. Implementation, executed package verification and independent source review are complete; see independent-source-review.md, including the corrected whitespace-path finding.
