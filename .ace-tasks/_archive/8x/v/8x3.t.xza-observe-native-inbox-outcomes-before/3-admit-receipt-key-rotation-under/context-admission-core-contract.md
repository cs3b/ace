# Context admission core checkpoint

This source checkpoint implements the independently approved plan for the Herdr control store, owner, key reader and authenticated bounded exchange. Frozen source review remains required. xza.3 remains in progress. Assign migration, protected direct-entry enforcement, all-context-before-slot maintenance integration, actual signer provisioning and positive orphan reclamation are not delivered by this checkpoint. Native-observation siblings remain draft.

Control metadata is operational admission state, not a second delivery ledger: version/context, current public key/config identity, at most256 active operations, one active rotation and one last rotation for exact lost-ACK replay. Metadata ceiling1MiB; installed public/config artifacts and wire frames each16KiB. One request per connection requires explicit upload write-half-close; extra bytes refuse before any mutation. Thirty-second framing deadline reports blocked and never clears a grant. Public errors have fixed code context_blocked and contain no caller key/signature/private bytes or raw filesystem diagnostics.

The fixed installed key config is closed `{schema: ace.herdr.inbox-key/v1, context_id, key_generation, public_key_sha256}`. Paths are constructor-selected trusted installer artifacts, never request arguments. Both key and config are held/read/rechecked using ProtectedArtifactSet; fingerprint is SHA256 of RSA public DER. A restart reads existing private metadata and never initializes a missing/corrupt file as empty. Explicit provision is separate. A lifetime flock excludes another context owner.

Operation begin durably writes before ACK. An exact original kernel peer/context/event/purpose/current-generation retry returns the same operation ID; a changed purpose conflicts. Each active operation binds Linux boot/start birth, UID/GID/groups and event. A pending effect projects unknown on retry and cannot execute/end. Original peer end is explicit; EOF/deadline/dead or replaced PID never removes it. The source effect gate durably marks in_flight before releasing metadata ownership; neither a callback boolean nor an exception authenticates completion. Clearing a pending effect will require the integrating source owner's genuine canonical result verification. There is no fake completion/recovery verifier in this checkpoint; unknown remains blocked, including after owner restart. No metadata mutex remains held during effect/ACK wait.

Rotation begin obtains exclusive logical context admission only when every operation ended, installed current key/config still matches metadata and exhaustive existing Inbox live/archive inventory is completed and attributable. All other states, malformed/inaccessible records and conflicting copies refuse. Old DeliveryRecord bytes/fingerprints are never rewritten.

Signer-authenticated interface precision approved by root: signer obtains `rotation_challenge(rotation_id,new_public_key_bytes,installed_config_digest,disposition)` through the fixed endpoint as the actual configured signer account. Its closed body binds schema/context/rotation/expected generation/proposed generation/fingerprint/public-file hash/config digest and random owner challenge. Signer signs these exact JSON bytes and calls `attest_rotation` with expected generation and signature. Disposition replacement binds the next generation; rollback binds the exact retained old key/config and old generation. Maintenance cannot impersonate signer by relaying a claimed UID or a signature. The owner durably retains an opaque authenticated attestation ID; commit consumes `{attestation_id}` as signer_keypair_attestation, not arbitrary receipt flags. Replacement-to-rollback attestation is allowed after partial installation; conflicting same-disposition claims refuse.

Signing bytes are compact UTF-8 JSON from the shared owner serializer, with exact returned field order: schema, context_id, rotation_id, expected_key_generation, new_key_generation, disposition, challenge, fingerprint, public_key_sha256, installed_config_digest. No whitespace/newline or arbitrary caller payload is signed. The verifier reconstructs this same closed ordered body; signature input is canonical base64.

Rollback precision: `abort_rotation(rotation_id,signer_keypair_attestation)` consumes actual signer rollback challenge proof plus protected exact old public/config readback. Restoring only public bytes while the private pair remains replaced cannot authorize abort. Failed/partial installation or rollback leaves the exclusive rotation durable and blocked. Exact same original maintenance process can replay the committed/aborted result, never install again merely because ACK was lost.

The generic transport currently exposes control operations only. It does not activate a live installed server/CLI or silently route existing local Inbox commands through partial admission. Protected snapshot/bind/reconcile byte routing, source completion authentication, context owner schema and canonical all-root migration are the next coordinated implementation step. Historical verification must preserve original keys and no current-key fallback. Positive orphan reclaim can use9c2 preterminal no-writers only for an original signer positively bound to that scope plus drained accepted downstream mutations; final stopped is not a prerequisite or proof substitute.
