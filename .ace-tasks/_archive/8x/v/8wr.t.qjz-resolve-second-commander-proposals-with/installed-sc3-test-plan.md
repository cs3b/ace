The maintained scenario belongs in `ace-hitl/test/edge/installed_proposal_test.rb` with copied consumer fixtures in `ace-hitl/test/support/installed_proposal/`. Runtime package code gains no test overrides. Only the external Telegram transport and injected UTC dependency are controlled. Fixture configuration uses existing trusted in-process configuration APIs and actual current OS UID; it is explicitly not an installed root-owned policy or multiUID proof. The public authenticated Client API is the workflow driver; normal production CLI configuration is covered by existing source tests and is not asserted as deployed here.

No binding, coordinator, executor, authorization, claim, receipt verifier or journal is replaced. The local executor is a real subprocess with fixed argv and an actual private attestation. An isolated tmux fixture provides the native ancestry prerequisite; this does not establish protected Herdr launch acceptance.

The opt-in run retains artifacts outside the checkout in `/tmp/ace-installed-sc3/run-*` and writes a manifest/result pointer under checkout `.ace-local/installed-sc3/`; default package runs skip this expensive build/install scenario. No network fallback, timeout increase, manual queue insertion, live Telegram or privileged deployment claim. Root coordinates the heavy slot before execution. Independent review and actual executed receipt gate integration; task completion remains separately owned.
