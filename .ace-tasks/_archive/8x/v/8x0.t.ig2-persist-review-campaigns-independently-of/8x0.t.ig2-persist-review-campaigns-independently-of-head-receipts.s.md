# Persist review campaigns independently of head receipts

## Behavioral Specification

### User Experience

An operator resumes a review after a new commit, restart or context compaction and sees the same campaign history, with current evidence validity shown separately.

### Expected Behavior

- Persist subject/repository identity, immutable task-contract identity, effective policy, required scopes, rounds, findings/dispositions and observed head transitions. A contract change starts a linked successor campaign; it never silently rewrites prior history.
- Commits, squash and rebase preserve round history and the consecutive no-High/Critical count. They invalidate evidence for changed code; unchanged campaign counters never certify the new head. A round finding a confirmed High/Critical is non-clean even if fixed immediately.
- A round counts only after every required scope has a completed substantive report and verified findings. Provider calls, report files, execution retries and completed rounds have separate counters. Failed/incomplete attempts and zero-model/no-op sessions do not count as clean rounds.
- Earlier unresolved findings remain open when absent from later reports. Current acceptance requires the applicable policy, required fixes/tests and independent current-head evidence, not just search convergence.
- Expose one durable campaign authority through ace-review. ace-assign continues to own attempts and accepted execution receipts; consume a campaign result through its existing receipt boundary, without a second execution journal or self-approved worker result.
- Restart from artifacts must reconstruct state without conversation history. Recording the same round identity and content twice is idempotent; conflicting content for the same identity is rejected without changing accepted history.

## Interface Contract

Proposed public CLI: `ace-review campaign start --subject FILE --contract FILE --profile delivery`, `ace-review campaign status ID --format json`, `ace-review campaign record-round ID --input FILE`, and `ace-review campaign finish ID --format json`.

The subject uses the existing provider-neutral repository/PR identity, or an explicit local discovery identity; no GitHub-only identity scheme. JSON distinguishes campaign ID, contract identity, effective policy, completed rounds, clean streak, open findings, `search_converged`, and evidence validity with source/current heads. `finish` cannot turn stale/incomplete/blocked evidence into accepted output. Malformed input and conflicting replay fail nonzero; read-only status reports known state even when blocked.

All interfaces described here are proposed acceptance contracts, not a claim of currently installed functionality. Draft usage scenarios are in `ux/usage.md` in this task directory.

## Readiness decisions: campaign boundaries and evidence

- **R1/R3 ownership:** R1 supplies durable records, derived counters, input validation and current-evidence checks. It snapshots an explicit policy and supports the existing three-round/two-clean delivery rule. R3 adds the two-round discovery profile, five-round delivery cap, retries and escalation transitions. R1 does not depend on R3 or duplicate its policy engine.
- **Identity:** bind a campaign to one canonical repository and PR identity, or one explicit local candidate identity, plus the content digest of a frozen requirements document. Implementation changes, task status/archive metadata and editorial completion evidence are not requirement changes; the contract input excludes them. A changed requirements document creates a linked successor and cannot silently replace the old digest. Compare reuse against the active campaign: returning A → B → A creates a new successor of B, even though A’s digest appeared in superseded history. Record the reason and retain predecessor findings for disposition against the new contract.
- **No hidden provider prerequisite:** R1 records normalized identities from already available local/GitHub session sources; it does not fetch through a new Forgejo adapter or implement qk1. A requested unavailable source is unsupported, never silently redirected. qk1 remains owner of new forge adapters; R2 consumes qkb after delivery.
- **Round scope:** a round pins required scope IDs, code head and base/scope identity before collection. Multiple module reports count as one round only after coverage and dispositions are complete. Mixed-head reports cannot be combined into a current-head round. A completed historical round remains history after later code/base drift but is not current acceptance evidence.
- **Claim authority:** record-round validates real session/report references, checksums, completion and verified finding dispositions; caller-supplied counts or search_converged booleans are not authoritative. A local campaign result is not a trusted assignment approval; qjl's coordinator independently validates producer/reviewer identity, executed checks and live-head binding.
- **Concurrency/recovery:** one campaign identity serializes state mutations. Concurrent identical start requests for the same subject/contract/policy reuse one campaign; conflicting policy or round writes fail without lost history. A crash exposes either the last complete record or a recoverable incomplete attempt, never a partly counted round. Missing/corrupt artifacts make evidence unavailable, not clean.
- **Policy/history:** freeze the policy revision used by each round. Do not reset history on profile/policy change or silently recompute prior policy as though it had always applied. The active outcome is derived against the applicable policy and all retained findings.
- **Findings:** use existing feedback items/dispositions as source records. Campaign-level corrections are append-only assessments referring to source IDs. Reopening links a new evidenced occurrence to a canonical finding; do not force terminal feedback files through an illegal done-to-pending transition. Preserve immutable finding snapshots when recording; verified terminal updates of an earlier source finding may be assessed alongside current reports without treating that older report as current scope coverage.
- **Evidence binding:** final acceptance requires actual independent approval for the live head and reviewed scope plus passing required checks. A model response, exit zero, an empty report or the existence of a file alone is insufficient. Preserve existing receipt artifact-path and authority validation.

### CLI input and operating modes

Campaign start accepts JSON subject metadata with repository identity and either PR identity or explicit local candidate ID; reject empty/mixed identities and an empty contract. Round JSON identifies a round, required scopes, reviewed head/base, completed session references and dispositions; reject missing scopes, incompatible identity and self-referential predecessor IDs. Full syntax belongs in shipped help and usage with executable fixture examples. Scope identities pin the preset and explicit subject selectors before collection; PR delta scopes also pin the exact delta reference head, so narrowed coverage cannot stand in for a full scope. Required-check evidence references a coordinator-accepted assignment receipt by attempt ID and digest, exposed through the read-only `ace-assign attempt evidence` boundary; a caller-authored passed-check JSON file is not authoritative. Completed sessions require a successful feedback-extraction inventory, including explicit zero findings, bound to the reports; skipped/failed extraction does not count. Local head/base identities must name available Git commits; the latest local base pin defines current scope identity and invalidates earlier-base evidence without resetting history. Completed session references include coordinator-accepted review-collect receipt IDs/digests covering metadata, prompts and reports. Final approval additionally references a coordinator-accepted ordinary review receipt with an approved independent reviewer verdict bound to the live head, producer/reviewer and every approved report. Collection alone and caller-authored approval JSON cannot supply that verdict. Historical review approvals retain accepted receipt authority without certifying current checks. Findings from an incomplete/unaccepted session cannot change authoritative assessments; completed module sessions remain valid evidence during partial overall coverage. Required checks bind accepted receipt operations to their names (tests uses test); editable session fields or unrelated operation verdicts alone cannot establish execution. The existing trusted coordinator/service attests execution after verifying the outcome; R1 consumes that accepted authority and does not add an execution runner or a new process-attestation system. Retained completed sessions, including earlier and partial coverage, must retain accepted immutable receipt authority. The read-only review-collection query accepts an explicit historical head only for historical validation; it never makes historical proof current check authority. Local full scope requires the exact pinned diff selector; file subsets use explicit module scope IDs. A confirmed High/Critical in a later partial round invalidates an earlier approval even if immediately resolved, until completed current review and required convergence are restored. PR full scopes require complete verified unfiltered whole-PR diff manifests and cannot use delta references; explicit delta/module scopes retain pinned delta collection. Later changes to a canonical claim previously confirmed High/Critical require completed current coverage before acceptance, including invalidation, severity reduction and empty/partial submissions. Untracked ACE-private artifacts do not invalidate committed candidates; tracked modifications and untracked candidate source do. Superseded contracts preserve history but cannot be accepted or collected again; one submission may not assess a canonical finding more than once.

Existing `ace-review --pr ...`, local subjects, repeatable `--model`/`--subject`/`--evidence-session`, feedback commands and help remain supported primary operations. Add campaign dispatch without routing its operands through the existing single-command array preprocessing. This is an additive capability, not a renamed legacy alias.

Read-only status may report blocked/stale state successfully but errors on an unknown/corrupt campaign. Start/record-round return nonzero on invalid input; finish returns nonzero when acceptance requirements are unmet and emits a reason in JSON. Quiet/verbose affect presentation only; JSON stdout stays parseable. Mutation commands support dry-run validation without model calls, Git commits, state writes or external effects. No force flag bypasses evidence. Campaign commands never merge, publish or deploy.

## Success Criteria

- [x] SC1: Record two qualifying reviews across H1/H2: retain both rounds and the clean streak, while the H1 receipt is visibly stale for H2; an unresolved earlier High still blocks acceptance.
- [x] SC2: Restart after partial scope completion and after round persistence; recover the same state and reject a missing report, fabricated success or duplicate-count attempt.
- [x] SC3: Exercise no-op, provider failure and incomplete multi-module coverage; none increments clean or completed-round counts.
- [x] SC4: Change the contract and obtain a linked new campaign; commits under the same contract do not create a new campaign.
- [x] SC5: Consume the campaign through an existing assignment attempt; evidence publication does not advance the candidate branch and stale/current-head checks still hold.

- [x] SC6: Exercise the readiness decisions and public operating modes above through actual CLI/workflow entrypoints: dry-run is non-mutating, JSON is parseable, identity/authority failures cannot become acceptance, and replay or restart preserves the same result.
