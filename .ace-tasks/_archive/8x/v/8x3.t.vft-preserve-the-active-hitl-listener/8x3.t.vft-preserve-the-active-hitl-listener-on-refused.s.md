# Preserve the active HITL listener on refused startup

## Outcome and ownership

An operator can accidentally start a second `ace-hitl serve` without disconnecting the authenticated service already serving requests. Owner: ace-hitl. Consumers: deployment supervision in lab-config:gad.8/.b, Hermes y24 and daemon-free integration vs2. This is one small, independently verifiable service-lifecycle repair; it preserves the delivered 34i history.

## Verified gap

Code-path review at ACE `686abe359` found that Service#run always calls shutdown! even when prepare! rejects a live listener; shutdown! unconditionally removes the endpoint path. The current second-listener test invokes private prepare!, bypassing that cleanup. This is code-path evidence, not a newly executed reproduction. The first implementation check must reproduce the failure through public run or the installed CLI before applying the fix.

## Behavior and public contract

- Existing `ace-hitl serve --socket PATH --store-root PATH --grants-path PATH` and Service#run remain the public surface. A second process at a live endpoint returns the existing classified non-success; the original listener, endpoint identity and request state remain usable.
- Failed startup never removes, replaces or closes another service's endpoint. Cleanup removes only the endpoint established by that service invocation and only while that path still refers to its own listener. If another endpoint replaced it, cleanup leaves the replacement intact.
- Normal stop releases this invocation's listener and endpoint so a subsequent valid start can serve. A genuinely stale, non-listening socket may be recovered under the existing ownership/protection checks. Failure to prove stale ownership or endpoint safety remains an error, not permission to delete an arbitrary file.
- Concurrent start attempts cannot both claim successful ownership. The loser cannot unlink the winner; clients retain an authenticated usable endpoint. No new force option, bypass or compatibility path.
- Preserve active request data and OTP secrecy. The repair does not add orchestration, transport policy or daemon-free delivery behavior.

## Success criteria and verification

- [x] SC1: With a real temporary UNIX endpoint and the public service lifecycle, start A, invoke B at the same endpoint, observe B's classified refusal, then complete authenticated ping and create/read/consume through A. Prove the socket identity is unchanged.
- [x] SC2: Exercise failed setup before bind, failure after this invocation acquires a socket, normal stop, stale-socket recovery, and endpoint replacement before cleanup. Other endpoints/files survive; owned stale resources are released safely.
- [x] SC3: Race two starts with deterministic synchronization; exactly one listener succeeds and remains reachable after loser cleanup. A test that calls only prepare! does not satisfy this gate.
- [x] SC4: Run `bin/ace-test ace-hitl all` and the impacted lifecycle integration tests; record source SHA, commands/results and an independent reviewer verdict. Separate ordinary same-UID tests from real multi-UID installed acceptance owned by the Lab gate.
