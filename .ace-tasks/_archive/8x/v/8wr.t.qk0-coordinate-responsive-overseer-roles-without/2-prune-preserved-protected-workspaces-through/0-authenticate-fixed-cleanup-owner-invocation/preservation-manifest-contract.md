# Complete preservation manifest contract

Accepted source contract, 2026-10-08. Supersedes the file-only packet and `{inventory,destinations}` digest in the earlier physical and prune proposals. Independent reviewer approved matching Lab candidate `caf81c5fd57610d0f923eb266b67feaa0847637e559d057b2b8273db2b73ce2c`; source implementation and physical acceptance remain separate.


Replace the earlier canonical four-field file-only manifest with the closed private envelope `{schema,target,preservation,workspace,index,staged_blobs}`; schema is `lab.workspace-cleanup-preservation/v1`. `target` is the unchanged canonical target without artifact_digest; `preservation` is exactly `{head,branch,destinations}` without manifest_sha256. Neither envelope nor children contain their own digest/reference. Canonical UTF-8 JSON uses recursively sorted object keys, compact separators, and arrays in their prescribed order. `manifest_sha256` hashes these exact bytes; artifact_digest uses the existing canonical target-plus-preservation formula with that manifest digest. Preview and apply independently construct the identical packet from the held original owner. Public inventory_sha256 equals this full private manifest SHA256, and preservation.manifest_sha256 equals the same digest; neither describes only the workspace subarray. Capture persists those exact bytes, never a newly measured substitute.

`workspace` is the complete sorted typed array `{relative_path,kind,mode,bytes,sha256}`. It includes root `.` and every directory, including empty directories. `kind` is exactly `directory` or `file`; mode is the observed permission/special-bit integer. Directory bytes is zero and sha256 is SHA256 of empty bytes. File bytes/hash describe exact held raw bytes; no filters or line conversion. Root linked `.git` is authenticated separately and excluded from preserved workspace bytes; nested `.git`, symlink, hardlink and special-file layouts refuse. Directory-only additions/removals/mode changes therefore alter the manifest and invalidate apply. Restoration recreates directories and their modes, then exact files/modes; it never interprets `.git` pointer bytes as a destination.

`index` is exactly `{bytes,sha256,entries}` for the held raw linked-admin index snapshot. Each entry is `{relative_path,mode,oid}` sorted by UTF-8 path bytes, stage zero only, strict SHA1 object ID and ordinary regular-file Git modes 100644/100755. Raw index bytes are retained as a separate private capture member, not embedded JSON. Duplicate paths, malformed header/checksum/framing, unmerged stages, intent-to-add/zero objects, sparse/split index, submodule/symlink entries, unknown extensions or redirected object stores refuse before effects. The raw index alone is insufficient preservation.

`staged_blobs` is the sorted unique array `{oid,bytes,sha256}` covering EVERY distinct index object, including objects differing from HEAD and current worktree bytes. Fixed no-filter Git cat-file commands independently require object type blob, bounded exact length/framing and matching Git SHA1 object identity. Apply captures each blob's exact content as an independent private member before removal, so later common-repository GC cannot destroy staged content. Path/mode-to-blob mapping remains in index.entries; restoration can reconstruct the index from these retained contents without assuming objects survive elsewhere. No refs, filters, object-store writes or extra outcome ledger are introduced during preview.

The metadata record cap is separate: workspace rows (including directories/root), index entries and unique blob records together number at most4096. Public file_count counts only regular workspace files, plus one raw index member, plus unique staged blob content members; public total_bytes sums precisely those content members. This shared content total is at most256MiB, each content member at most64MiB. Metadata packet remains at most64KiB. Every workspace/index path must be valid UTF-8, at most1024bytes, with safe nonempty components and no NUL, absolute prefix, dot/dotdot or .git components (the root row alone uses literal `.`); binary filenames refuse before effects rather than encoding or dropping them. Both preview and capture enforce incremental accounting, no unbounded batch output or aggregate in-memory buffering. Capture reads one bounded member at a time into its fixed private evidence namespace. Any member/policy/ref/resource drift refuses or records truthful partial capture, never removes the original on incomplete preservation.


Receipt fields `manifest_sha256`, `inventory_sha256` and `private_manifest_sha256` name these same exact packet bytes and must agree. `archives_sha256` remains the separate digest of the privately retained capture members. No raw paths or private members enter canonical receipt transfers.
