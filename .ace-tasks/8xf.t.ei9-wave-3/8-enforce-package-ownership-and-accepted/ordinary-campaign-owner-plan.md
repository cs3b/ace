## Reused execution boundaries

- Reviewer work is a genuine registered and started ordinary attempt, selected
  from its canonical native process/session binding before review execution.
- Existing `submit_result` imports `review-collect` artifacts and attributes them
  to that actual reviewer. Existing supervisor `finish` establishes its terminal
  succeeded receipt. A submitted result alone is insufficient to count a round.
- Existing `accept_review` independently imports a reviewer approval for the
  running producer. Collection completion does not imply approval. Blocking
  reports can be counted without an approval.
- CampaignEvidence callbacks join those retained records at the held canonical
  prefix, require exact head/candidate/reference/report bytes and original native
  independence, and check current cancellation. No worker-owned report path is
  an alternate source and no second collection ledger is added.
- The producer remains running throughout campaign, checks, merge and service
  settlement. A finished reviewer does not finish the producer.

## Durable control and retries

The root-selected ordinary owner composes CampaignManager/Store at private paths
with the existing CampaignConsumerPolicy. Source callbacks remain closed over the
same journal, canonical producer and held lifecycle scope. The existing journal
records campaign association and selection; CampaignStore owns campaign rounds,
findings, phase bounds and provider reservations.

A supervisor starts an exact contract/profile association, pins an empty round,
and selects an independently started reviewer against that pinned round. Selection
reserves the existing provider budget before review begins. Its reservation needs
a stable source-selected ID so a lost response or failed journal publication can
recover the original reservation without another provider dispatch. Reusing an ID
with different round/scope/provider must fail. Running/uncertain reservations never
permit an implicit retry. Canonical collection settlement supplies completion.

Full round ingestion consumes CampaignRoundTransfer's closed, bounded envelope.
Materialized paths are private names; every imported session/report/prompt and
approval must be backed by the exact canonical executed result or accepted review.
The uploaded envelope digest and original request ID remain immutable on replay.
Budget escalation and finding assessment continue through existing CampaignManager
operations under the actual supervisor; they cannot erase counts or old findings.

## Head changes and consumers

A source-issued comparison context binds both retained candidate bundles, their
head/base/tree identities, complete inventories, original/current scopes and full
bounded object bytes. An authenticated supervisor assessment binds that digest,
its bounded rationale, the previous accepted result and exact current root-owned
executed-test references. Nonsemantic carry requires complete supported text
context. Material/uncertain changes require an independent executed delta with
that same complete comparison binding; a label or partial packet cannot approve.

Current merge consumption must select the latest candidate reference. Historical
campaign check reads must revalidate their original immutable candidate and command
execution without pretending that the old head is current. The dynamic materializer
owner owns that distinction in its existing test-evidence reader. This join must
not revive the old static test-selector fallback.

The accepted-reference v2 consumer will distinguish original reviewed head from
accepted merge head and bind the campaign assessment prefix. Campaign association
prevents a direct review receipt from bypassing configured campaign constraints.
Unconfigured campaign capability remains an explicit refusal.
