# Route project HITL and delegated commander decisions

Advisory size: **large**. Existing code owners: 8xa.t.nh0, 8wr.t.qk0, 8wr.t.qkb.
This child owns the observable program outcome; reuse/adopt their delivered work,
implement only remaining behavior there, and do not duplicate or reopen archived owners.
## Outcome and interface

One shared Hermes transport serves separate bidirectional Telegram groups per project,
preserving existing host/project routes. No second bot poller, Python bridge or
ACE-only replacement that silently drops other groups. Discover actual installed
provider, endpoint, trust config and requester/attempt binding. A working help command
or legacy broker presence is not proof the selected Lifecycle::Client route works.

Project-origin ask returns attributable request with channel/project/attempt,
context/options/proposed action and correlation. Exact Reply resumes that owner;
arbitrary group message is a new instruction, not a correlated approval. Confirm
notification separately from Reply, accepted operation and completed effect.
Service requests from project identity reach authorized executor without copying
credentials. Host/container locality and authenticated cross-boundary transport
must be demonstrated; same-UID local socket fixture proves no cross-VM identity.

## Short-lived OTP

Captain permits short-lived OTP as Telegram Reply in the PROJECT channel. Bind it
to fresh publisher challenge, exact release/artifacts, request/attempt and expiry;
never store OTP value in tasks, logs, reports, snapshots or learning corpus. Do not
substitute host-channel request when project-origin flow was requested. Wrong scope,
stale/expired Reply and orphan/unknown request are reconciled/refused without
blind publish or duplicate ask. Actual provider OTP challenge is distinct from
credential401, absent route or ordinary auth failure. Existing private executor
environment supplies long-lived credentials; no token grants to workers.

## SecondCommander decision cycle (in Wave 3)

Reuse existing 8wr.t.qjz proposal policy/Assign/HITL implementation, not a new
learning engine or automatic reopening of that archived owner. Its older all-class
timeout authorization wording does not override this Wave 3 scoped-delegation
contract; reconcile the effective policy explicitly.
For explicitly delegated decision classes, SecondCommander records context, options,
chosen decision and rationale. The 16-hour override window starts ONLY at confirmed
transport delivery of that unchanged proposal to Captain, not request creation
or assumed reading. Failed/uncertain notification never arms or consumes the window.
A material change to proposal/head/input/scope creates a new revision and requires
new confirmed delivery plus a full new window. Timely Captain reply overrides with recorded what/why; absent reply
after the deadline executes the scoped proposed decision ONLY within that prior
delegation. Deadline never grants new credentials, cross-project rights or publication
permission. Explicit refusal/changed scope wins. Restart preserves deadline/decision
identity and executes at most once. Resolve Reply-versus-timeout atomically:
reconcile transport ingress through the deadline and give timely received Reply
precedence; unavailable/backlogged transport defers resolution. One revision has
one decision/effect claim. Uncertain effects still reconcile before retry.

Retain sanitized feedback/decision/outcome examples to improve future choices.
Window shortening is FUTURE explicit policy adjustment based on evidence, not
self-authorized automation. OTP values and secrets are excluded from learning.
Resolution is bounded so an unavailable transport cannot freeze status/conversation.

## Verification and failure acceptance

Real project group notification and correlated Reply reach correct project owner;
other groups continue functioning. Missing endpoint/trust mapping reports exact
blocker. Test wrong group/attempt, expired OTP, orphan request and lost reply without
secret output. Test proposed decision, Captain override, timeout within delegated
class, timeout outside class→deny, failed notification→no deadline, changed proposal
→new acknowledged window, Reply/timeout race→one decision, restart across deadline
and one resulting effect.
Controlled clocks may test16h in source; installed route/correlation needs real proof.
No need to wait16h in a blocking agent turn; native wake schedules reconciliation.
