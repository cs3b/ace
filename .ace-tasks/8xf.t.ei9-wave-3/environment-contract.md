# Wave 3 environment and execution contract

This document is normative ACE context, not a live inventory or credentials file.
The implementer needs this repository only. Actual deployment values come from the
configured environment owner through the public interfaces below; absence is a
precise readiness failure, not a request to reconstruct chat or read another repo.

## Development and installed receiver

Develop/test/review generic ACE code host-side in isolated task worktrees. Keep
canonical checkout clean on main. The existing Lab receives published/configured
artifacts and runs acceptance; do not dispatch development into its agents for
this iteration. Domain operator alone performs privileged installation/repair.
Project overseer requests scoped effects and adopts results; it does not inherit
root, borrow credentials or invoke a broad shell as an operation substitute.

Source ownership remains in the existing qk0/qkb/xz9/iy6/nh0/ig3 families. A generic
provider API lives in its owning package; domain config/OS installation is outside
ACE implementation. Preserve source-only tests versus installed evidence explicitly.

## Cold implementation entry

1. Load project context using `bin/ace-bundle project`, then the chosen child bundle.
2. Use `bin/ace-task show <owner>` and inspect its current source/receipts before
   implementing remaining behavior. No automatic reopening of archived owners.
3. Resolve `bin/ace-bundle wfi://overseer/configure-project` and shared Assign
   presets from actual source/installed resolver. Record effective versions,
   paths/digests and project overrides, not only a file's presence.
4. Discover current public command help/status and supported inputs; bind the
   semantic contracts in usage to those interfaces. Examples are not permission
   to advertise a proposed command as already shipped.
5. Execute source checks via `bin/ace-test` / `bin/ace-test-suite`. Record actual
   outcomes, skips/limitations and independent review against accepted head.

Role defaults: workers Pi zai/glm-5.3-flash high; reviewers Pi zai/glm-5.3 high.
Configured explicit Captain exceptions are allowed and attributable. A model profile
never grants operations. Verify actual harness/model/identity/start, no silent fallback.

## Domain inputs and public results

| Input supplied by deployment/project owner | Consumer obligation / observable result |
|---|---|
| Stable project/agent/service IDs, repository IDs and provider URLs, source/target refs | Resolve uniquely, retain selected identity; unknown/ambiguous denies before effect. Pane changes do not change project identity. |
| Workflow/context/release policy, concurrency and workspace bindings | Report effective paths/digests; task purpose is separate from capabilities; bootstrap/restart loads all before new dispatch. |
| Executor account/transport and authorized operation schema | Caller cannot choose UID/argv. Public submit/status/recovery exposes admitted request, actual start and canonical result. A local same-UID function cannot claim cross-user service. |
| Protected trust/config, scoped decision and canonical journal location | Bind identity, project, operation/input digest, target/head, lease/expiry and request. Requester cannot rewrite trust or copy journal to another checkout. Missing config reports exact missing binding. |
| Shared Hermes routes and authenticated host/container endpoint | Keep one poller, all existing project/host group routes and correlated bidirectional replies. Cross-VM route proves actual reachability/authentication (configured TLS identity where applicable), not local peer UID alone. |
| Publisher/deployer environment and exact release selection | Credentials remain in authorized executor environment; environment-file existence does not prove usable key. Provider challenge/auth failure are distinct. No credential values in docs/logs. |
| Exact release lock/manifest/artifact digests and consumer inventory | Install coherent graph, preserve legacy pins, return actual versions/paths/smokes for each consumer; no mutable latest selection. |

Core operation surface has input schema, authority, status and recovery for merge,
configured project command, publish/deploy, selected-ref code sync and project setup.
Scoped configuration approval is NOT code-review approval. Operation selection or
`route` discovery does not dispatch, authenticate or grant. Missing legacy Work
must be reported as incompatible binding, never fabricated to satisfy a wrapper.
Use the supported ACE executor, not a second Python broker/protocol/queue.

## Installation and privilege boundaries

Domain owner installs exact reviewed published gems/dependency closure and runtime
configuration in independently controlled locations. Validate all consumers:
interactive-user tools, isolated service runtime, coordinator/project bundles and
persistent installer manifest/locks. Read each actual Bundler path, interpreter and
CLI default; merely requiring selected gems can hide a different default executable.
Preserve older runtime dependency pins in their separate runtime when required.

Installer must preflight complete affected consumer/writer set, quiesce through
supported ownership, preserve previous coherent set and give interruption recovery
or rollback with evidence. Missing trust, incompatible manifest, active/uncertain
writer or unsafe replacement refuses before effect. Reinstall proves idempotence;
partial deployment never returns success. Exact original/candidate provenance and
canonical evidence survive recovery. Do not replace an executing updater's own trust
or receipt boundary. Source installer tests cannot substitute installed acceptance.

NoNewPrivileges may forbid sudo inside a terminal even when discovery names an
admin role. Do not weaken that protection or copy tokens to work around it. A
configured scoped executor must actually spawn under its selected identity. Normal designated root-owned provisioning/install through the authorized scoped
route is intended behavior. Manual per-item executor rescue or host-chat scheduling
bypass is recorded as failed autonomy; diagnostic work alone is not acceptance.
Transport must not be added to a broad group merely to obtain a new socket if that
group also exposes unrelated legacy control sockets.

## Ordinary slice versus protected obligations

First working slice is ordinary authorized integration plus two sequential merges.
Do not make full protected native replacement, network/boot/devpts proof or all
historical installation tasks prerequisites. Those existing owner contracts retain
their independent maintenance/identity/writer-preservation requirements. No protected
denial can be bypassed by relabeling ordinary success or borrowing a protected lease.
Mandatory native read/consumed/superseded receipts and signing infrastructure were
removed from this ordinary acceptance scope. Prove actual start/result adoption;
unknown consumption stays unknown rather than manufacturing a signed claim.

## Evidence and handoff

An accepted result includes exact source/artifact/config versions, target identity,
request/attempt, executed command/interface, exit/result and provider readback.
Sanitized durable source/installed acceptance summaries are versioned in ACE;
operational domain ledgers may keep the same receipt reference, not a competing
execution store. Never include passwords, API tokens, OTP values or private keys.
Question/decision/escalation goes through project's configured HITL route; exact
Reply correlation and actual actor determine adoption. Captain commands override
briefs. Failure names actual owner, missing capability and next action, not a global hold.
