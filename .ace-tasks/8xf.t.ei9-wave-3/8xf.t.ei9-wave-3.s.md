installation/acceptance receiver, not the development scheduler. Captain overrides

## Common invariants

- Project overseer owns full project delivery and service requests; Lab coordinator
  only routes, pauses/resumes and caps projects. Avoid duplicated PR status boards.
- Purpose/workflow input/output/completion and scoped capability/executor identity/
  readiness are independent dimensions. Role/model name never grants authority.
- Worker implementation lists may finish PR-ready. Separate delivery list references
  producers; local .ace-tasks/overseer queue references canonical Assign. No second
  execution store, reparenting, completion:explicit or fake blocking child.
- Initial review is independent. Integrator accepted-head delta assessment permits
  proven identical-rebase carry-forward/minor-safe-correction tests; material or
  uncertain change gets independent delta review. Exact server-side head guard
  always applies. Formal reviewer approval and published evidence are distinct.
- Short observe/reconcile/choose/dispatch-or-adopt/record/idle cycles keep user
  steering responsive. No accepted request means not dispatched, not waiting on
  an imaginary executor. Native wake/watch, no external heartbeat or sleep-polling.
- Preserve work and canonical main. Every active executor including release has
  its own pane and appropriate worktree; accepted cleanup uses exact stable IDs.
- Real effect proof cannot be replaced by fixtures, source versions, terminal text,
  manual host rescue or paper-closing a task. Unknown effect reconciles before retry.
