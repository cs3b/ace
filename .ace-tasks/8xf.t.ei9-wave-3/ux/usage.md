# Wave 3 — proposed operating contract

These are semantic workflow scenarios, not invented executable CLI commands.
Use the effective installed ACE public interfaces after readiness validation.

## Cold start / resume

Input: project profile and objective. Reuse as-overseer-configure-project and
shared Assign presets; load role/context/queue/actual attempts, scoped services,
limits and release target. Output: selected next action or precise missing
capability; restart adopts the existing request, never a duplicate worker.
Labels remain human-readable; controls use exact runtime IDs.

## Two sequential integrations

Input: reviewed candidate with configured repo/ref, expected head/base and scope.
Output: accepted request/attempt → actual executor start → forge effect/readback
or uncertain/denied. After first merge, prepare second against new main and admit
its newly created scoped decision on the still-running receiver. Integrator uses
risk-based carry-forward/minor-delta assessment, independent review for material
or uncertain deltas, and always exact accepted-head guard. Lost reply reconciles;
no host chat scheduler and no replay on nil/404.

## Project delivery and reuse

Input: selected release cut and concrete authorization. Existing release scripts
run in dedicated worktrees; OTP validates actual route; sync reads exact provider
refs. Output: separate publication, sync, installation and cleanup receipts.
Cold-onboard another project with the same skills/templates and config only;
its different release may be an explicitly authorized demo. No blanket rights,
secret output, new external heartbeat or duplicate execution ledger.
