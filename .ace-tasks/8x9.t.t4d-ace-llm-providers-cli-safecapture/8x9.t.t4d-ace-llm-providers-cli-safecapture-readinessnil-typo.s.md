# ace-llm-providers-cli: SafeCapture readiness.nil typo breaks every successful supervised CLI capture

## Behavioral Specification

### Defect

`ace-llm-providers-cli/lib/ace/llm/providers/cli/molecules/safe_capture.rb:100`:

```ruby
return nil if supervised != true || readiness.nil.
```

The trailing dot (missing `?`) makes Ruby continue the expression onto the
next line (`message = readiness.to_s`), so at runtime `readiness.nil` raises
`NoMethodError: undefined method 'nil' for an instance of String` whenever
`readiness` is a String — i.e. on every successful supervised spawn. The
check runs unconditionally in `run_capture` for every CLI-delegating
provider (codex, agy, claude, pi, ...), so the whole `role:assign-executor`
CLI chain fails deterministically before any model call.

Introduced by commit `799f339d7` ("preserve accurate CLI failure evidence",
2026-09-29), found via `git log -S "readiness.nil."`.

### Expected Behavior

1. **Successful supervised capture:** when `supervised == true` and the
   supervisor wrote a readiness message (String), `run_capture` proceeds,
   reads the message, and returns captured output — no exception.
2. **Correct failure handling:** when `supervised != true`, capture returns
   `nil` (falls through to the failure-evidence path); when `readiness` is
   `nil`/missing, the same guarded skip applies without raising.
3. Failure evidence semantics from `799f339d7` (accurate CLI failure
   capture) remain intact — this is a one-character syntax repair, not a
   behavior redesign.

### Verification plan

- Executed regression in `ace-llm-providers-cli` test suite covering
  SafeCapture/run_capture: (a) successful supervised spawn with String
  readiness returns captured output without NoMethodError; (b) failure
