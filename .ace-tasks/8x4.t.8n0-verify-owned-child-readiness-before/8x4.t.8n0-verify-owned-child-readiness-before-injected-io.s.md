# Verify owned child readiness before injected IO failure

## Objective

Make the ordinary Herdr post-launch IO-error cleanup test report the fate of its exact owned child, rather than race on an incomplete PID publication. This is one small standalone test-only slice; no public interface changes or new dependencies.

## Expected behavior

Before injecting the IO failure, the fixture identifies a strictly positive PID attributable to the process launched by that BoundedProcess call and verifies that child is still alive. Missing, empty, malformed, zero, or unrelated identity must not count as readiness or be used as a kill target. Readiness uses bounded synchronization and positive evidence; retrying the flaky test, longer sleeps, tolerance of a live child, and product timeout increases are not fixes.

The injected IO error still yields PostLaunchError. The exact child must be reaped/absent after BoundedProcess cleanup. An implementation which leaves it alive must fail the regression. All fixture-created processes are cleaned on assertion/error paths using only retained owned identities; never PID0 or an unrelated PID. Ordinary deadline and missing-executable behavior remain unchanged.

## Interface contract

Existing BoundedProcess.call behavior, errors, deadlines and package APIs are unchanged. Existing bin/ace-test package/file entrypoints report real success or failure. No usage document is required for this internal fixture correction. Production primitive, SafeCapture/lq8, protected launch, privileges and unrelated cleanup work are outside scope.

## Success criteria

- [ ] SC1: Retain the reported combined suite failure8x48iu and deterministic evidence that file existence can precede PID bytes; distinguish confirmed publication mechanism from unobserved historical scheduling.
- [ ] SC2: IO-error test uses exact positive live-owned identity before injection, refuses incomplete/invalid readiness, and cannot silently probe PID0.
- [ ] SC3: Actual child cleanup remains verified: PostLaunchError, absent/reaped owned child, and maintained negative proof that a surviving child fails the check. Owned fixture cleanup remains bounded on failing paths.
- [ ] SC4: Run affected absolute-file check and full Herdr all through bin/ace-test; no timeout increases, blind retries or product code changes. Independent source review precedes integration.

## Verification plan

Deterministically hold a fixture child between destination creation and PID-byte publication; observe existing readiness predicate accepting an empty file while the real child remains alive. This is analysis evidence, not a package passing test. During authorized task work add or revise maintained regressions to expose incomplete readiness independently of scheduler luck, and verify a real live owned child is not mistaken for absent. Reuse the owned process handle if it supplies simpler exact attribution than a PID file; behavioral requirements do not prescribe an algorithm. A controlled failing path must clean only its fixture-owned process. Then execute the exact affected file and all Herdr gates, retain receipt/timing and review verdict.
