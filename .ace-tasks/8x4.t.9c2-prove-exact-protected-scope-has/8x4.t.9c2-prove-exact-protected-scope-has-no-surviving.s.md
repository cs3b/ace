# Prove exact protected scope has no surviving writers


## Objective and ownership

Supply independently verifiable absence of all writers attributable to one exact
protected attempt so canonical finish and stop can truthfully release ownership.
This is the real upstream generic runtime/Assign capability extracted from
xz9.2's unresolved scope-proof requirement. It depends on 09j launch origin;
xz9.0 finish and xz9.2 stop consume it. It never depends on either consumer,
R2/R3 or Lab deployment. Existing Assign lifecycle/journal and runtime/native
owner remain the owners; no second controller, journal, domain broker or implicit
privilege increase is permitted. Advisory size large; real end-to-end slice.

## Observable contract

Before worker payload release, an attempt has one owner-established execution
scope bound to project, assignment, attempt, mapping, exact native server/launch
origin, original process PID/UID/OS birth and an unambiguous scope incarnation.
Workers cannot select scope names/paths, alter membership, create writers outside
it, migrate/escape membership, repopulate it after closure or obtain control over
unrelated attempts. The scope includes all descendants across fork, double fork,
reparenting, process/session/group changes and allowed namespace behavior.
Accessible native sockets and external spawners must be denied for outside-scope
writer creation or enforce exact inherited scope membership atomically. Merely
watching the original PID or its descendants does not meet this contract. Killing
all processes of a shared worker UID is not an acceptable substitute.

The existing protected owner offers a read-only scope observation to authenticated
mapped launcher/supervisor consumers, with owner-resolved origin identity and
sanitized state: running, closed_no_writers, or unverifiable. Only positive
closed_no_writers for the exact accepted scope/incarnation, after admission of new
writers is irreversibly closed, permits finish/stop to consume the proof.
It proves process/writer absence only; service effects and inbox reconciliation
still require their separate canonical owners. Worker booleans, exit codes,
mtime, timeout, empty pane, empty process group or empty unprotected subtree are
not evidence. Missing/unreadable/unsupported/replaced scope refuses and retains
ownership. Observation itself does not terminalize, kill, authorize effects or
prune. The proposed authenticated close operation may request scope termination; actual closed
no-writer observation is separately required after it.

Proof consumption and scope closure serialize with existing lifecycle admission
and canonical CAS. A competing spawn/claim cannot begin after the proof's
closed state. No journal event can become accepted proof solely by asserted
metadata: the selected runtime owner must positively verify the underlying exact
scope and bind observation lineage in the existing canonical attempt chain.
Restarts must reattach/revalidate the same scope incarnation without adopting
unrelated processes. Lost reply may reread retained truthful proof without
reopening the scope or repeating a destructive control. If reattachment cannot
prove identity/closure, retain uncertainty and expose required owner inspection.

## Proposed boundary and readiness

The reviewable proposal in scope-owner-proposal.md uses one existing system
systemd manager, a retained active parent slice and a dedicated Herdr service
per fixed reusable execution slot. Existing authority serializes scoped
StartUnit/StopUnit permission with canonical admission/seal/proof; no cgroup
delegation to workers and no new privileged domain broker. New attempts start
fresh generations automatically only after prior positive closure and canonical
release. Fixed map v2 pins installed unit/config/native/boundary artifacts;
canonical generation records pin actual manager InvocationIDs, kernel/server/
socket/cgroup/native origin. Existing 09j checks are adapted by this task while
preserving the actual fresh-child gate. This is proposed, not Captain-approved
architecture or installed acceptance.

Protected worker servers are exclusive per attempt and teardown at closure;
operator/overseer servers stay long-lived separately. Parallel attempts need
separate writer principals/slots. Unpartitioned same-UID simultaneous attempts
refuse, rather than allow UID-wide termination. These product choices need
Captain's decision. A required persistent shared worker server instead needs
native authenticated per-attempt spawn routing or another independently selected
boundary. No implementation may silently choose between those product outcomes.

Technical readiness remains unclosed: exact OS permissions, native per-start
0600 endpoint ACL setup and fresh fixed workspace readiness, active-slice identity
retention/reopening, and the complete usable filesystem/socket/network writer
boundary. The bounded native-readiness-acl-feasibility.md review establishes that same-User
ACL changes need no root execution, but the existing root-owned socket-parent
contract prevents unprivileged dynamic rebinding. The revised scoped proposal
uses a worker-owned final runtime parent and authenticates every connected kernel
peer against the exact admitted MainPID/birth/InvocationID before sending authority
data. Its explicit FD discipline and fresh-baseline contract preserve protected
origin; no installed proof or product preference acceptance is inferred.
local-writer-boundary-proposal.md declares the exact local resource set and usable
Linux/systemd Codex/Pi shell/build/provider profile. Remote effects and authorized
receiver in-flight work retain separate canonical settlement requirements; scope
closure cannot assert their cancellation. Effective installation and refusal
proof remain unperformed mandatory acceptance work.
These are mandatory results of this same real task, not future orphan
work. Source-backed required behavior, exact proposed interfaces/schema, generic
ACE versus Lab installer responsibilities and failure defaults are concrete in
the proposal; no fictional existing setup hook, scope owner or proof is assumed.
09j's existing retained pidfd proves exact-child exit only. The retained native
fixture demonstrates creation of another child through an accessible Herdr
socket; this task must close/account for that path, not infer it cannot occur.
A mechanism comparison and exact owner/installer/API/proof schema decision must
be independently reviewed before this task can be promoted. The requirements
above identify the result needed; they do not authorize an implementation guess.
Unsupported platforms explicitly refuse positive proof rather than claim parity.
macOS requires its own selected supported scope proof before supported acceptance.

This task and affected xz9.0/xz9.2 stay draft / needs_review. Positive finish/stop
are incomplete until this prerequisite is delivered. No native/protected probes,
Yama/auth changes, filter workaround or deployment are executed in this drafting
pass. The existing automatic-filter limitation remains recorded by 09j; future
verification requires an authorized permitted environment, never retry bypass.

## Success criteria and verification

- [ ] SC1: Real supported distinct-user launch establishes exact immutable scope
  membership while payload is gated; wrong origin/incarnation and placement race
  refuse release. Worker cannot enroll or control another attempt's processes.
- [ ] SC2: Real descendants including fork/reparent/session changes and each allowed
  external/native spawner are included or denied; no writer survives outside the
  observed scope and none can be created after its closed_no_writers proof.
- [ ] SC3: Original child exit with a surviving writer remains running/unverifiable;
  genuinely closed empty scope produces attributable proof consumed by canonical
  finish/stop under existing lifecycle/CAS, without settling unrelated effects.
- [ ] SC4: Owner/native restart, native replacement, stale scope identity, concurrent
  spawn/closure, lost reply and denied scope read preserve uncertainty until exact
  positive proof; retained cache cannot fake proof or reopen scope.
- [ ] SC5: Simultaneous unrelated slots remain isolated; control of one scope cannot
  inspect/kill/free another. Under the proposed exclusive-principal profile,
  unpartitioned shared worker UID refuses before payload release. Existing 09j gate
  remains intact. A Captain requirement for same-UID/shared-server concurrency
  requires revising the mechanism before promotion, not weakening this criterion.
- [ ] SC6: Selected source/schema and installed proof receive independent verdict;
  actual supported platform claims are backed by executed native evidence, not
  mocked kernel truth or documentation alone.
- [ ] SC7: After canonical close/release, the existing authority automatically
  starts a fresh fixed-slot native/scope generation without reinstall or privileged
  caller argv. Old proof cannot release the new attempt; crashes/unknown start
  outcomes inspect exact held generation without duplicate native spawn.
- [ ] SC8: Installed unit/native/ACL setup and filesystem/socket/network profile
  are independently verified from actual artifacts. Wrong unit/verb/property,
  outside-spawner path, mutable native startup/session and unsupported namespace
  refuse. Retained empty parent scope survives authority restart until proof and
  lifecycle release; service inactive/failed or missing cgroup alone never succeeds.

Component tests use real scope-owner and canonical journal/lifecycle behavior
with fault timing injection; installed tests in permitted isolated environments
exercise the selected native mechanism. During implementation run relevant
bin/ace-test suites and bin/ace-test-suite; no tests are executed for this spec.

This is one standalone large vertical slice: gated origin → complete writer
scope → authenticated close → restart-readable positive empty observation →
consumer-ready canonical proof → safe automatic reuse. Its generic installer
contract and permitted multi-UID/native fixture are included. xz9.0/xz9.2 own
their terminal integration; real existing Lab deployment work consumes the
generic installed profile. No task is created solely to research a primitive.
