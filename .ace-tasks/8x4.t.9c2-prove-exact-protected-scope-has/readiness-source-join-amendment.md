# Normative readiness and terminal source joins

2026-10-07. Complements the service-created-resource-stage and network-installation-evidence amendments. Source implementation only; no installed/native readiness claim or whole 9c2 acceptance.

## Acyclic installed readiness configuration

The trusted installer publishes one protected immutable `readiness_configuration` artifact. Its fixed service-view path is `/etc/ace/execution-slots/<slot_id>/readiness.json`. The unit manifest requires this role and the `boundary_manifest` role projected read-only at `/etc/ace/execution-slots/<slot_id>/boundary-manifest.json`. Both artifacts use the existing protected artifact identity/content verifier. No full Deployment descriptor is projected into the service: the descriptor already pins the unit manifest, so pinning it in that manifest would create a digest cycle.

Readiness configuration is at most 65,536 bytes of strict UTF-8 duplicate-free JSON with a closed schema: `schema` (`ace.assign.readiness/v1`), `slot_id`, `mapping_id`, `project_id`, `authority` (`socket_path`, `uid`, `gid`, `groups`), `worker` (`uid`, `gid`, `groups`), `native` (`workspace_id`, `socket_path`, `executable`, `version`, `protocol`, `executable_sha256`), `boundary_manifest` (`path`, `sha256`), and `runtime` (`interpreter_path`, `load_paths`, `dependencies`). Runtime load paths are at most 16 fixed absolute paths; dependencies are at most 256 exact `{path,sha256,bytes}` protected file references comprising the actual interpreter/stdlibrary/hook dependency load closure, within existing artifact-set aggregate bounds. Every dependency joins an immutable runtime_dependency or readiness_executable installation artifact and effective read-only projection; a directory path is never authenticated by a single file hash. The direct interpreter command is `[interpreter_path, "--disable=gems,rubyopt", readiness_executable_path, slot_id]`; no shell/env/Bundler/home discovery. Startup uses interpreter-owned standard-library paths only until protected fixed runtime inputs are established; all initial loaded file features must join declared protected dependencies, subsequent require paths are restricted to that same verified closure. Undeclared loaded files or writable load surfaces refuse. No process identity, runtime evidence, unit-manifest digest or Deployment digest is configuration. The authority independently compares every configuration value with its selected protected Deployment and verified installation profile. The hook verifies local protected bytes and the exact authority peer. Neither reader trusts caller transport hashes as installation authority.

The installer is the independent artifact producer. The runtime readiness hook is the service-view observation producer. The existing Assign authority is the independent admission consumer; its retained selected Deployment and profile decide the expected context. No new journal, privilege owner or controller is introduced.

## Complete resource topology

Boundary entries add exact Boolean `worker_visible` and `read_only` fields alongside `host_path`, `view_path`, `stage`. Native entries are worker-visible. A parent-only ancestor may be excluded from the hook projection only when positive installed topology proves it is not reachable in the worker namespace and is not writable there; a flag alone never authorizes omission. The installation reader compares the complete effective bind, writable path, runtime-directory and namespace topology with the declared resource union. Undeclared writable projections, ambiguous aliases and missing reachable entries refuse admission. Host observations still cover parent-only backing ancestors.

The hook pins the exact server PID incarnation, credentials, mount namespace and server root. It observes every reachable declared view with a read-only descriptor-relative traversal that contains resolution in the pinned server root and refuses symlinks (Linux openat2 RESOLVE_IN_ROOT|RESOLVE_NO_SYMLINKS; ordinary bind mounts remain allowed). Unsupported kernels/architectures refuse. It reports mount ID plus backing device/inode/filesystem/ownership and repeats server/namespace/credential checks after collection. No setns, ptrace, extra capability or namespace mutation is added. The authority independently observes backing roots, joins the exact projected identities and validates complete installed topology. Server namespace/root/executable reads requiring ptrace READ_FSCREDS belong to the same-UID hook; the different-UID authority does not require impossible proc reads. It independently pins the exact live manager MainPID/ControlPID and typed direct command runtime PID under the verified installation, joins kernel birth/credentials and host backing, and consumes only that authenticated hook observation.

## Admission and callback ordering

Before service admission, the existing NetworkInstallationEvidence owner verifies effective selected network evidence against the exact retained namespace, current boot, installed policy/profile and producer artifact. The canonical admission records its existing exact output. Missing effective evidence refuses.

The private readiness protocol uses one authenticated connection, one challenge, one nonempty scope-boundary-observation upload of at most 65,536 bytes and one exact acknowledgement with a fixed ten-second deadline. Control frames retain the existing 16,384-byte ceiling. The hook write-half-closes after the exact upload so the authority can verify EOF and still send acknowledgement on the same connection; neither side waits for a full close. The authority verifies the current fixed unit's exact ControlPID incarnation as the hook and the unit's exact MainPID as the server; matching worker UID alone is insufficient. Effective ExecStartPostEx must name the exact installed interpreter and fixed disabled-feature/hook/slot argv directly; shells/wrappers or any ambiguity between ControlPID and that actor refuse. This route does not confer ordinary worker mutation rights. Transfer length, digest, strict JSON, complete identity joins and EOF are mandatory.

No slot/assignment exclusion or authority mutex is held while waiting for StartUnit/readiness. The retained admitted generation coordinates one in-flight start; replay never starts a second service. Callback validation acquires fresh normal exclusions and checks the canonical generation/seal. A seal winning the race prevents native binding and causes the same fixed service cleanup. The authority registers a source-owned pending issuer atomically before dropping exclusions. While that issuer can still call StartUnit, closure/proof/release remains unavailable even when the current unit is inactive. A fresh exclusion check before issue skips a seal already won; if issue has begun, pending persists through completed or lost command return and cleanup. Only the issuing owner settles that pending lifetime. On authority restart, exclusive listener lifetime ownership and joined old handlers establish old issuer absence; durable admitted uncertainty still requires positive fixed-service cleanup and current proof. An inactive snapshot alone never clears pending issuance. Native binding is committed only after successful completed activation and independent Herdr endpoint/version/workspace verification. The original gated direct child remains unchanged.

## Closed proof and canonical terminal release

Fresh post-native or admitted-but-unbound closed proof requires the canonical seal, completed fixed service stop, no queued jobs, exact retained parent incarnation/cgroup, recursively empty population, worker UID quiescence and current boot/resource boundary checks. Lost-start recovery inspects the actual fixed unit and performs the same cleanup; missing native binding does not prove no execution. Native resources may disappear only after positive stopped-service and retained-parent emptiness evidence. The existing closed proof payload and its parent/seal bindings remain unchanged. Empty cgroup proves absence of surviving writers only; it never proves terminal success or no external effect.

No new terminal receipt type is invented. The shared lifecycle release owner accepts the existing canonical `receipt_accepted` terminal receipt only by invoking the existing receipt authenticity core after the terminal/receipt owner has authenticated its exact attempt/project/scope/producer/candidate/imported evidence and canonical terminal state. Supported receipt verdicts are `succeeded` and `failed`; stopped/reconciled outcomes remain unavailable without their own authenticated existing terminal receipt contract. `result_submitted`, unaccepted worker evidence, state text and population flags cannot authorize release. Guarded pre-release abort retains its existing independently verified terminal receipt path.

The existing `scope_reservation_release` mutation retains its exact data: assignment_id, attempt_id, mapping_id, scope_generation, scope_binding_event_id, proof_id, terminal_event_id, reservation=`released` (plus canonical authority generation). `terminal_event_id` is the digest of the actual accepted terminal receipt event or the existing guarded-abort terminal event. Release requires both authenticated terminal evidence and exact current closed proof, plus complete existing service/inbox settlement, under the same exclusions and CAS. This shared source capability does not implement new finish/stop product controls. Historical consumers structurally join this exact producer event and authenticate the release-prefix receipt/settlement with the original protected descriptor context.

## Complete fixed implicit resource profile

The supported effective service profile requires `PrivateTmp=false`, `MountAPIVFS=true`, `PrivateDevices=true`, `PrivateIPC=true`, `ProtectKernelTunables=true`, `ProtectControlGroups=true`, zero capability sets, `RestrictNamespaces=0`, and no extra device grants (`DeviceAllow=[]`). `DevicePolicy=closed` is the supported effective device policy. These are exact typed manager observations joined to the protected installation manifest, not optional hints. The existing direct fixed executables, RootDirectory, no inherited listeners and restricted address-family/syscall contract remain required. No new privileged owner or broad syscall denylist is introduced.

`/dev/shm` must have exact effective `ReadOnlyPaths` coverage and no overlapping writable projection. Kernel API/device views are excluded from ordinary durable storage only under the complete fixed profile above and live readiness mount verification; filesystem names and visibility flags alone never authorize exclusions. Explicit bind mounts into `/dev`, `/proc`, `/sys` (including their descendants) are unsupported and refuse rather than introduce host storage through a pseudo-filesystem exemption. Implicit journal descriptors retain the accepted outside-local-set logging contract; filesystem journal/control socket mounts do not gain an exception.

With PrivateTmp disabled, `/tmp` and `/var/tmp` use the selected RootDirectory or exact declared bind projection. Each must be positively read-only under effective strict protection (no overlapping writable projection), or have its complete exact writable host/view declaration and original backing identity in the boundary inventory. Any writable ReadWritePaths/bind/runtime projection still requires complete declared inventory and same-UID live server observation. ReadOnlyPaths syntax is exact absolute paths, without optional prefixes or aliases. A read-only ancestor cannot conceal a writable descendant; every writable projection is independently enumerated. Unverified manager-generated tmpfs/IPC backing remains unsupported. Ordinary shared memory via memory objects confined to the admitted process population does not create a new durable host resource grant.

The source test matrix includes a legitimate supported profile with read-only implicit paths and explicit writable workspace/runtime roots, writable `/tmp` with exact declared backing, and refusal of missing backing, PrivateTmp, writable `/dev/shm`, API-subtree bind aliases, additional device grants and changed effective kernel protections. Tests use controlled typed profiles and synthetic mount observations only.

This precision follows the fixed-profile behavior documented by [systemd v257 execution documentation](https://raw.githubusercontent.com/systemd/systemd/v257/man/systemd.exec.xml): strict protection exempts API trees, PrivateDevices supplies a minimal device view, kernel-tunable protection closes API writes, and PrivateTmp introduces separate backing. It does not assert installed effectiveness or authorize native probes.
