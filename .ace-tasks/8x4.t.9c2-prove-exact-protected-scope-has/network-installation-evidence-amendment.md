# Network installation evidence and maintenance — proposed normative amendment

2026-10-05; specification freeze based on main dd7681099. Independent readiness review required; 9c2 remains in-progress / needs_review=true. No product implementation, probes, Lab operations, publication or installed acceptance is claimed. Existing accepted source freezes and negative review evidence remain intact.

This candidate supersedes only the ineffective passive packet-filter readiness assumption and temporary network drafts. It preserves all accepted writer/resource/closure/settlement and continuous-reuse criteria. The rejected fixed outbound provider/DNS/Git CIDR allowlist is not adopted. It selects the existing trusted root installer as the effective enforcement evidence owner; runtime receives no NET_ADMIN, Netlink permission, controller or new privileged API.

## Required behavior

Ordinary Internet egress, including provider/DNS/TLS and remote Git traffic and their established responses, remains permitted. There is no provider CIDR allowlist, and ordinary provider address changes require no maintenance. Deny unsolicited external ingress and connections to protected host/internal process-control or storage-control destinations capable of escaping the protected writer boundary. Loopback tools stay within the slot namespace/scope. Remote business effects remain separately scoped canonically; Internet access alone is not a local escape.

The root installation owner classifies protected host/internal destinations and enforces their denial before general egress. Unclassified host/internal control reachability refuses installation. If ordinary Internet resolution lands on a protected destination, the deny wins. Ordinary Internet routing/address churn that preserves this boundary is allowed; changing protected network topology, denial sets, namespace object or enforcement rules requires excluded installation maintenance and fresh evidence. No passive /proc snapshot proves firewall enforcement.

## Closed profile selected by the boundary manifest

Use UTF-8 JSON with no duplicate keys, root exactly `{version,profile_id,slot_id,namespace_path,families,protected_controls,loopback_tools,credential_profiles}`; version1, bounded ASCII IDs1..128, unique per collection, file at most1MiB, combined entries at most256. Namespace path equals protected deployment selection. families contains exactly ipv4 and ipv6, each `{family,mode}`, mode enabled/disabled. Disabled requires actual enforced absence of external family reachability; unavailable check tooling cannot count as disabled. Unsupported configured family refuses.

protected_controls entries exactly `{id,family,kind,address_ranges,protocol,ports}`: kind host_process/internal_process/protected_storage; protocol tcp/udp; address_ranges canonical CIDRs, ports explicit integer1..65535 list or literal `all`. This enumerates the complete protected control surface from trusted Lab topology/catalog, including namespace backing host/control networks. The domain policy may deny an entire protected range for simplicity; it must not make approved ordinary Internet egress depend on a finite provider list. IPv4/IPv6 treatment includes loopback, link-local and routing controls necessary to exclude protected host/internal reachability. Unclassified protected control destination refuses, rather than becoming general egress.

loopback_tools entries exactly `{id,family,protocol,address,port,artifact_sha256}`; tcp/udp, address127.0.0.1 or::1, valid port, immutable executable digest. Arbitrary payload-created listeners on external interfaces remain inaccessible because all unsolicited new external ingress is denied; denial is not limited to listed tools.

credential_profiles entries exactly `{id,kind,helper_artifacts,configuration_artifacts,authority}`; kind provider/dns/remote_git; authority remote_only; protected artifact references use `{path,sha256,bytes}`. No credential contents in evidence. Fixed helper source/config and actual installed ownership establish no host-login/process/protected-local-storage control authority. Unknown helper capability refuses. Credential endpoint address changes alone do not invalidate the profile; grants/helper/config capability changes do.

Timeouts alone never prove denial. Environmental/observer inability yields incomplete/refused report. ## Closed selection and generic verifier

Add one required `network_installation` selection to each fixed execution-scope boundary manifest, exactly `{profile,policy_export,report,installer_artifact}`. Each is an immutable protected artifact reference exactly `{path,sha256,bytes}`: absolute canonical path without NUL or traversal, lowercase 64-hex digest, positive integer byte length within the bounds above. Source paths are fixed installer selections, never params/worker upload. Artifacts are regular files under authenticated root-owned, non-group/other-writable ancestry; no symlink, mutable shared directory, ACL permitting untrusted writes or overlapping worker writable resource. Existing protected artifact owner verifies actual bytes, ownership and ancestry before parsing, with handles held across verification. Namespace path is a separately authenticated persistent nsfs object, not parsed as an ordinary content file. Evidence filenames use content digests; publication never overwrites historical selected artifacts.

Proposed source-only `Ace::Runtime::Molecules::NetworkInstallationEvidence.verify!(selection:, expected:)` has exact keyword arguments. `selection` is the manifest object above; `expected` is exactly `{slot_id,namespace_path,boot_id,namespace_identity,installer_artifact_sha256}` derived by the fixed installed owner, not a new trust root supplied over transport. Namespace identity is exactly positive integer `{device,inode}`; the owner opens/pins the selected namespace object and validates its nsfs network type, boot and identity. The verifier does bounded protected reads only, no shell, policy mutation, network probes, arbitrary policy parser or live privileged exchange. It checks every transitive report/trace/artifact reference once against its declared length/digest/root protection; cycles, duplicates with inconsistent refs, unknown fields/types, invalid UTF-8/duplicate JSON keys, unsupported version, bounds overflow and context mismatch refuse. IDs are ASCII `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`; digests 64 lowercase hex; source SHA 40 lowercase hex; UUIDs canonical lowercase; timestamps RFC3339 UTC. No coercion or defaults. Every profile ID, target ID and check tuple is exact and unique. Family values are only `ipv4`,`ipv6`, or `all` where the mandatory check table selects it. Address family, canonical address/CIDR, port/protocol and referenced helper digest must agree.

Successful output is a deeply immutable exact `{report_id,boot_id,slot_id,namespace_path,namespace_identity,profile_sha256,policy_export_sha256,report_sha256,installer_artifact_sha256}`. Root report references and selected producer agree. Artifact integrity/schema success is authenticated installation evidence validation, not an independent runtime verdict about actual packet filtering. The independently reviewed root producer and its enforced lifetime are the explicit trust premise. Unreadable/unsupported/incomplete evidence raises the existing boundary evidence refusal, exposed as `evidence_unavailable`; malformed untrusted public selectors retain existing `invalid_input`. No optional absent evidence fallback.

The domain producer's raw export combines every effective table/chain/hook/rule/set and relevant namespace/host routing, forwarding/NAT and interface topology capable of bypassing this boundary, including IPv4 and IPv6. Its fixed reviewed source must compare the complete supported installed policy against the profile, including conflicting/extra hooks, forwarding routes and enforcement precedence. Unknown topology, unsupported policy constructs or unclassified reachable control paths refuse. The generic verifier does not choose nft syntax or implement this domain comparison. Named source procedures and exact tested supported tool/kernel versions are selected by the immutable producer artifact; implementation details may vary only while satisfying this contract and receiving source/installed review. Raw exports and actor/setup/correlated flow observations must be retained; a summary result alone never establishes a producer pass.

## Canonical stage and readiness joins

`scope_bound` adds required `network_installation_selection` (the exact four fixed manifest artifact references, not successful report output) and `network_namespace_identity` (exact `{device,inode}`). The latter is the authority's opened/pinned installed slot network namespace object, not its own namespace. Manifest selection/protection and the actual object are pinned before parent activation; missing namespace identity refuses activation before creating a parent. Parent binding asserts no effective-policy verification and does not parse an unavailable report. The independent parent remains bindable/closable when later network admission refuses. No native process/payload may start from parent selection alone.

Immediately before the existing private `scope_service_admission` canonical CAS and fixed StartUnit, the generic verifier must succeed under the same lifecycle exclusion. The successful private mutation's immutable data adds exactly `network_installation` (the complete successful verifier output), matching parent selection/boot/slot/path/held namespace. The fresh CAS winner alone may start; replays never call StartUnit. Missing/invalid evidence creates neither service-admission mutation nor service start. Native startup failure/lost reply retains the original admitted parent; no report is retrofilled or fabricated.

`scope_native_bound` adds required `network_namespace_identity` and `network_admission_event_id` (64 lowercase hex digest of that exact private authority mutation), joining its successful immutable installation output to the original parent selection and actual original server namespace. The approved authenticated same-User ExecStartPost private report adds exactly `network_namespace_identity`: the hook opens `/proc/<exact original server PID>/ns/net` only after existing kernel birth/credential and manager InvocationID/ControlPID admission, validates nsfs type and derives dev/inode from that held object. It never substitutes its own namespace, reads privileged firewall state or changes networking. Existing challenge, 64 KiB total purpose bound, exact report schema, ACK/pending observation, activation-completion revalidation and no-lock-held-across-StartUnit ordering remain in force. This additional field is proposed protocol/schema work, not an existing implemented field. Pending report without complete activation and revalidation commits no native stage.

Original-child admission continues through genuine 09j native direct spawn and the original immutable worker gate. The selected independently reviewed native startup/layout implementation must create this exact child directly within the original server namespace, without setns/unshare/CLONE_NEWNET or handing spawning to an outside process; exact original native/child binding already proves the admitted spawn origin. Fixed gate and server syscall/capability/FD profiles deny network namespace replacement/escape before and after release. `scope_child_bound` references the exact native stage with that network selection; it does not claim a direct cross-UID child `/proc` observation. Denied namespace mutation plus proven direct spawn inheritance supplies the child join. An unsupported native/helper artifact or unexplained external spawn refuses before payload release. This adds no gate-ready caller boolean, cross-UID ptrace, runtime privilege or native API.

Before any service-admission mutation exists, close/positive proof validates the exact independent parent/seal/recursive-empty/no-pending-activation facts; unavailable network report cannot block cleanup of a never-native-admitted generation, and that cleanup asserts no effective policy readiness. Once native activation was admitted, close/positive proof validates its committed successful installation joins and retained original artifacts as well. Later live admission additionally verifies current boot/held namespace when claiming current readiness. Stopped server metadata/namespace handles may disappear exactly as permitted by the accepted retained empty-parent rule; no stopped-child or missing namespace path becomes positive process proof. Historical released terminal replay validates original canonical facts and retained original content artifacts, without requiring the old namespace to stay installed after legal retirement; it cannot authorize new current admission. Missing canonical original evidence remains refusal. After boot change, installation must regenerate current evidence for the new boot; an unreleased generation remains uncertain under the existing rule, rather than getting adopted by a new report.

## Shared complete-slot owner interface

The following proposed Ruby-only methods belong to existing `LaunchLifecycle`, constructed from fixed authenticated Deployment, its existing protected journals and kernel/scope owner. They are callable by the existing root installer after authority shutdown, without a live Authority socket, worker peer or new controller. They are source contracts to implement and independently review, not delivered calls.

`with_execution_slots(mapping_ids:, candidate_deployment:) { |contexts| ... }` accepts a nonempty unique array of at most 256 mapping IDs plus the authenticated staged candidate Deployment descriptor. The owner is constructed with the original selected Deployment and its fixed journals. The staged object validates closed schema/protected source/artifact selections but supplies no assertion of current installed readiness; effective evidence is verified only after installation. These are existing source-owned descriptor objects, not arbitrary payload hashes or caller-selected roots. It resolves through fixed Deployment and expands to the complete mapping/journal set for affected slots in the original selected and proposed descriptors; caller-selected assignment/journal paths cannot limit the scan. Current v2 forbids duplicate slot/unit/worker owners, so each physical slot has exactly one fixed project/journal association. Existing mapping IDs retain their project/journal/authority state-root/slot association, and cannot be recycled to hide old history. This contract prohibits reassociation of an existing physical slot to another project/journal; new ownership uses a fresh physical slot and namespace identity. All removed old entries must complete settlement/release and exact parent retirement under their old selected roots/locks before publication can remove them. Fixed installer configuration determines the full affected mapping set for descriptor publication. Inconsistent physical-slot/lock aliases refuse; configuration cannot give the same physical slice/service/namespace separate exclusions under different authority IDs. Existing persistent slot locks use the identical normal admission lock path; acquire the union of original and proposed unique `(canonical authority state_root, LifecycleExclusion.slot_key(slot_id))` locks in fixed lexical order and release in reverse order. Every affected slot stays excluded for the whole block. No public mutation API is added.

Only after locks are acquired, resolve every fixed relevant journal root and its current protected canonical ref. Yield a frozen array of exact contexts `{mapping_id:,journal:,commit:}` sorted by mapping ID; journal is the existing owner object, commit a verified immutable canonical commit. Each context is internally pinned to its exact original selected owner map, including mappings removed from the candidate; newly added fresh slots use their staged fixed map. A plain mapping ID cannot cause lookup in the replacement descriptor. Contexts for one project/journal share the same snapshot. Different relevant roots are all included; missing root, unreadable ancestry/history, duplicate conflicting identity or unavailable lock refuses before any policy operation. No hidden default journal. Normal admission and canonical slot-release operations use these same exclusions. The root installer keeps the yielded exclusions continuously through complete scan/settlement, retirement, policy/artifact/descriptor publication. Contexts confer no later independent mutation grant after the block ends.

`slot_reusable!(mapping_id:,journal:,commit:)` requires that corresponding slot exclusion is currently held by this owner invocation and that the context is one of the complete selected fixed roots. It rechecks current ref equals supplied commit; a changed ref is `Conflict`, not a stale success. Enumerate `journal.assignment_ids(commit:)` and complete `read_events` at that same commit for every assignment/attempt/reservation that can own the slot, including retained reservations represented in accepted history for that fixed slot association. Missing/unknown historical mapping or provisioning identity refuses; the current mapping list cannot silently erase history. Corrupt/unattributable chains cannot disappear because current map or disposable cache omits them. Across all yielded roots, any active/unreleased/uncertain reservation refuses maintenance. No-reservation empty slot is legal only after the complete inventory and actual fixed-unit job/process check confirm no unexplained owner.

Every previously owned reservation must have exact original positive whole-parent proof, canonical terminal admission and existing private `scope_reservation_release` authority mutation naming that original parent/proof/terminal event; a terminal flag or child exit alone is insufficient. Call the shared `scope_settlement_complete!(journal:,events:,params:,map:,commit:)`, using the full exact attempt event chain and immutable context commit. It derives two cases from canonical events rather than a caller-selected historical flag: before release it requires current exact service/inbox settlement; after a structurally verified unique canonical release it verifies original immutable terminal/release/evidence/import authentication at the release prefix and examines the remaining chain/current actual retained inventory for new, unsettled, unattributable or unregistered work. A post-release event cannot be hidden by the historical branch. Any such work refuses. Superseded/requeued current inbox is not terminal settlement.

Historical released validation uses the original retained fixed descriptor and public authentication artifacts selected by its canonical deployment/key digests, original signed receipt/signature bytes and canonical import descriptors/claim generations, plus service completion/result/closure lineage. It does not demand old live process metadata, old namespace existence, current rotated key bytes or current context paths. The root installation manifest retains explicit protected content artifact refs for original descriptors and referenced public keys/configuration; original immutable files are never overwritten by rotation (a new key gets a new protected artifact/path). Generic source-owned evidence readers select those original refs by exact canonical digests and verify their bytes/ownership; no global discovery or current-key fallback. Historical use is verification only and cannot authorize a current claim. No new delivery/execution ledger is introduced. Missing original authentication artifacts refuses rather than silently trusting a release boolean; installer must preserve them before replacement/rotation. The shared owner uses its existing verification core with the original fixed context for historical imports, while current inventory validation remains exhaustive under the original/candidate fixed contexts. Successful result is `true`, with no canonical mutation or released-proof replacement. Cross-root validation is complete before any retirement begins. Ref change or occupied slot raises `Conflict`; unreadable/unsupported origin/proof/settlement raises `EvidenceUnavailable`.

`retire_released_parent!(mapping_id:,journal:,commit:)` requires the complete-slot predicates above at the still-current snapshots under the same held exclusions. Resolve actual fixed parent/service from installed owner, join any active retained parent InvocationID/cgroup to the exactly released canonical generation, verify original positive proof, seal, no pending activation/job and current recursive unpopulated state. Service must be stopped with no pending job; stopped service metadata may be absent only under the accepted retained-parent rules. Then invoke the existing permitted fixed `StopUnit(slice)` through that same scope owner and verify actual parent stopped, no pending jobs and no surviving scope processes; never independently kill/recreate/delete an unreleased parent. Replaced, populated, unknown or unprovable active object refuses. Already stopped with no jobs/processes is an idempotent no-op after canonical eligibility verification; absent old unit metadata alone is not a positive writer proof. Return `true` only after actual retirement/no-op verification. No historical proof is deleted, rewritten or regenerated. Interrupted stop reinspects the same released identity; a subsequent invocation cannot adopt a replacement or duplicate start. Retirement creates no new reservation, terminality or network readiness.

## Trusted root installation transaction

Root installer keeps immutable original selected descriptor/artifacts and the staged candidate accessible throughout failure recovery. The existing protected installation manifest contains exact `{original_descriptor,candidate_descriptor}` artifact references; this is installation configuration/provenance, not a second canonical execution ledger. It is atomically published/fsynced while inhibited before any policy mutation; existing descriptor selection remains authoritative until final publication. Recovery must scan the union of both and never choose whichever set makes admission easier. If original/candidate cannot be authenticated or scan obligations cannot be reconstructed, inhibition remains and maintenance refuses. Removed roots/locks are retained until complete old eligibility/retirement and final transaction completion; historical content artifacts, original descriptors and referenced public authentication/configuration artifacts remain retained thereafter. Rotation creates fresh protected artifact paths and cannot overwrite historical verification inputs.

Root installer resolves all descriptor-consuming authority units/processes and automatic activation routes from fixed protected installation configuration. The default is to stop all authorities loading the shared descriptor; an allegedly unaffected cached partition cannot be inferred from paths. No concurrent second installer/manual bypass is allowed. Intended final unit activation configuration is immutable installed manifest input, separate from current masks.

1. Before any namespace/policy/descriptor mutation, persist and fsync activation inhibition for every affected authority and socket/path/timer/dependency activation route through the existing system-manager installation owner. Use persistent masks, never runtime-only masks/disable. Reload and verify all inhibition. Unknown unit/restart route or untracked authority process refuses. Masking inhibits future activation, not current handlers.
2. Request normal stop, wait for all old authority process incarnations and dispatched handlers to terminate, listener ownership to release and authority jobs to settle. Verify exact fixed-unit/process closure; a stop exit or missing socket is insufficient. Do not hold slot/assignment/journal locks while waiting for handlers that need them. Failed quiescence refuses policy mutation; no shortcut unlink. Existing installer stale-endpoint recovery remains owner-checked.
3. With authorities stopped and durably inhibited, enter `with_execution_slots` for all affected slots. Verify every complete `slot_reusable!` snapshot across all roots, then owner-mediated `retire_released_parent!` for eligible retained generations. Revalidate refs/eligibility before policy mutation. Stop never terminalizes attempts. Unreleased/uncertain history blocks maintenance even across reboot.
4. Keep exclusions and persistent inhibition through namespace/policy change, actual effective-policy verification/checks, immutable artifact atomic publication/fsync and final whole descriptor atomic publication/fsync. Runtime may not use original cached Deployment across replacement. Failure publishes no positive replacement; inhibition remains. Rollback repeats the same complete verified transaction; never restore old descriptor over changed enforcement.
5. Only after complete selected descriptor/artifacts/current boot+namespace policy pass verification, leave the exclusion block, restore the fixed approved activation configuration/unmask, reload and start fresh authorities. Verify new exact incarnation loaded the complete final descriptor and startup/readiness before reopening product operation. No old authority may survive. Do not hold slot locks through startup admission/readiness that needs them.

Root guarantees no enforcement weakening, protected topology/grant/helper/namespace replacement while any slot has an unreleased/uncertain owned reservation. Ordinary Internet routing/provider address churn preserving the protected-denial boundary is allowed without maintenance. Protected topology/denial rules/namespace or credential capability changes require this full excluded transaction and fresh evidence. Worker/server/gate cannot mutate namespace/policy or root evidence. This is a declared trusted root installation lifetime, not a runtime claim to reexport firewall state on each request.

## Crash, reboot and failure ordering

Before durable inhibition finishes, policy/descriptor must remain unchanged. Crash during stop can leave an old authority alive with unchanged installation; recovery first redoes inhibition and exact quiescence. After inhibition/stop or during mutation/publication, persistent masks prevent boot and automatic activation. Existing files, a timestamp or prior installer exit never clear inhibition. Recovery repeats this same source-owned slot scan/retirement and either finishes a fully verified installation or fully verifies rollback. No accepted canonical reservation/release state is invented to unblock it.

Crash after verified complete final descriptor but before unmask leaves safe unavailability. Crash after unmask may activate only fresh authorities loading that final selected set. Every automatic restart route must honor persistent inhibition. Boot mismatch requires fresh current installation evidence; historical proof retains its original boot and cannot release an uncertain unreleased generation. Root bypass of this protocol is forbidden to the installer; its absence is part of the stated trusted-owner premise. No new maintenance ledger, key service, daemon or runtime authority is introduced.

## Source evidence and review boundary

Read-only source seam: Deployment.load copies the protected descriptor; Authority Server retains it and joins dispatched handlers at shutdown. This requires stopped/drained fresh authority replacement, not hot reload. [systemd v257 mask semantics](https://github.com/systemd/systemd/blob/v257/man/systemctl.xml) distinguishes persistent and runtime masking; fixed installation must verify the actual activation graph. [Linux namespaces](https://man7.org/linux/man-pages/man7/namespaces.7.html) documents opened namespace identities and process namespace inheritance; [network namespaces](https://man7.org/linux/man-pages/man7/network_namespaces.7.html) includes network devices/routing/firewall state. Same-User passive hook feasibility and inability to read effective nft policy are retained in network-boundary-feasibility-review.md and approved resource amendment; this proposal does not reverse that finding.

Scope author supplied current source-only interface seams and agreed the original/candidate union design is compatible. The candidate_deployment keyword and internal original-map pinning above are explicit proposed extensions to that seam, not existing WIP functionality; no WIP implementation is represented as integrated/approved. Independent readiness review must cover this exact consolidated candidate and the domain task patch proposal before needs_review can clear. Product source and actual installed tests remain subsequent work.
