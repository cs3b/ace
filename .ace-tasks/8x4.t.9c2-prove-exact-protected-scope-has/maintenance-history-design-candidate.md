## Research finding requiring an explicit decision

`scope_provisioning.deployment_digest` and the scope binding currently hash only the launch mapping. They cannot distinguish two whole descriptors with the same mapping but changed project context/public key. Inbox registration does pin the public key's DER digest. Canonical service imports already authenticate executor identity/binding/generation through the protected journal and do not use an independent public signature key. Current `ProtectedInbox.build` uses the current key path/live retained record; it is unsuitable as a historical released verifier.

Proposed decision: preserve the existing mapping digest semantics used by native/network installation joins and add `descriptor_sha256` to canonical scope provisioning, naming the exact protected whole descriptor artifact selected when reserving. The current Deployment load must use the same held protected artifact reader as installer descriptor loading so it retains exact immutable byte provenance. Historical selection requires this canonical selector and the matching protected artifact reference. Missing original selector/artifact is unavailable; no current-descriptor/key fallback, automatic migration, or historical record rewrite. This is a pre-1.0 schema change. Root must approve this producer contract before implementation, including its consequences for already retained unsupported reservations.

Fixed current `/etc/ace/assignment-authorities.json` necessarily changes content on publication. Immutable retained descriptor artifacts remain at their protected manifest reference paths, including the original after publication. The installed current descriptor therefore joins the manifest original/candidate **by exact verified whole-file SHA256 and byte length**, not by pathname equality. Each side has its own independently verified held protected bytes; no parsed mapping comparison, current-context substitution, reserialization digest or discovery fallback authorizes the join. Historical descriptor selection still resolves the exact immutable manifest artifact reference by canonical SHA256. Maintenance requires original content selection and exact candidate content selection. This precision replaces the prior shorthand 'exact selected artifact reference' where it referred to binding the fixed current publication path; it does not relax any retained artifact reference verification.
