# Preserve active Git operation state during scoped commits

## Objective

Prevent scoped commits from silently abandoning an active merge or other sequenced Git operation. During xz9.0 integration, the author reported loss of merge metadata and auto-staged paths after scoped commit staging. Source inspection confirms `stage_paths` executes an unrestricted `git reset --quiet`; the orchestrator validates only that the directory is a Git repository before staging. No independent disposable reproduction has yet been performed.

## Behavioral contract

`ace-git-commit` refuses an active merge, rebase, cherry-pick, revert, or sequencer operation before changing the index, working files, operation metadata, refs, or invoking message generation. This applies to explicit paths, all-files, staged-only, and split modes. Exit is nonzero with the detected operation and guidance to finish through the native Git continuation command. No automatic abort, reset, repair, or inferred continuation is allowed.

For repositories without an active operation, existing scoped and staged-only commit behavior remains available. Worktrees must be inspected through their actual Git metadata, including shared versus per-worktree state. An inability to inspect operation state refuses mutation with an actionable diagnostic.

## Success criteria

- [ ] SC1: A resolved but uncommitted two-parent merge is refused unchanged; native merge completion still produces both expected parents and all resolved files.
- [ ] SC2: Unresolved merge and active rebase/cherry-pick/revert/sequencer states are refused without losing staged entries, conflict stages, operation markers, refs, or working content.
- [ ] SC3: Explicit path, all-files, staged-only and split invocations obey the same pre-mutation boundary, including linked worktrees and inspection errors.
- [ ] SC4: Ordinary scoped commits still commit only the requested paths, with existing behavior verified outside an active operation.

## Slice and verification

Single medium slice: safe user-visible refusal before any commit preparation mutation. Use maintained real disposable Git repository scenarios through `ace-test`, with before/after index, operation metadata, tree/ref evidence and actual successful native continuation. Include a two-parent merge and sequenced cherry-pick/rebase in linked worktrees; component checks can cover detection errors. Independent review must verify the guard precedes every staging and split-reset path. Do not run destructive reproduction commands in a user checkout.

## Scope and readiness

Owns ace-git-commit operation-state safety and public diagnostics. Does not implement native operation continuation or change the Lab execution contracts. Existing native Git completion is the current integration procedure; this task is not a prerequisite for the Lab release. Draft pending independent readiness review; no package implementation is included here.
