# Sprawdzić pełną sekwencję przygotowania i wykonania

## Cel

Przed release potwierdzony jest pełny system z lokalnie zbudowanych paczek. Ten subtask dostarcza następujący wycinek: Na lokalnie zbudowanych gemach w świeżym środowisku wykonać planner → worker → reviewer z poprawkami → integrator → odblokowanie następnego taska.

Reguły wspólne są częścią tej specyfikacji: [kontrakt programu](.ace-tasks/8xg.t.sbz-lab-ace-pliki-zadania-role/contract.md). Obowiązuje zatwierdzony model plikowy; stare materiały są źródłem kontekstu, nie nakazem zachowania ich architektury.

## Zachowanie i interfejs

Istniejące testy i scenariusze ACE; lokalne gemy, świeże środowisko, zapis wyników przy zadaniu. Bez nowego frameworka odbioru.

Na lokalnie zbudowanych gemach w świeżym środowisku wykonać planner → worker → reviewer z poprawkami → integrator → odblokowanie następnego taska.

## Kryteria odbioru

- [ ] Wynik dokumentuje faktyczne przejścia ról, taski, worktree, review i integrację wraz z wersjami testowanych paczek.
- [ ] Niespełniona zależność lub nieukończony assignment nie przechodzą do następnego kroku i nie są oznaczane jako sukces całego testu.
- [ ] Wynik jest zgodny z kontraktem programu i możliwy do użycia przez następną rolę lub narzędzie.

## Plan weryfikacji

- Scenariusz pozytywny / integracyjny: Wynik dokumentuje faktyczne przejścia ról, taski, worktree, review i integrację wraz z wersjami testowanych paczek.
- Scenariusz błędu / niepoprawnego wejścia: Niespełniona zależność lub nieukończony assignment nie przechodzą do następnego kroku i nie są oznaczane jako sukces całego testu.
- Zapisać rzeczywisty wynik i odnośniki do testów lub przeglądu w folderze tego taska.

Dla zmian implementacji: `bin/ace-test <zmieniony-pakiet> all`, `bin/ace-test-suite` i niezależny review przed merge; commity ograniczone do właściwych ścieżek. Dla samych instrukcji: weryfikacja rozwiązywania workflow, kompletności i zgodności scenariuszy. Poniższe scenariusze są wymaganiami odbioru, nie deklaracją wykonanych testów.
