# Productionize the ACE RubyGems publisher

## Behavioral Context

W565 required an emergency publication of 38 ACE gems. Sequential builds and
registry checks consumed multiple short-lived OTPs, while an empty
`GEM_HOST_API_KEY` indirection caused rejected pushes. The follow-up workflow
documented build-all-then-burst behavior, but left the mechanical publisher as
an untracked seed without tests or a secret-safe interface.

## Objective

Ship a tested repository publisher that discovers the current ACE gem graph,
builds every pending artifact before publishing, and performs resumable,
dependency-safe RubyGems pushes without exposing credentials or OTPs.

## Behavioral Specification

### Interface Contract

```bash
.ace-bin/ace-rubygems-publish --dry-run [ace-gem...]
GEM_HOST_OTP_CODE=<otp> .ace-bin/ace-rubygems-publish [ace-gem...]
```

- `--dry-run` reports the deterministic pending schedule without credentials, builds, or publishing.

- Live mode uses only `GEM_HOST_OTP_CODE`; OTP values never enter argv, output, errors, reports, or fixtures.

- RubyGems commands receive credentials and OTP only through their inherited environment.

### Expected Behavior

- [x] Discover every local `ace-*/*.gemspec` and its internal runtime dependencies.
- [x] Produce deterministic dependency-respecting waves containing at most five gems.
- [x] Resolve the pending set from one remote version snapshot and skip versions already published.
- [x] Build or validate every pending artifact before the first push.
- [x] Fail before publishing when credentials or OTP are absent or invalid.
- [x] Stop after a failed wave, retain every unproven artifact, and safely resume by re-querying RubyGems.
- [x] Delete only artifacts whose push response proves publication or prior publication.
- [x] Keep every remote and publish boundary stubbed in tests.

### Security Constraints

- Do not accept OTP through CLI arguments.
- Do not print, persist, hash, interpolate into errors, or place OTP values in fixtures.
- Do not inspect credentials in repository tests and do not make live RubyGems mutations.
- Use ACE HITL only to request operator attention; persisted HITL answers must never contain an OTP.
