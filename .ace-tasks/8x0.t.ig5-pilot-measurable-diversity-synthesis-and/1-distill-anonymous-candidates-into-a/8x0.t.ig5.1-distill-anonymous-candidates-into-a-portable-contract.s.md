# Distill anonymous candidates into a portable contract

## Behavioral Specification

### User Experience

A fresh implementer receives a decision-complete synthesis package without needing the discovery chats or reviewer transcripts.

### Expected Behavior

- Provide Sol anonymous candidate labels, code/artifacts and verified evidence; exclude author/model reputation and implementation cost from quality judgment. Retain the label-to-provenance map for audit outside the judgment input.
- Produce the canonical task contract, demonstrated strengths/failures, shared versus differing assumptions, invariant/evidence matrix, architecture recommendation, executable acceptance probes or explicitly marked missing probes, and uncertainties.
- Distinguish demonstrated facts from architectural recommendations and untested hypotheses. Require every decisive factual comparison to reference a candidate revision and evidence.
- Include the applicable validated L4 invariants; unrelated/version-inapplicable catalog entries are not blindly imported. Missing or contradictory evidence is visible and cannot become a supported claim.
- Synthesis may recommend reuse of selected implementation code, but records provenance and never labels reuse as independent discovery. The final implementer starts from the common base with the synthesis package; there is no automatic merge of all candidates.
- Freeze/hash the handoff package. A fresh context after restart/compaction can resolve all required relative artifact references; mutable or missing inputs fail validation.

## Interface Contract

A synthesis assignment step consumes candidate manifests plus the canonical task contract and applicable invariant entries. It emits a self-contained package with a manifest, decision/specification document and probe references. The final implementation step consumes the package identity; status distinguishes complete, unsupported-input and architecture-conflict outcomes.

All interfaces described here are proposed acceptance contracts, not a claim of currently installed functionality. Draft usage scenarios are in `ux/usage.md` in this task directory.

## Success Criteria

- [ ] SC1: Generate a package for candidates with complementary strengths and a shared false assumption; preserve all three in the evidence matrix.
- [ ] SC2: Launch a fresh-context implementer using only common base and package; reproduce the required probes and implement without chat history.
- [ ] SC3: Change or remove an input artifact after package freeze; detect the drift and refuse to claim a valid handoff.
- [ ] SC4: Present identical code under different anonymous labels/model mappings; judgment input contains no author/model/cost ranking cues.
- [ ] SC5: Recommend reused code explicitly and preserve its source revision rather than claiming a fresh independent implementation.
