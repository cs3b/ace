# Create tasks in target folders atomically

## Behavioral Specification

Creating a task with an explicit destination either creates exactly one complete task in that destination or fails without leaving task artifacts.

### User Experience

Input and expected output are defined by the concrete scenarios in `ux/usage.md`. Normal completion reports its result; failure identifies the unmet condition without claiming success.

## Verification Baseline — 2026-10-10

Confirmed on main: CLI create --in next exits 1 with NoMethodError at create.rb:122 and leaves a .s.md file in the default root. TaskManager exposes update(move_to:), not move. Reproduced in /tmp/ace-github-triage-20261010 using checkout binstub and Ruby 3.4.8.

Revision: `aaf6dfec4c2d93c8f0b1c7cd53b6a07c68942659` (HEAD and fetched origin/main). See the parent triage report for executed tests and limitations.

## Interface Contract and Success Criteria

- [ ] SC1: The existing create TITLE --in next and --in maybe interfaces succeed with one task in the requested destination.
- [ ] SC2: An invalid destination, denied write, or relocation failure returns an actionable nonzero error and leaves no new orphan spec or directory.
- [ ] SC3: Default destination, dry-run and child creation retain their documented behavior; dry-run makes no changes.
- [ ] SC4: Retry after a failed operation does not inherit partial artifacts from that failure.
