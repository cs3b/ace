# Goal 2 — Restart and reconcile from observed proof

Use the installed executable in another process to run `inbox status --event inb-12345678 --format json`; save its output and exit under `results/tc/02/`. The first event was accepted for submission and should report `delivered`. Create an independent second event with the same ref and payload. Set `ACE_E2E_CODEX_FAIL=1`, `ACE_E2E_EVENT_ID=inb-87654321`, and `ACE_E2E_OUTCOME_LOG` to a sandbox-local log before delivering it. The fake native executable records a simulated consumed-and-acknowledged outcome linked to the second event, then returns a stalled result, leaving the inbox record `uncertain`.

For the uncertain second event, use its status and the native outcome log to prepare a receipt with outcome `consumed`, identified operator or supervisor, and the exact native observation reference. Keep this order: (1) invoke `inbox deliver` again in a separate process and capture that it stays `uncertain` without another queue call; (2) submit a complete but unsigned self-authored receipt and capture its refusal while still uncertain, then call `inbox deliver` again; (3) write a wrong attempt ID and sign that file with the setup-created private key, then reconcile and capture the refusal, then call `inbox deliver` again; (4) write the matching receipt and sign its exact bytes using the documented `openssl dgst -sha256 -sign receipt-private.pem -out FILE.sig FILE` command, then reconcile. Capture status, all three reconciliation outputs, each retry output and exit, the native outcome log, and a final status in `results/tc/02/`. Confirm the queue log still has only one submission for each event and no resend after the uncertain outcome.
